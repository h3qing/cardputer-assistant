## [v0.5.1] - 2026-10-29
### Added
- Recordings no longer get lost between Macs (docs/28 S1a, #84; requirement (2026-10-26): a recording meant for another Mac must not be lost because this Mac connected first):
  - **Kept copies**: when a Mac pulls and deletes a recording, the device no longer deletes the file. It appends a record with the receiving Mac's hash (CRC-32 of `hello.host_id`) to `/cpa/rec/<E7>/SENT.L` and acks only after fsync. Kept copies are invisible to every Mac (not in `file.list` or `files.n`) and take none of the 256 waiting slots. They are kept per whole recording for 7 days (the clock comes from `time.set`; a jump forward of more than a day is not used at first, D16); the oldest go first when there are more segments than the scan table holds or the card has less than 1 GB free. Recordings that are too long, and a full card, are deleted at once as before.
  - **Deliver again**: Settings → Storage (Opt+M, then `,`) → "Send again · from 3F2A: 2" (再交一次 ·3F2A 的 2 次), Enter; the confirm box opens on Cancel; `/` Enter: the last batch delivered to that Mac is waiting again, **that Mac never sees it again**, and another Mac takes it. At least 12 waiting slots stay free, so recording is never blocked.
  - **Give to this Mac**: the second row of Settings → Storage undoes "deliver again" (or the hint's "keep from this Mac"): the Mac that is connected can take what was held back from it (with only one Mac nothing gets stuck).
  - **The 5-second plug-in hint**: when there are recordings made offline, after the handshake with a Mac the hint bar says "2 offline go to this Mac · Tab: no" (离线 2 条 → 这台 · Tab 不给), and for those 5 seconds only these are held back. Do nothing and they go as usual (0 presses); Tab then Enter keeps them from this Mac (2 presses). Offline = recorded since the cable was last pulled (the next id is saved to NVS when the cable is pulled). While the device is locked (taken out of a pocket and plugged in) or the Tab menu is open, the hint cannot be seen, so the 5 seconds do not run and the keys are not its; these recordings stay held, for at most 2 minutes. Press Enter and pull the cable at once, and that Mac still does not get them.
  - **Clear kept copies**: Settings → Storage → "Clear kept" (清掉留底); the confirm box opens on Cancel. The lock card gains "kept N" (留N), and so does the sync row of the Settings page.
  - Only the audio task writes the ledger. Each record is 28 B with a magic number and a CRC; a bad record is skipped by its magic; a dirty or too-long ledger is tidied into the other name (`SENT.L` ↔ `SENT.K`), never changed in place. The boot scan reads the ledger first and does not read `.M` for kept segments; with more names than the scan table holds, recording refuses to start ("Too many files: sync first" (卡上段太多), D15).
  - Power-cut tests on the host (truncation at every byte and at every record boundary, a CRC error in every record, a power cut at every file call while delivering, delivering again, clearing and tidying at boot, plus fuzzing of random commands and power cuts); the simulator gains a `pull` step and the four `scripts/kept/` scripts (Chinese and English). On the real device (docs/07 §11): device tests, 10 HIL scenarios, the two-Mac simulation, 36 chip resets standing in for power cuts (mid-pull, right after Clear, during the boot scan) and a 62-minute two-Mac soak all pass; a real power cut (battery off, cable pulled) has not been run yet.
  - Fixed after review: after a ledger tidy, deliver again no longer also takes earlier recordings of the same Mac (the tidy records in GEN where the last batch starts); a clear whose file could not be deleted does not come back as waiting after a tidy; with the cable in and less than 1 GB free on the card, kept copies are cleared between two pulls (pulls no longer make room); clearing by segment count goes down to the limit minus a whole waiting table (1008 segments), so what was just delivered is not deleted at once; a clock that jumps back by more than a day is not used at first either; a fifth Mac does not make the boot scan exclude the wrong one; the hint's receipt counts recordings, not segments; when the command did not reach the audio task the toast says "Not changed: this Mac gets them" (没改成，已照常给这台 Mac) instead of "SD card error"; a ledger command with no answer for 30 s frees the screen; the facts on the Chinese storage page no longer crowd together; the English sync row says `kept N`.
  - Fixed on the real device (docs/28 §12): when B had just stopped and A handshook straight away (the link never went down), the hello's `files.n` still counted for the previous Mac, so A waited 60 s before pulling. Now the hello is counted for the Mac that sent it before it is answered, and a change of Mac also moves `files.rev`, so A pulls at once.
- English first, with Chinese supported (#88–#92):
  - Docs (#91): English at the normal path, Chinese next to it as `*.zh-CN.md`, line 1 of each linking to the other (the docs language rule in CONTRIBUTING). The README, CONTRIBUTING, docs/01–29, the ADRs, gates, release notes, and the protocol, daemon and Mac app READMEs follow it; in this release so do CHANGELOG, SECURITY, docs/07, docs/28 and `firmware/sim/README.md`.
  - `cpa`, cpad and cpa-stt (#92): the language is decided at each call: `CPA_LANG`, then `lang` in `config.json` (`cpa lang zh|en|auto`), then `LC_ALL`, `LC_MESSAGES`, `LANG`; a value starting with `zh` is Chinese, anything else (or nothing) English. `cpa filing triage`, `cpa dest test --send` and `cpa setup check` (`--todo` prints one language), which were Chinese only or Chinese and English side by side, follow it. What cpad and cpa-stt write (daily-note lines, a meeting's default title, the board's voice prefix, the built-in destination labels, the header another app receives, the MCP truncation markers, cpa-stt's "(nothing heard)", the export README) is in the language of the moment it is written; a line already written is never rewritten, and readers parse the format, never the words. `cpa service install` passes the login shell's `CPA_LANG`, `LC_ALL`, `LC_MESSAGES` and `LANG` into the LaunchAgent.
  - Installer (#89): `install.sh` and `uninstall.sh` print each line in one language, English by default: `--lang zh|en`, else `CPA_LANG`, `LC_ALL`, `LC_MESSAGES`, `LANG`; `--help` follows it; the last screen's `cpa setup check --todo` uses the same language. The digest, quarantine and token handling are unchanged.
  - Mac app (#90): screenshots are drawn in English first, then Chinese (see Changed), with English demo data; one project and one memo stay Chinese so the screens still show CJK text. The core tests run in English by default; suites that check Chinese pin `zh`.
  - HIL tools (#88): comments in English; when the start language cannot be read, a run puts the device back in English.
- Design doc docs/29 (#86): saving power when the device sits unused: light sleep when the screen is dark on battery, deep sleep after 2 h, shutdown on low battery. Not implemented yet.
- The firmware reports `cpa-fw/0.5.1`; `cpa --version`, `cpa-stt --version` and the Mac app are 0.5.1.
### Changed
- Mac app screenshots (`swift run CardputerShots`): English in `out/shots/`, Chinese in `out/shots/zh/` (before: Chinese in `out/shots/`, English in `out/shots/en/`; #90).
### Fixed
- A race when installing the background service (#83): `cpa service install` waits (up to 10 s) for the old cpad to exit, then checks that the new one is running with a different pid; it retries once, then exits 1 with a clear message. `install.sh` trusts only that result and checks `cpa status` again a few seconds later.

- Changes after this round's review of To file (#54): `cpa filing file` is also refused while there is an open queue item (`E_ALREADY`; the queue item keeps its project; `reopen` withdraws it first), so undoing several steps in a row always gets back to the very start; a queue item withdrawn while the device is opening it still counts as handed to AI once it has opened; undo can restore a project this Mac has already deleted; half an emoji in a transcript (a lone surrogate code point) no longer makes `ls`, `show`, `hand` and export fail entirely; `ls` waits only 0.5 s for the running cpad (`hand` waits 2 s), so the list still comes out when cpad is stuck; `status.json`, like other files, does not follow symbolic links; queue records written by cpad itself also go into its fold.

## [v0.3.2] - 2026-10-21
### Fixed
- The first recording after power-on started with about 1 second of zeros (#31): after power-up the ES8311 forces its output to 0 for about 2^14 clock frames. After the boot scan, the audio task warms up the codec once at 48 kHz (about 0.5 s, silent, no file written); after recording starts, `● REC` shows and the file starts being written only once the first block of sound that is not forced arrives, the forced part before it is dropped, and it waits at most 2 s. Recording times (`at.up_ms`, ★, `lead_ms`) all count from the first written sample.
### Added
- Claude Code hooks (#33): `cpa hooks print|install|uninstall` (only writes `~/.claude/settings.json` with `--yes`, backing up the old file to `$CPA_HOME/hook-backups/`) and `cpa hook` (called by Claude Code for each event; it sends only allow-listed fields to the daemon over `cpad.sock`). The board updates as soon as a hook fires, with the reason for waiting (permission, plan, question, login); polling remains the final authority. `cpa status --json` gains `hooks`. Terminal sessions only run hooks in trusted folders.
- Why opening a session failed (#25): `agent.result` and `agent.spawn_failed` events gain an optional field `why` (`untrusted` | `login`, protocol v0 additive only); `cpa status`'s claude line shows `login=`, and the `warning:` line gives a one-off fix command. cpad never accepts trust or logs in on the user's behalf.
- Local data access (#34): `cpa export` (exports to a folder or zip, with SHA256SUMS, refuses cloud-synced folders) and `cpa mcp serve` (a local stdio MCP server, read-only by default, writes turned on one by one, every call logged for audit); `cpa mcp setup` prints the config for Claude Code, Codex and Cursor.
- Host simulator (#32): `firmware/sim` runs the firmware on the Mac, producing screenshots with the real fonts, or opening a pty virtual device for cpad and HIL.
- The test firmware's `debug.codec{warm}` (protocol v0 additive only): soft-resets the codec to its just-powered-up state, optionally running the boot warm-up again; HIL scenario `rec_cold_start` and device test `test_mic_cold`.
### Changed
- What counts as "waiting" (#5): a background session whose `state` is `blocked` and that is not running also counts as waiting at once; Claude Code 2.1.306's `waitingFor` (permission / question / dialog) is parsed.
- The firmware reports `cpa-fw/0.3.2`.
