## WP2 · Pure firmware core libraries (testable on native: protocol, link, outbox, input, state)

- **Owned paths**: `firmware/app/platformio.ini`, `firmware/app/lib/core/`, `firmware/app/lib/protocol/`, `firmware/app/lib/link/`, `firmware/app/lib/outbox/`, `firmware/app/lib/input/`, `firmware/app/test/core/`, `firmware/app/src/ (stubs only; WP4 takes over)`
- **Depends on**: WP1

### Scope

To do: (1) platformio.ini: three envs, cardputer-adv, cardputer-adv-test and native, written as in 05 §3. Toolchain per ADR-0001; until decided, use A. Use -std=gnu++17. Pin ArduinoJson to 7.4.3. The native env sets lib_ignore=hal,usb_transport and defines CPA_PROTOCOL_DIR. (2) core/: FixedStr<N>, Result, Effects/Step, MonoId (Crockford base32 encoding; generate and parse; the interface expresses the rule that boot is incremented before any ID is issued), the AppState slices, plus static_assert(sizeof(AppState)<=4096). Slice reducers cover projects, sessions (a toast event when need newly becomes true; age counts up locally), queue, link info, outbox info, and agent request state (≤1 in flight; on timeout or link loss the result is unknown and it becomes a queued draft). (3) protocol/: messages.h defines every type in 05 §6.5, codec.cpp uses one reused JsonDocument, limits.h mirrors limits.json, errors.h. (4) link/: LineFramer (limit 2048, drops lines that do not start with {, ignores \r); LinkSession is a pure state machine (Detached/Attached/Ready; exactly one reply per host-initiated message; 15s timeout; a new hello restarts the handshake and in-flight items go back to pending); transport.h holds only the interface. (5) outbox/: OutboxCore is pure (ID order, ≤4 in flight, retry intervals 3/6/12/30s, handles stored/duplicate/rejected, in-flight items go back on link loss, capacity 200 items and ≥64KB free, boot scan rules: delete an orphan .tmp, but if a .json with the same name sits next to the .tmp, do not delete it, only count it); file_store.h is the interface; FakeStore can inject a crash at any step and lives in test/core/support. (6) input/: KeySet, GhostFilter (rectangle detection), ChordDetector (G0 under 500ms is Tap, 500ms or more is Long; only Backspace auto-repeats, 500/60ms; no Char while Ctrl/Opt/Alt is held), the keymap table (every key in 04 §8), plus a static ghost check of the keymap. (7) src/main.cpp holds only stubs: it references each core type to confirm it compiles with xtensa. Not in scope: hal, usb_transport, shell, module_api, modules, any Arduino/M5/esp_* header, SD, the Leader key, sleep, hooks.

## WP3 · Mac daemon cpad and the cpa command line

- **Owned paths**: `daemon/`
- **Depends on**: WP1

### Scope

To do: (1) A Python 3.12 project built with uv, package cpad, entry point cpa. The only runtime dependency is pyserial==3.5; dev dependencies are pytest, pytest-asyncio, pytest-cov, hypothesis, ruff, jsonschema, lizard. (2) protocol/: messages as frozen dataclasses, hand-written validators, limits read from ../protocol/limits.json, ensure_ascii=False when serialising, entries dropped from the tail above 2048. (3) device/: PortFinder (binds to the serial number, 30s backoff), SafeOpen (control-line sequence), Handshake (wait 2s and retry, 3 times in all; checks the fw prefix and v; releases within 6s), DeviceLink (reader thread hands off via call_soon_threadsafe; credit window ≤4096; 5s ping; 15s drop; resync after a boot change is detected). (4) hub/: HubState, reduce, EffectRunner, snapshot building (respects the limits; rev is not affected by age). (5) events/: events.jsonl is append-only with an fsync every time, and must be on disk before the ack; dedupe by (dev,id), with the index rebuilt at startup; entries whose project was deleted are kept and marked orphan. queue/: the queue is folded from events with pure functions; qid format is q<n>. notes/: daily markdown with block IDs, idempotent writes, catch-up writes at startup. (6) projects/: projects.json validation (root must be an existing directory, stored as realpath, git not required; key and slot unique; mode defaults to plan, and bypassPermissions refuses to load); cwd matching uses the longest prefix, then git common-dir if that fails, cached for 60s; reloads automatically when the file's mtime changes. (7) agents/: the AgentAdapter protocol, plus a claude_code implementation. probe parses the version and absolute path. list runs agents --json every 3s only while the device is Ready, with lenient parsing. spawn's argv is [bin,'--bg','--name',name,'--permission-mode',mode,'--',text], cwd=root, env=spawn_env; parse short from the output, and if that fails compare the list before and after. reply is only available when config.experimental_bg_reply is on; the flow is stop → resume → check the ID with agents --json --all; if a fork is found, return E_REPLY_FORKED and turn reply off. Bodies that start with '-' are rejected, and sid must match exactly one session. (8) inbox/: need rules: waiting at once, idle after 60s; dismissals at (sid,st,since) level live only in memory. (9) control/: AF_UNIX cpad.sock with mode 0600, supporting pause and status. cli/: daemon, status, project add|ls|rm, queue ls|add|done, pause, service install|uninstall (plist built with plistlib; spawn_env built from zsh -lic env through an allowlist), device forget. logging/: RedactFilter. At startup check that $CPA_HOME is 0700/0600. (10) All test helpers live in daemon/tests: FakeDevice (pty; simulates TX being held and drops bytes when RX exceeds 8192), tests/fixtures/bin/fake-claude (records argv/cwd/env, prints per fixture, can flip state), and a redacted agents --json fixture (every kind and status present, with Chinese names). Not in scope: an HTTP or TCP server, hooks, a settings installer, MCP, SQLite, pydantic, starlette, pairing, mods, transcription, queue markdown, polling while the device is offline.

### Acceptance (tests first)

- (RED first) cd daemon && uv run pytest tests/unit tests/contract -q   # contract tests read ../protocol/vectors/v0
- cd daemon && uv run pytest tests/integration -q   # at least: test_handshake_tx_parking, test_credit_window_rx_overflow, test_safe_open_never_rts1_dtr0, test_spawn_argv_hostile_texts, test_spawn_default_permission_mode_plan, test_bypass_mode_rejected, test_offline_intents_never_execute, test_events_fsync_before_ack, test_replay_dedupe, test_orphan_item_kept, test_notes_idempotent, test_inbox_debounce_and_dismiss, test_reply_disabled_by_default, test_reply_fork_detected, test_pause_socket_perms, test_foreign_board_released_within_6s, test_no_poll_without_device

- cd daemon && uv run ruff check . && uv run ruff format --check .

## Decisions for the user to confirm (we proceed with the defaults)

| Question | Default | Why it matters |
|---|---|---|
| What permission mode do Claude Code sessions opened from the device use? (must be confirmed before M3) | plan for every project by default; per project it can be changed to acceptEdits or manual in projects.json; auto only if the project says so explicitly; bypassPermissions is always refused | Your ~/.claude/settings.json has defaultMode set to auto. Without an explicit --permission-mode, a session opened from a device bumped in a pocket or lost would change code directly in auto mode. With plan as the default, the worst outcome is an extra plan waiting for you to review back at the Mac |
| Firmware toolchain: once the Day-0 spike passes, do we accept pioarduino (in practice a single maintainer) as the v0.1 toolchain? | Accept, provided all four G2 checks pass on the day (CDC round trip ≤100ms, mic RMS not 0 after the speaker has played, SD write then rename, all three libraries compile), and it is pinned to the release zip URL. If any one fails, use espressif32@6.10.0 | IDF 4.4 is EOL, so v0.3's WiFi/BLE work would lack security fixes. Moving from Arduino 2 to 3 has breaking API changes, and migration is cheaper with less code. On the other hand, a single maintainer for pioarduino is a supply-chain risk |
| Do you mostly run Claude Code in the terminal or in the Claude desktop app? Do you accept that in v0.1 feedback goes to a queue first, and only background sessions can be replied to directly? | v0.1 does not upgrade the CLI. Feedback goes to the project queue; once G3 passes, experimental_bg_reply can be turned on by hand to reply directly to idle background sessions. v0.2 re-evaluates upgrading to 2.1.287 or later and injecting through mods | Fast feedback is one of your core needs, but 2.1.272 has no way to inject text into an interactive session. Which path v0.2 takes (mods or something else) depends on where you actually run sessions |
| Where do notes go? | ~/CardputerNotes/YYYY-MM-DD.md, one file per day, each note with an Obsidian block ID ^cpa-<id> | Writing straight into an Obsidian vault under ~/Documents or iCloud would get the Python running in the LaunchAgent blocked by macOS TCC, and you would have to grant uv's Python Full Disk Access by hand |
| The immutability rule says No exceptions. Do we accept mutable hardware buffers confined to hal/ and usb_transport/ as the only exception? | Accept: inherently mutable things like the serial RX/TX rings, the display sprite and file handles appear only in these two directories (and the daemon's shell layer); all business logic is pure functions, and state is only replaced whole | Without this boundary the firmware cannot drive the hardware; drawn too wide, it breaks your engineering rules |
| Are the rules for the Inbox (sessions waiting for you) right? | waiting enters at once; idle enters only after 60 seconds or more; only sessions in registered projects count; you can dismiss with Opt+D until its state changes again; long-idle sessions are not hidden automatically | The session you are using at the Mac also becomes idle. Too loose, and !N never reaches zero; too strict, and sessions that really are waiting for you get missed |
| Does a quick note's default target follow the current project, or is it always unassigned? | Follows the current context: if you are on a project page or have a session selected, it goes to that project; otherwise unassigned | Decides whether you have to sort things again back at the Mac, and affects how often things get misfiled |
| If the device is lost, items not yet synced are plaintext. Is that acceptable for v0.1? | Accept. Delete on ack, show the pending count in the status bar, and write it into SECURITY.md; v0.2 evaluates a PIN lock and an encrypted wrapper for the SD card | We do not turn on flash encryption by default, because it is one-way and community flashing tools stop working afterwards.
