## 0. 一句话

把 Cardputer ADV 变成 Mac 的"口袋副屏 + 速记键盘"，做到三件事：
- 一眼看到每个项目里哪个 Claude Code session 在跑、哪个在等你；
- 随手记下想法或反馈，归到对应项目的队列，或者确认后直接给这个项目开一个新 session；
- 离线时照样能记，插回 Mac 就自动同步。离线记下的东西**只会变成笔记或排队项，绝不会自动执行**。

## 1. 背景

### 1.1 要解决的问题
你同时推进好几个项目（A、B、C），每个项目都有自己的想法、待办和几个并行的 Claude Code session。现在有四个痛点：

1. **不知道谁在等你。** 要在 Mac 上一个个切终端或窗口，才能知道哪个 session 跑完了、哪个卡在权限确认或提问上。session 空等的每一分钟都是浪费。
2. **想法容易丢。** 灵感随时会冒出来，可能在写代码、走路或开会的时候。要记下来，得掏手机、解锁、找 App、选项目，步骤太多，注意力也会被手机带走。
3. **"想到"和"交给 AI 去做"之间是断开的。** 想到一件要跟进的事，得先回到 Mac、进项目目录、开 session、粘贴描述，才算真正交出去。
4. **离开电脑就没法异步推进。** 没网、不在 Mac 旁边时，想法没有可靠的地方落脚。

### 1.2 为什么是现在，为什么用这台设备
- **设备合适**：Cardputer ADV 有完整键盘，装得进口袋，电池能撑一天，带麦克风和 SD 卡，USB 免驱。
- **接口够用**：Claude Code 的命令行接口不需要任何配置，就能读取 session 状态、开后台 session（L2 到 L6）。
- **有空白可做**：2026 年大约出现了 60 个"Cardputer + AI 编程助手"项目，几乎都只做"状态显示 + 批准/拒绝"。**还没有人做按项目组织的异步工作流**，也就是项目看板、反馈队列、从设备开 session、组合键速记、离线语音回传。这是我们的差异点（02 报告 TL;DR）。

## 2. 用户画像

**主用户：多线程开发者（就是你）**
- 同时推进 3 个以上项目，每个项目开 1 到 3 个 Claude Code session。终端和 Claude 桌面端都在用。
- 口述以中文为主、夹着英文技术词。在设备上只打英文或拼音。
- 想要：少切窗口、少掏手机；想法不丢；离开 Mac 时 AI 也在推进；回到 Mac 时一切已经整理好。
- 不想要：在 240×135 的小屏上读长文或审代码；复杂的配置；数据上云。

**贡献者：Cardputer 玩家或开源贡献者**（v0.2 起重点照顾）
- 想加自己的小工具，比如番茄钟、Home Assistant 开关、其他 AI 助手的适配器。
- 想要：清楚的模块边界；本地能跑测试；文档讲清楚怎么刷机、怎么调试。

**同类用户：Claude Code 重度用户**（v0.2 以后）
- 想要一个"等你"提醒器加一个速记键盘，从克隆仓库到跑通不超过 15 分钟。

## 4. 产品原则

1. **重活交给 Mac，设备只当手和眼。** 设备负责采集、显示和暂存；分组、调用 CLI、存储都由 Mac daemon 完成。
2. **随时能记，执行必须在线确认。** "执行类"操作指开 session 和给 session 发反馈。这类操作只能在设备在线时，经过确认框，以**在线请求**的方式发出。它们**永远不进 outbox，重连后也不会自动重放**。离线时发起的执行请求一律存成排队项。
3. **v0.1 只用稳定的 CLI，不动你的配置。** 不装 hooks，不改 settings，**不监听任何网络端口**，也不要求升级 CLI。
4. **从设备开出的 session，权限是显式指定的，而且不会比你手动开的更高。** daemon 每次都带上 `--permission-mode`，取值来自项目配置，默认 `plan`。永远不用 `bypassPermissions`。
5. **数据不离开你的机器。** 没有云、没有账号、没有遥测。Mac 是唯一的权威存储；设备上只保留还没同步的内容。
6. **要模块化，但不为假想的需求做抽象。** 只做一个编译期的模块列表，加一套很小的接口。运行时插件和插件市场以后再说。
7. **小屏只放一眼能看完的东西。** 不在设备上读长文、看 diff 或对话记录。

## 5. 版本切片

### 5.1 v0.1「USB 闭环」

**一句话**：插着 USB 时（或者离线一段时间后插回），设备、daemon 和 Claude Code 形成闭环，支持速记、项目看板、等你收件箱、排队和开新 session。如果 G3 通过，还能回复空闲的后台 session。

| ID | 功能 | 优先级 |
|---|---|---|
| F1 | 速记：在任意界面按 G0 或 Opt 组合键，内容写进机身 Flash 的 outbox | P0 |
| F2 | 同步：握手、时间同步、outbox 幂等上传、Mac 端只追加的事件日志 | P0 |
| F3 | 项目登记表（在 Mac 上用 CLI 管理）和项目看板 | P0 |
| F4 | 等你收件箱：`waiting` 的 session 立即进入；`idle` 超过 60 秒的进入 | P0 |

### 5.2 v0.2「离线语音 + 能回复任何 session」
- **回复 interactive session**：升级到 Claude Code ≥2.1.287，用 mods 的 `$.prompt.submit` 注入。daemon 先检测能力，做不到就回落到 v0.1 的做法。
- **可选的 hooks**：用"命令转发脚本 + 权限 0600 的 token 文件"来接入，**不用**原生 http hook，因为 2.1.272 不会把被判定为凭据的环境变量插值进 header。安装要显式执行命令，先备份，可以完整卸载。Notification hook 用来显示 session"为什么在等"；Stop hook 的 `last_assistant_message` 用来显示进度摘要。
- **在设备上审批**：按风险分键，常规操作 Enter 批准、Esc 拒绝；高风险操作长按 Fn+Y。确认框打开后 400 ms 内的按键一律忽略。**设备不在或超时，就不做决定，由终端照常询问**，不会默认拒绝。所有决定写审计日志。
- **离线语音**（前提是 G2 通过）：
  1. 长按 G0 录音，写到 SD 卡，每 5 分钟分一段；
  2. 同步时分块上传，带 SHA-256 校验；
  3. Mac 上转写，转写引擎可以替换；
  4. 转写结果变成笔记或排队项。执行类操作仍然要在线确认。
- **SD 卡历史**：已同步的条目归档到 SD 卡，每个记录带校验和，每个文件用 Mac 公钥单独加密封装。
- **其他**：省电（灭屏、浅睡眠）、Leader 键、模块 SDK（模板模块和贡献指南）、排队的反馈重新投递给原 session、MCP server（每条队列项记录来源，见 §14 风险）。

### 5.3 更以后（v0.3 起）
- **无线**：WiFi 和 BLE。先用 USB 做正式配对（NVS 里的密钥 + HMAC 挑战），之后走 Noise 加密信道。
- **兼容和扩展**：Hardware Buddy 兼容模块；Codex 等其他适配器；daemon 插件；OTA；U 盘（MSC）模式。
- **工具链和平台**：迁移到 Arduino 3.3.x / IDF 5.5，麦克风改用自写的 `i2s_std` 驱动；评估 Tactility。

### 5.4 明确不做

**v0.1 不做：**
- 设备配对。它不带密钥，起不到作用，推到 v0.3 和无线一起正式做。
- hooks，以及对 Claude Code 配置的任何修改。
- 任何 TCP 或 HTTP 端口。
- mods。
- SD 卡、语音、录音。
- 在设备上审批权限。
- 在设备上打中文。
- 在设备上浏览历史、编辑已提交的条目。
- 在设备上看对话记录或 diff。
- 多台设备或多台 Mac，账号、云同步、遥测。
- 运行时加载模块，OTA，Codex，睡眠，Leader 键。
- 队列 markdown 输出。

**整个项目都不做：**
- 在 240×135 的屏幕上复刻终端或聊天界面。
- 把任何接口暴露到公网。
- 默认开启 Flash 加密或 Secure Boot。
- 做成通用的 Cardputer 操作系统，或者做手机 App。

## 6. 用户故事与验收标准（v0.1）

"在线"的意思是：链路处于 Ready 状态，即已经握手，并且 15 秒内收到过 daemon 的数据。所有延迟指标都用 p95，测量方法见 §12。

### US-01 速记（F1，P0）
我想在任何界面一键开始记笔记，5 秒内把想法记下来。
- **AC1**：在任何界面短按 G0（按下不到 500 ms），p95 在 300 ms 内打开采集页（Compose），可以直接打字。在采集页里按 G0 等于提交。
  - v0.4.1 起（gh #51，[docs/20 U26](20-ux-review.zh-CN.md)）：短按以后要等 0.35 秒（`kDoubleTapMs`）看是不是"点两下"，所以采集页在松开后 0.35 秒才打开，p95 上限放宽到 650 ms。在这之前就按别的键，采集页马上打开，这个键落进去，一个字都不丢。
- **AC2**：默认类型是"笔记"。默认目标是当前所在的项目，比如正在看的项目页、或者选中的 session 所属的项目；不在任何项目里时，目标是"未归属"。
- **AC3**：按 Enter 或 G0 提交，空文本不提交。只能输入单行 ASCII，最长 500 字节，页面上显示已用字节数，到上限后不再接受输入。
- **AC4**：提交时，条目要**先写完、改名落盘**，然后才显示"已保存 · 待同步 N"。保存延迟 p95 不超过 100 ms（真机测 200 次）。断电保护的验收分两部分：
  - native 测试在每一步存储操作处注入崩溃，结果是已确认的条目 0 丢失、0 重复；
  - 人工做 10 次真实断电（侧面开关拨到 OFF 并拔掉 USB），每次都在看到"已保存"之后立刻断电，0 丢失。
- **AC5**：按 Fn+`（Esc）取消。如果已经输入了内容，要二次确认：Enter 放弃，Esc 回到编辑。
- **AC6**：离线时、daemon 没运行时，速记都照常可用。
- **AC7**：outbox 满了（达到 200 条，或者剩余空间不到 64KB）时拒绝提交，提示"存储已满，请连 Mac 同步"。绝不覆盖还没同步的条目。

### US-02 改类型和目标（F1，P0）
- **AC1**：在采集页里，Opt+N、Opt+Q、Opt+S 把类型分别切换成"笔记""排队""新 session"，标题栏立刻跟着变。
- **AC2**：Opt+1 到 Opt+9 把目标改成对应编号的项目，Opt+0 改成"未归属"。"排队"和"新 session"不能是"未归属"，这时按 Enter 会提示先选项目。
- **AC3**：离线时也能按编号选项目。设备会持久保存"编号 → 项目代号和显示名"，但**不保存路径，也不保存任何 session 信息**。
- **AC4**：类型是"新 session"或"反馈"时，文本不能以 `-` 开头。采集页会给出提示，不允许提交。

### US-03 同步（F2，P0）
- **AC1**：daemon 发现设备后，先用安全方式打开串口，再发 `hello`。2 秒没回应就重发，最多 3 次。握手成功后，daemon 下发时间和看板快照，设备按 ID 顺序上传 outbox，同时在途的条目最多 4 条。
- **AC2**：握手后 5 秒内，outbox 里的 100 条全部得到确认（HIL 测试）。
- **AC3**：设备只在收到 `outbox.ack` 之后才删除条目。如果 ack 丢了、或者 daemon 崩溃导致设备重发，Mac 按 `(设备, 条目 ID)` 去重，结果是 0 重复（HIL：丢弃 ack 的场景）。
- **AC4**：daemon 先把事件追加进 `events.jsonl` 并 fsync，然后才回 ack。设备不知道时间时，`wall_ms` 为空，Mac 端记录收到的时间 `received_at`，**不编造时间**。
- **AC5**：在线时新提交的条目，p95 在 1 秒内送达，状态栏的 ↑N 回到 0。
- **AC6**：离线记下的条目，类型只可能是"笔记"或"排队"。outbox 里**不存在**能触发执行的类型（这条由契约测试保证）。

### US-04 设备识别与端口礼让（F14，P0）
- **AC1**：只有当 `hello` 的回复满足两个条件时，daemon 才占用这个串口：`fw` 以 `cpa-fw/` 开头，并且 `v` 等于 0。否则 6 秒内释放端口，不再写任何内容，30 秒后才重新尝试这个端口。
- **AC2**：第一次握手成功后，daemon 把这台设备的 USB 序列号绑定到配置里。之后其他 `303A:1001` 端口一律不碰。运行 `cpa device forget` 可以解除绑定。
- **AC3**：如果双方的协议主版本不一致，设备显示"固件和 Mac 端版本不兼容，请更新"，daemon 释放端口，`cpa status` 里写明原因。
- **AC4**：daemon 在任何时候都不会让 (RTS, DTR) 出现 (1, 0) 的组合。验证方法有两个：单元测试检查控制线的变化序列；HIL 测试检查重新打开端口后 `up_ms` 是连续的。

### US-05 项目登记（F3，P0）
- **AC1**：登记命令是 `cpa project add <key> <path> --slot N [--name 显示名] [--mode plan|manual|acceptEdits|dontAsk|auto]`，下面每一条都必须满足，否则报错并且不写入任何东西：
  - `path`：存在的目录，转成绝对路径（realpath）后保存。**不要求是 git 仓库**，因为本项目目前就不是 git 仓库。
  - `key`：符合 `^[a-z0-9][a-z0-9-]{0,11}$`，并且没有被占用。
  - `slot`：在 1 到 9 之间，并且没有被占用。
  - `name`：不超过 24 字节的 UTF-8，可以是中文，默认等于 `key`。
  - `mode`：默认是 `plan`。传 `bypassPermissions` 会被拒绝。
- **AC2**：`cpa project ls` 和 `cpa project rm <key>` 可用。在线时，登记表改动后设备 5 秒内更新。
- **AC3**：设备只拿到 `slot`、`key`、`name` 和统计数字，拿不到路径和权限模式。

### US-06 项目看板（F3，P0）
- **AC1**：主页（Opt+H）按编号列出项目（v0.4.0 起这一页叫项目看板，按 Opt+P 打开；Opt+H 改成主页启动器，见 §8.2），每个项目显示三个数字：运行中、等你、排队。最后一行是"其他"，统计工作目录不属于任何已登记项目的 session。"其他"里的 session 不进收件箱。
- **AC2**：Mac 上 session 状态变化后，设备 p95 在 5 秒内更新（HIL：用 fake-claude 翻转状态 100 次）。
- **AC3**：Opt+1 到 Opt+9 打开对应的项目页。项目页有"Sessions"和"队列"两个标签页，用 `,` 和 `/` 切换。Sessions 列表显示名字、状态、持续时长，以及 `bg` 或 `tty` 标记。
- **AC4**：断开连接后，看板保留最后一份数据，并标注"N 分钟前"。设备重启后，只显示缓存里的项目名，数字显示 `--`。session 信息不写进 Flash。
- **AC5**：如果 Mac 上找不到 Claude Code，看板显示"Mac 上未找到 Claude Code"，开 session 和回复两个功能变灰。

### US-07 等你收件箱（F4，P0）
- **AC1**：Opt+I 打开收件箱。进入收件箱的条件：
  - session 属于已登记的项目；
  - 状态是 `waiting`（立即进入），或者状态是 `idle` 并且已经持续至少 60 秒。

  排序：`waiting` 的在前，`idle` 的在后；同一组里等得越久越靠前。
- **AC2**：状态栏显示 !N，N 是收件箱的条数。有新条目进入时，弹出 2 秒提示："<key>/<session 名> 等你"。
- **AC3**：选中一条按 Enter，进入回复（US-10）。按 Opt+D 忽略这个 session，直到它的状态再次变化。忽略记录由 daemon 保存在内存里，daemon 重启后失效。
- **AC4**：后台 session 显示提示 `claude attach <short>`；interactive session 显示"在 Mac 上处理：<name>"。v0.1 不在设备上审批。
- **AC5**：忽略操作只能在线时做，离线时这个操作变灰。

### US-08 排队（F5，P0）
- **AC1**：排队项有三个来源：设备上类型为"排队"的条目、降级下来的开 session 或反馈请求、`cpa queue add`。它们出现在对应项目的"队列"标签页里，最新的在前。设备上每个项目最多显示 4 条，总共最多 12 条；数字显示的是全部条数。
- **AC2**：在队列项上按 Enter，走 US-09 的确认流程。prompt 用 Mac 上保存的**全文**，不用设备上截断过的文本。成功后，这一项标记为"已开 session"并从列表里消失，事件日志里仍然保留记录。
- **AC3**：Opt+D 把一项标为完成。只能在线时操作，离线时变灰。
- **AC4**：Mac 上可以用 `cpa queue ls [key]`、`cpa queue add <key> <text>`、`cpa queue done <qid>`。设备在 5 秒内跟着更新。

### US-09 开新 session（F6，P0）
- **AC1**：操作流程：
  1. 在项目里按 Opt+S，或者在队列项上按 Enter；
  2. 输入任务描述，按 Enter；
  3. 弹出确认框，显示项目代号、文本的前 60 个字符和权限模式；
  4. 按 Enter 确认。

  确认框打开后 400 ms 内的按键一律忽略。
- **AC2**：确认框只有在两个条件同时满足时才提供"开始"：链路在线，并且 daemon 报告 Claude 可用。否则确认框写"离线，将存为排队"，按 Enter 后存成一条排队项，标记为"原本要开 session"。
- **AC3**：在线时，设备发出一条**在线请求**。它不写进 outbox，也不会自动重试。daemon 在项目根目录下用参数列表直接执行，不经过 shell：
  ```
  claude --bg --name <key>/<slug> --permission-mode <mode> -- <text>
  ```
  成功后设备显示"已开始 · <短 id>"。这个 session 在看板上出现的时间，p95 不超过 5 秒。
- **AC4**：如果链路在结果回来之前断开，设备显示"结果未知，请在看板确认"，同时把文本存成排队项，标记为"不确定"。这样可能和已经开出的 session 重复，但文本绝不会丢，也绝不会自动重试。
- **AC5**：设备不能指定路径、参数或权限模式，只能发项目代号和文本。daemon 拒绝以 `-` 开头的文本，永远不使用 `bypassPermissions`。权限模式取自项目配置，默认 `plan`。
- **AC6**：失败的情况包括：找不到 Claude、项目不存在、启动失败。设备只显示错误码和一句中文提示，细节只写在 Mac 的本地日志里。文本存成排队项。
- **AC7**：契约测试要用这些恶意文本：`--dangerously-skip-permissions`、`-c`、`--permission-mode=bypassPermissions`、`$(rm -rf ~)`、`; ls`、控制字符、501 字节的文本。每一条要么被拒绝，要么作为**一个原样的 argv 元素**到达。

### US-10 回复 session（F7，P1，G3）
- **AC1**：在收件箱或项目页选中一个 session，按 Enter，进入采集页，类型是"反馈"，目标是这个 session。输入后按 Enter，确认框会写明这次是"直接发送"还是"存为排队"。
- **AC2**：只有下面四个条件同时满足才直接发送：
  - 是后台 session（`kind=bg`）；
  - 状态是 `idle`；
  - 链路在线；
  - daemon 声明支持回复（`caps.reply`），也就是 G3 已通过、并且在配置里打开了。

  发送过程：daemon 先重新查询一次，确认它还是空闲，然后执行 `claude stop <short>`，再执行 `claude --bg --resume <sessionId> -- <text>`（**不能**带 `--permission-mode`，否则 CLI 会另开一个副本；原 session 的 plan 模式会保留。见 docs/gates/cli-gates.md G3），最后确认 session ID 没变。成功后，这个 session 回到"运行中"。
- **AC3**：其他情况一律存成排队项，关联到这个 session，并告诉你原因：交互式 session 要到 v0.2 才支持、session 正在运行，或者设备离线。
- **AC4**：如果 daemon 发现 resume 复制出了一个新 session（出现了新的 sessionId，或者输出里有复制提示），就返回 `E_REPLY_FORKED`，在本次运行期间关闭回复功能，写日志，并把文本存成排队项。
- **AC5**：永远不对 interactive session 执行 resume。

### US-11 状态栏（F8，P0）
- **AC1**：状态栏始终显示这几项：
  - 链路状态：● 在线 / ⟳ 同步中 / ◐ daemon 未响应 / ○ 离线
  - 待同步条数 ↑N
  - 等你的条数 !N
  - 电量
  - 时间：还没同步过时显示 `--:--`
  - 键盘告警计数：只在大于 0 时显示 ⚠kN
- **AC2**：超过 15 秒没收到 daemon 的数据，就切到 ◐（还插着 USB 主机）或 ○（没插）。重新握手后 1 秒内恢复 ●。

### US-12 每日笔记（F9，P1）
- **AC1**：每条笔记追加一行到 `<notes_dir>/YYYY-MM-DD.md`，格式是 `- HH:MM #<key> 文本 ^cpa-<id>`。未归属的笔记不加标签。设备时间未知时，用 Mac 收到的时间，写成 `~HH:MM`。
- **AC2**：写入是幂等的：文件里已经有同一个块 ID，就跳过。如果写失败，daemon 启动时会从事件日志里把缺的行补上。
- **AC3**：`notes_dir` 可以配置，默认是 `~/CardputerNotes`。不默认放在 `~/Documents` 或 iCloud 下，因为这些目录受 macOS 隐私保护（TCC），LaunchAgent 写不进去。
- **AC4**：v0.1 不生成队列的 markdown，用 `cpa queue ls` 代替。

### US-13 键盘可靠性（F10，P1，G1）
- **AC1**：如果新按下的键和已经按住的键在矩阵上构成一个完整的矩形，就判定整帧有歧义：丢弃这一帧，并计数。计数显示在状态栏的 ⚠k 和系统页上。
- **AC2**：看门狗：有键处于按下状态，但按键集合超过 10 秒没有任何变化，就重新初始化键盘，并计数。G1 复现锁死之后，再细化触发条件。
- **AC3**：G1 的验收：连续 10 分钟抄打一段已知文本，字符错误率（CER）不超过 0.5%，没有任何一次超过 1 秒的输入卡顿。

### US-14 中文显示（F11，P0）
- **AC1**：项目名、session 名和队列文本里的中文，用 efontCN_12 正常显示。固件大小不超过 2.5MB。
- **AC2**：daemon 截断文本时按 UTF-8 字符边界切，设备上永远不会出现被切断的半个字符。
- **AC3**：字库里没有的字显示为 `□`；如果 M5GFX 没法检测缺字，就沿用它的默认行为，这点由 HIL 记录。HIL 会用本机真实的 session 名做渲染检查。

### US-15 后台服务（F12，P1）
- **AC1**：`cpa service install` 和 `cpa service uninstall` 安装、移除 LaunchAgent，登录 Mac 时自动启动 daemon。配置里记录 `claude` 的绝对路径；安装时抓取一次登录 shell 的环境变量，只保留白名单里的几项，比如 `PATH`。
- **AC2**：`cpa pause [秒数]`（默认 120 秒）通过本地 unix socket 通知 daemon 暂时让出串口，时间到了自动重新连接。固件工程的上传前脚本会自动调用它。
- **AC3**：`cpa status` 显示 daemon 是否在运行、设备状态、绑定的序列号、Claude 的版本和能力、各项目路径是否有效、outbox 统计。**不显示任何正文。**

### US-16 系统信息（F13，P2）
- **AC1**：Opt+M 打开设置，按 `/` 是设备页（v0.4.3，docs/21 §4.5），显示：固件版本、`dev`、boot id、outbox 条数（含坏条目）、空闲堆、历史最小堆、最大连续块、loop 栈剩余量、幽灵键计数和键盘重新初始化次数、电池电压、daemon 版本；最后同步时间和待传数在设置页的"同步"一行。

## 7. 核心流程

### 7.1 速记：从按键到 Mac
1. 在任何界面短按 G0（或按 Opt+N、Opt+Q、Opt+S），打开采集页。类型由按的键决定，目标是当前所在的项目。
2. 输入文字：Shift 打大写，Fn 层打符号，Backspace 删除（按住会连删）。需要的话，用 Opt+0…9 改目标、用 Opt+N/Q/S 改类型。
3. 按 Enter 或 G0 提交。如果类型是"新 session"，接着走 7.6 的第 3 步。
4. 设备生成条目 ID（MonoId，格式是 `epoch-开机次数-序号`），把条目写成 `<id>.tmp`，关闭文件，再改名为 `<id>.json`，然后才显示"已保存 · 待同步 N"。
5. 在线时，设备立刻发送 `outbox.item`。daemon 依次做这几件事：校验 → 去重 → 追加事件并 fsync → 回复 `outbox.ack` → 渲染每日笔记。设备收到 ack 后删除文件，↑N 减一。
6. 离线时，条目留在 outbox 里，下次握手后按 ID 顺序上传。

### 7.2 连接与握手
1. daemon 找到 VID:PID 为 `303A:1001` 的串口。如果已经绑定过序列号，就只认那一个。打开时用安全顺序：先以 `dsrdtr=True` 打开，再 `rts=False`，最后 `dtr=False`（03 §2）。
2. daemon 发送 `hello`。2 秒没回应就重发，最多 3 次。回应不是本项目的固件，就释放端口，30 秒后再试。
3. 握手成功后，daemon 依次下发 `time.set`、`projects.snapshot`、`sessions.snapshot`、`queue.snapshot`；设备同时开始上传 outbox。
4. daemon 每 5 秒发一次 `ping`。设备在 `pong` 里报告自己手上各份快照的版本号（rev），版本落后了 daemon 就重新推送。任何一方 15 秒收不到对方的数据，就判定掉线。
5. 设备的 boot id 变了，或者 `up_ms` 变小了，说明设备重启过，回到第 3 步。daemon 永远不会通过拨动控制线来复位设备。

### 7.3 项目看板
1. 只有设备在线时，daemon 才每 3 秒执行一次 `claude agents --json`。设备不在线时完全不轮询。
2. 对每个 session，先对 `cwd` 取 realpath，再按最长前缀匹配已登记项目的根目录。匹配不上时，用 `git rev-parse --git-common-dir` 再试一次（结果会缓存）。还是匹配不上，就归到"其他"。
3. daemon 记录每个 session 进入当前状态的时间，算出每个项目运行中、等你、排队各有多少，生成有上限的快照。快照内容变了，`rev` 加 1 后下发。只有时长变化不算内容变化，时长由设备自己往上加。

### 7.4 等你收件箱
1. daemon 判断每个 session 是否"需要你"：状态是 `waiting`；或者状态是 `idle` 并且持续了 60 秒以上；同时这个 session 不在你的忽略列表里。
2. 设备对比前后两份快照，发现有新的"需要你"，就弹出提示，并更新 !N。
3. 选中一项后：
   - 按 Enter：回复（7.5）
   - 按 Opt+D：忽略
   - 后台 session 会显示 `claude attach <short>`；interactive session 显示"在 Mac 上处理"。

### 7.5 反馈：直接发送，或者存为排队
1. 选中一个 session，按 Enter，输入反馈，按 Enter。
2. 确认框写明这次是"直接发送"还是"存为排队"。只有 US-10 AC2 的四个条件全部满足时，才会是"直接发送"。
3. 直接发送：设备发 `agent.reply`，daemon 执行"stop → resume → 核对 ID"，再回复 `agent.result`。
4. 存为排队：设备在 outbox 里写一条 `kind=queue`、`intent=feedback` 的条目，关联这个 session。v0.1 里，这类排队项只能用来开新 session；把它重新发回原来那个 session，要到 v0.2。

### 7.6 开新 session
1. 在项目里按 Opt+S，或者在队列项上按 Enter。
2. 输入任务描述，按 Enter。
3. 确认框显示："在 <key> 开新 session（plan 模式）：『前 60 个字』 Enter 开始 / Esc 取消"。确认框打开后 400 ms 内的按键忽略。
4. 离线时：存成排队项（`intent=spawn`），提示"离线，已排队"，流程结束。
5. 在线时：设备发出 `agent.spawn{project, text, qid?}`，这条请求不进 outbox。
6. daemon 逐项检查：链路是否 Ready、项目是否已登记、路径是否有效、Claude 是否可用、文本是否合法（长度、UTF-8、不以 `-` 开头）。任何一项不通过，就回复 `agent.result{ok:false, code}`。
7. daemon 生成 session 名 `<key>/<slug>`，然后执行 7.6 里那条 argv。从 stdout 解析出短 id；如果解析不到，就对比执行前后两次 `agents --json` 的差别，按名字找出新 session。然后写事件，回复 `agent.result{ok:true, name, short}`。
8. 下一轮轮询后，新 session 出现在看板上。

### 7.7 离线语音（v0.2，前提是 G2 通过）
1. 长按 G0（≥500 ms）开始录音，保留按下前 300 到 500 ms 的预录。
2. 录音写到 SD 卡：文件名 `/rec/<id>.wav.part`，每 5 分钟分一段。录完后改名，算出 SHA-256，登记进 outbox。没插 SD 卡时不录音，并给出提示。
3. 联网后分块上传，daemon 核对 SHA-256 后再回复 ack，然后转写。转写结果变成笔记或排队项，执行类操作仍然要在线确认。

## 8. 按键方案（v0.1 定稿；v0.4.0 起按本节的表）

> **v0.4.1 的改动**（docs/20 D1–D9，2026-10-22 定）：主页上 R、L 要按 Opt；编辑器里 ` 退出、Fn+` 打出反引号；开 session、回复的确认框上 ` 回到编辑器；会议的开始框和结束框有 Opt+L、会自己关掉；会议页上 ` 只提示；浮层下按住 G0 也录便条；菜单开着时按菜单上写着的组合键会执行；用电池时熄屏即锁。下面的表已按这些改过，改过的行标着 v0.4.1；和 v0.4.0 的对照见 docs/releases/v0.4.1.md 的"按键变化"。

> v0.3 加了录音的键（§8.6），v0.4.0 加了主页、Tab 菜单和锁屏（§8.2、§8.3、§8.7、§8.8；设计见 [13 §5–§7](13-assistant-v2-plan.zh-CN.md)）。
> 所有绑定都写在 `firmware/app/lib/input/keymap.cpp` 的 `kKeymap` 里，每个动作的中文说明在 `firmware/app/lib/help/action_help.cpp`。本节的表、README 的按键表要和这两处一致，改键时一起改（[CONTRIBUTING](../CONTRIBUTING.zh-CN.md) 的 PR 检查单有这一行）。

### 8.1 约束
- **只用单键和两键组合。** 三键组合一律不用：Fn+Shift、Ctrl+Opt、Ctrl+Alt 加第三个键都会出幽灵键（02 §6）。keymap 里的每个组合都要过 native 静态检查（05 §5.7）。
- **G0 是专用的采集键**，只在固件运行时读取。
- **Opt 是本应用专用的一层**，因为 Opt 在 HID 键盘协议里没有含义。Ctrl 和 Alt 先不用，留给以后。
- **防误触**：确认框打开后 400 ms 内的按键一律忽略。
- **只有一张按键表**（v0.4.0）：Tab 菜单从 `kKeymap` 生成。菜单里的一行、主页上的一个格子，都是"替你按那个键"，所以效果和直接按相同。`test_action_help` 保证每个动作都有一句说明。
- **一个字母只代表一件东西**（v0.4.0）。预留、暂不绑定的字母见 [13 §5.2](13-assistant-v2-plan.zh-CN.md)；不用 Z（测试拿 Opt+Z 当"没绑定"的例子）。
- **按键分发顺序**：锁屏关卡 → 亮屏 → Tab 菜单 → Tab 和 Opt+L → 录音浮层 → 浮层（采集页、确认框）→ 全局组合键 → 前台模块，最后最多重放一个键（05 §5.6）。所以在采集页里按 Opt+1…9 是改目标，不是切换项目。

### 8.6 录音浮层（v0.3）

录音的设计见 [11 §4.1](11-m3-design.zh-CN.md)。录音期间这些浮层吃掉所有键，表里没有的键不起作用。

| 在哪 | 按键 | 作用 |

| 便条（按住 G0 时） | 1 到 9 / 0 | 归到第 N 个项目 / 不归属 |

| 免提便条（点两下 G0） | G0 | 按下就结束并保存（松开不算第二次；结束后 0.35 秒内再点一下也不算，不会打开速记）；Tab 菜单开着时也是，菜单关掉 |
| 免提便条 | 1 到 9 / 0 | 归到第 N 个项目 / 不归属 |
| 免提便条 | Tab | 打开菜单，只有"本页"和"控制"两页；"G0 结束并保存"一行只是说明，按 Enter 不结束；按 Opt+L 菜单关掉、锁屏，录音不停（docs/20 D9） |
| 免提便条 | Opt+L | 锁屏，录音不停 |
| 免提便条 | 其他键 | 不起作用（防口袋误触），不会结束录音 |
| 会议确认框 | Enter / `` ` `` 或 Fn+` | 开始 / 取消。打开后 400 ms 内的 Enter 不算，屏幕提示"太快了，再按一次 Enter"（v0.4.1） |
| 会议确认框 | 其他键（字母、数字、空格……） | 取消（v0.4.1，docs/20 D3）；15 秒没人按也取消，从最后一次按键算 |

| 会议页 | G0（短按或按住）、空格 | 加 ★ |
| 会议页 | 1 到 9 / 0 | 归到第 N 个项目 / 不归属 |
| 会议页 | Opt+R | 结束会议：先弹结束确认框，Enter 结束，`` ` `` 继续录；10 秒没人按就回到会议页（v0.4.1） |
| 会议页 | `` ` ``、Enter | 只提示"开会中：Opt+R 结束"（v0.4.1，docs/20 D3：以前 `` ` `` 打开结束确认框） |
| 会议页 | Tab | 打开菜单，只有"本页"和"控制"两页（v0.4.0） |
| 会议页 | Opt+L | 锁屏，录音不停（v0.4.0） |

1 到 9 / 0 各是哪个项目，便条页和会议页上一直写着（gh #53）：按数字键那一排的顺序，数字是键帽，后面是项目键，`0` 是"不归属"；现在选的那个亮着，按下数字就换过去，按了没有项目的数字写 `?`。项目多时多占一行，长的项目键截短（不加"…"）；会议页上项目太多时不写 0（标题写着去向）。

### 8.7 Tab 菜单（v0.4.0）

按 Tab 打开，任何页面都能按（按住 G0 说便条时和锁屏时除外；免提便条可以）。菜单有三页：

| 页 | 内容 |
|---|---|
| 本页 | 这一页的键：应用自己写的行（`help()`；应用没写时是列表页的键），浮层上是 `kKeymap` 里那一层的绑定；最后补上 Opt+L（这一页还没列出时）。不列 Tab |
| 去哪 | 全局层的绑定：先列主页、项目看板、等你、Opt+1-9、设置，再列其余的。Opt+L 放在"控制"页 |
| 控制 | 锁屏一行，然后是只读的事实：声音（关，录音不出声）、电池、SD 卡剩余和待传、Mac 链路和 cpad 版本 |

在采集页、确认框、会议页上打开时没有"去哪"页，不能从菜单跳到别处，草稿和正在录的音都不受影响。确认框上没有 Opt+L 这一行。

| 菜单里按 | 作用 |
|---|---|
| `;` / `.` | 选上一行 / 下一行 |
| `,` / `/` | 换到上一页 / 下一页 |
| Enter | 关掉菜单，再替你按下这一行的键，效果和直接按相同。一组键的行（如 `Opt+1-9`）和"按住 G0"那一行只是说明，Enter 不执行 |
| 字母 | 在"去哪"和"控制"页：等于按 Opt+那个字母（只在这一页有这一行时）。在"本页"上：全局键和锁屏的字母都等于按 Opt+那个字母，所以 Tab 再按 P 两下就到项目看板；在采集页、确认框、会议页上，"本页"的字母被菜单吃掉 |
| G0（短按或按住） | 关掉菜单，G0 照常起作用：开会时加 ★，不开会时记一条或录便条 |
| Tab、`` ` ``、Backspace、Fn+` | 关掉菜单 |
| 菜单上写着的组合键（如 Opt+L） | 关掉菜单，再照常起作用（v0.4.1，docs/20 D9） |
| 其他键 | 被菜单吃掉，不起作用 |

正在录音时，菜单保留状态栏那一行，所以 ● 和计时一直看得见。

### 8.8 锁屏（v0.4.0）

按 Opt+L 后屏幕马上熄灭，键盘锁住，**插着 Mac 也熄屏**。锁屏前的页面、采集页的草稿、正在开的会都原样留着，录音不停。

| 锁住时按 | 不开会 | 开会中 |
|---|---|---|
| Opt+L | 亮出锁屏卡片，开一个 3 秒窗口；窗口内按 Enter 就解锁，回到锁屏前的页面 | 同左 |
| G0 短按 | 亮出锁屏卡片 3 秒，这 3 秒里按住 G0 就录 | 加 ★ |
| 按住 G0，没有先点一下 | 只亮出锁屏卡片，写"没有在录 / 松开，点一下再按住"，不录音（这一次按住到松开都不录；v0.4.1 起卡片亮着时这样按也不录） | 加 ★ |
| 按住 G0，先点了一下 | 录语音便条；松开后有 0.6 秒宽限（gh #51）；录完卡片亮 2 秒写结果，再回到黑屏锁定 | 加 ★ |
| 点两下 G0，卡片是按键点亮的 | 免提录语音便条（v0.4.1，gh #51；黑屏时、卡片自己亮着时的第一下只亮卡片，不算）；开始后卡片熄灭，左上角写"● 免提 0:12" | 加 ★ |
| 免提便条录着，按 G0 | 卡片亮着：结束并保存，仍锁着，卡片再亮 3 秒写结果（"√ 已存 0:06"）；屏幕黑着：只亮出卡片（写"免提录音中：按 G0 结束"，不写"没有在录"），录音不停 | — |
| 其他任何键 | 不起作用，也不点亮屏幕 | 同左 |

- 用电池时屏幕因为 60 秒没按键熄灭，就自动锁上（v0.4.1，docs/20 D2）；插着 Mac 不自动锁。
- 卡片自己亮的时候（v0.4.1，docs/20 D7）：上锁那一刻 2 秒（"已锁屏"）；锁着时录音结束 2 秒，写结果；插着 Mac 时等你的数量增加 3 秒。锁着按 Enter、空格不亮。
- 锁在采集页上时草稿留着；先点一下再按住 G0 照样录便条，草稿不受影响，解锁后还在。
- 锁屏卡片只显示时间、日期、电量和数量（等你、待传的录音段数、↑N），不显示项目名、session 名或任何正文。锁住时不弹提示。
- 正在录音时，背光最暗只到"调暗"，左上角一直显示 ● 和计时；便条在麦克风打开之前显示"● 准备"，看到 ● REC 再说话。
- **锁屏不是安全锁**：没有 PIN，只防口袋里误触、不让旁人看到内容（[SECURITY.md](../SECURITY.zh-CN.md)）。

## 9. 在线与离线状态

| 状态 | 怎么判定 | 这时能做什么 | 状态栏 |
|---|---|---|---|
| 在线 | 链路 Ready，并且 15 秒内收到过 daemon 的数据 | 全部功能 | ● 在线 |
| 同步中 | 在线，并且 outbox 里还有条目 | 全部功能 | ⟳ ↑N |
| daemon 未响应 | 插着 USB 主机（`isPlugged` 为真），但还没握手，或者 15 秒没收到数据 | 速记可用；看板显示上一次的数据；执行类操作降级为排队 | ◐ |
| 离线 | 没插 USB 主机。只接充电器也算这一种 | 同上 | ○ 离线 |

**规则**：离线时，任何执行类操作都不会先缓存、等联网后再执行（原则 2）。

## 11. 隐私与安全要求

**v0.1 的信任边界**：物理插着 USB，加上当前登录的这个 macOS 用户。daemon **不监听任何网络端口**，本地控制只走 `$CPA_HOME` 里权限为 0600 的 unix socket。

- **S1 只认自己的固件，并绑定序列号。** daemon 只接管握手回复为 `cpa-fw/` 的端口；第一次握手成功后绑定 USB 序列号（US-04）。v0.1 **不做配对**：配对码没有密钥做后盾，任何固件都能冒充同一个 `dev`，做了也只是摆设。正式配对和无线功能一起放到 v0.3。
- **S2 设备控制不了命令。** 设备只能发送项目代号、文本，以及 daemon 自己下发过的 `qid` 或 `sid`。路径、参数和权限模式都由 daemon 根据登记表决定。
- **S3 防参数注入。** daemon 用参数列表调用 CLI，不经过 shell。正文放在 `--` 之后，作为一个参数传入。以 `-` 开头的正文直接拒绝。`sid` 必须能在最近一次 `agents --json` 的结果里唯一对上。
- **S4 显式指定权限模式。** 每次都传 `--permission-mode`，取自项目配置，默认 `plan`。拒绝 `bypassPermissions`；只有项目配置里明确写了 `auto` 才会用 auto。这样从设备开出的 session，最坏也就是"一个 plan 模式的 session"。
- **S5 执行只能在线进行。** 开 session 和回复只能通过在线请求发出，需要在确认框里按键确认，并且要求链路处于 Ready。outbox 里没有能触发执行的类型，所以离线写下的东西不可能在你不在场时被执行（US-03 AC6）。
- **S6 两端都校验输入。**
  - 消息类型必须在白名单里；
  - 单行不超过 2048 字节，正文不超过 500 字节；
  - 必须是合法的 UTF-8；
  - 控制字符替换成空格；
  - ID 要符合格式。

  不合法的消息丢弃并计数。
- **S7 错误信息不泄露细节。** 设备只收到错误码。路径、命令输出这些细节只写在 Mac 本地日志里。日志里正文只记长度和哈希的前 8 位，除非显式设置 `CPA_LOG_CONTENT=1`。
- **S8 数据只在本机。** `$CPA_HOME` 目录权限 0700，文件 0600，启动时检查。没有云、没有账号、没有遥测。
- **S9 设备上尽量少留数据。** outbox 收到 ack 就删除；session 信息只放在内存里；设备拿不到项目路径。
- **S10 不放密钥。** v0.1 的设备上没有任何密钥，仓库里也没有硬编码的密钥。
- **S11 不开 Flash 加密和 Secure Boot。** 已知风险：拿到设备的人能读出 LittleFS 里**还没同步**的条目。缓解办法：同步后立即删除；状态栏显示待同步数量；v0.2 评估加 PIN 锁。
- **S12 调试日志里不出现用户内容。** 正式固件设 `CORE_DEBUG_LEVEL=0`；只有测试版固件才有调试消息。

## 12. 非功能需求与工程要求

### 性能（全部用 p95）

| 指标 | 目标 | 怎么测 |
|---|---|---|
| 按 G0 到采集页可以输入 | ≤650 ms（v0.4.1 起含 0.35 秒的点两下窗口，gh #51；以前 ≤300 ms） | HIL：注入按键，读取测试版固件的 `debug.state` 时间戳 |
| 提交到显示"已保存" | ≤100 ms | 真机设备测试：连续保存 200 次 |
| 握手后同步 100 条 outbox | ≤5 s | HIL |
| Mac 上状态变化到设备更新 | ≤5 s | HIL：fake-claude 翻转状态 100 次 |
| 确认开 session 到它出现在看板上 | ≤5 s | HIL，使用 fake-claude |

### 资源预算
- 设备：
  - 空闲堆 ≥150KB，最大连续块 ≥64KB
  - 静态 RAM ≤96KB
  - loop 栈 16KB，在系统页显示剩余量
  - `AppState` ≤4KB
  - 固件 ≤2.5MB
- outbox 存储：LittleFS 数据分区 1.5MB，最多存 200 条，并且剩余空间不低于 64KB。
- daemon CPU：没有设备连接时不轮询；设备在线时平均占用不超过单核的 5%。按每 3 秒轮询一次、每次约 0.1 秒算，大约是 3%。

### 可靠性
- **v0.1**：
  - native 测试在每一步存储操作处注入崩溃，结果 0 丢失、0 重复；
  - 10 次人工断电，0 丢失；
  - 连着 USB 浸泡 1 小时，串口不卡住，消息不丢失。
- **v0.1.x**：8 小时浸泡、100 次断电。原来写进 v0.1 完成标准的这两项挪到这里，因为每次断电都必须把开关拨到 OFF 并拔线，100 次在 v0.1 里不现实。

### 工程要求（对应你的开发规则）
- **数据不可变。**
  - Mac 端所有状态都从只追加的事件日志推导出来，用 frozen dataclass 表示。
  - 固件里所有业务逻辑都是纯函数：`旧状态 + 输入 → 新状态 + 副作用`。状态只会被整体替换，不会被原地修改。
  - 硬件缓冲（串口收发环、显示 sprite）天生是可变的，只允许出现在 `hal/` 和 `usb_transport/` 里（§16 待定 5）。
- **代码规模。**
  - 每个文件 200 到 400 行，最多 800 行；函数少于 50 行；嵌套不超过 4 层。
  - 目录按功能划分。
  - CI 里用 `tools/repo/check_sizes.py`、lizard、ruff 检查，从 WP1 起就开；clang-tidy 的函数规模规则在 WP4 加。
- **TDD（RED → GREEN → REFACTOR）**，三层测试：
  - 单元测试：固件纯逻辑用 `pio test -e native`，daemon 用 pytest。
  - 集成测试：daemon 对接用 pty 模拟的设备，再加一个放在 PATH 上的假 `claude`。
  - 端到端测试：真机 HIL 脚本，加一份人工检查单。

  覆盖率目标 80%，固件纯逻辑和 daemon 分开统计。
- **安全。** 每次提交前确认：没有硬编码的密钥；输入都做了校验；错误信息里没有敏感内容。
- **提交信息** 用 conventional commits 格式（`feat:`、`fix:` 等）。

### v0.1 的完成标准（DoD）
- 所有 P0 故事都在真机上满足验收标准。P1 故事要么满足，要么明确挪到 v0.1.x。
- 三层测试全绿，覆盖率 ≥80%。完成 1 小时浸泡、断电故障注入和 10 次人工断电。
- README 的 15 分钟目标要实测：在一个**全新的 macOS 用户账户**下，从克隆仓库开始，完成刷固件、`cpa service install`、`cpa project add`，直到在设备上看到看板，全程计时。
- 有 LICENSE（Apache-2.0）、NOTICE（列出致谢和许可证）、CONTRIBUTING 草稿，ADR-0001（工具链）和 ADR-0002（协议 v0）。

## 16. 需要你拍板的问题

下面每一项都给了默认值。不回答就按默认值做；标 ★ 的需要在对应的里程碑之前确认。

1. ★ **设备开出的 session 用什么权限模式？** 默认 `plan`，可以按项目改成 `acceptEdits`；`auto` 只有明确写了才用；`bypassPermissions` 永远不用。（M3 之前确认）
2. **工具链**：接受 pioarduino 只有一个维护者的风险吗？默认：G2 通过就用 B，并锁死 release 包的地址。
3. **反馈怎么送达**：你主要在终端还是在 Claude 桌面端里跑 session？v0.1 默认不升级 CLI，反馈进队列；v0.2 再评估升到 ≥2.1.287。
4. **笔记写到哪里**：默认 `~/CardputerNotes`。如果要直接写进 Obsidian vault，而 vault 在 `~/Documents` 或 iCloud 下面，就需要给 uv 的 Python 授予"完全磁盘访问权限"。
5. **不可变规则的例外**：硬件缓冲只允许出现在 `hal/` 和 `usb_transport/` 里，可以接受吗？默认接受。
6. **收件箱规则**：`waiting` 立即进入，`idle` 持续 60 秒后进入，不会因为空闲太久而自动隐藏。默认就是这样。
7. **速记的默认目标**：跟着当前所在的项目走，还是一律"未归属"？默认跟着当前项目。
8. **丢失设备时的风险**：还没同步的条目是明文，可以接受吗？默认 v0.1 接受，v0.2 评估加 PIN 锁。
9. **命名**：`cpa`、`cpad`、`cpa-fw`、`$CPA_HOME=~/Library/Application Support/CardputerAssistant` 这些名字可以吗？默认就用这些占位名。
10. **session 开在哪里**：直接开在项目主目录，还是开在独立的 git worktree 里？默认开在主目录。

## 17. 评审意见处理记录

**全部采纳的阻断问题（15 条）：**
1. 离线的开 session 和反馈请求不再进 outbox，改成在线请求加确认（S5、US-09、US-10）。
2. 重写 G3，只测"空闲但进程还活着的后台 session"，验证 stop 再 resume 后 ID 不变；永远不 resume interactive session。
3. 加 `--`，拒绝以 `-` 开头的正文，`sid` 必须能对上，并用恶意文本做契约测试（S3、US-09 AC7）。
4. 显式传入 `--permission-mode`，默认 `plan`（S4、§16 待定 1）。
5. v0.1 不装 hooks、不开 TCP 端口，`cpa pause` 改走 unix socket。
6. 删掉设备配对，改为校验固件 + 绑定序列号。
7. outbox 只用 LittleFS，收到 ack 就删除。不删除旁边已有同名 `.json` 的 `.tmp`（05 §5.9）。
8. 接收缓冲设为 8KB，单行最长 2048 字节，daemon 端用 credit 做流控。
9. 登记项目时不要求是 git 仓库。
10. 中文显示升为 P0，关闭 G5。
11. `claude attach` 的提示只对后台 session 显示。
12. 协议以 05 §6 为准，补上 `queue.done` 和 `inbox.dismiss`。
13. loop 栈改成 16KB，按切片做 reducer，加上 `sizeof(AppState)` 的断言。
14. 工具链由 G2 第 0 天决定，写成 ADR。
15. daemon 只用 pyserial 和标准库，存储用 jsonl。

验收标准也都改成了能测的形式（CER、故障注入、p95 和对应的测法、在新账户里计时）。

**全部采纳的范围削减：** 配对、hooks/HTTP、SD 卡、Leader 键、manifest 校验、运行时 jsonschema、Starlette 等依赖、SDL 截图测试、session 拉取协议、离线轮询、队列 markdown、8 小时浸泡和 100 次断电，以及电池省电只保留"灭屏 + 按键唤醒"。

**没有采纳或做了修改的部分（附理由）：**
- **`time.set` 保留了 `tz_min`。** 状态栏要显示本地时间，这只是一个整数字段，成本可以忽略。`device.reboot` 已经删掉，HIL 改用测试版固件专有的 `debug.reboot`。
- **幽灵过滤没有改成"先挂起、松开后再判断"。** 最常见的情况是按住修饰键再点一个字母，这时真实按键和幽灵键同时出现、同时消失，挂起也判断不出来。所以保留"丢弃 + 计数显示"，由 G1 的 CER 测试来兜底。也没有加"丢键时蜂鸣"：v0.1 不启用扬声器，避免和 v0.2 的麦克风切换问题搅在一起。
- **CI 里的 lint 不全部推到 M2 之后。** `check_sizes`、ruff、lizard 都很便宜，从 WP1 起就开；只有 clang-tidy 放到 WP4。
- **"队列项标为完成"不再离线写进 outbox**，改成只能在线操作。这是为了简化（离线时设备手上的队列数据本来就可能过期），评审没有提出这个问题。
- **"速记模块"并进了 shell 里共用的采集页。** v0.1 的模块只有 `board`、`inbox`、`system` 三个。

## 隐藏按键（彩蛋，v0.5.0）

不进提示栏，也不进 Tab 菜单，只记在这里。都不出声、不弹 toast，不写任何文件（只在内存里），也不改协议。

| 按键 | 在哪里有用 | 做什么 |
|---|---|---|
| `Opt+W` | 主页；锁屏卡亮着、显示时钟时 | 摸摸 Mando：他跳一下，头上冒个心，说一句（汪! / 嘿嘿 / 摸摸 / 再来，英文 Woof! / Hehe / Pat pat / Again，随机，不连着重复），旁边计数"摸 ×N / pats ×N"（说"摸摸 / Pat pat"时只写"×N"，放不下时不写），显示 1.5 秒；每第 100 下说"今天也辛苦了 / You did great today"。录音中、编辑器或菜单开着、别的页面、锁屏卡熄灭或正显示录音结果时都不起作用。 |

另外两个不用按键的小彩蛋（`firmware/app/lib/eggs/mando_eggs.h`）：

- **看钟点的心情**（时间未知时照旧）：23:30 到 5:00 锁屏卡的牌子是"夜深了 / Bedtime"，多一个 z，主页问候是"夜深了 / Late night"；5:00 到 7:00 牌子是"早起鸟 / Up early"，Mando 醒着；周六周日牌子是"周末啦 / Weekend"，主页问候是"周末好 / Weekend"。
- **搞定啦**：在主页上时，等你的 session 从有变成没有，Mando 跳一下，卡片里显示"搞定啦 / All clear"（问候已经说"都处理完了"），2.5 秒，只一次；刚录得太短、他头上的"?"还在时不盖掉它。
