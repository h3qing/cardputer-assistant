## v0.2.0 · Launcher + microSD 存储

这一版让 Cardputer ADV 上的速记和待同步条目改存到 **microSD 卡**，并且能和其他固件（比如出厂固件、Bruce）一起装在 **bmorcelli Launcher** 里随时切换。

### 新功能
- **SD 卡存储**：待同步条目存在 SD 卡的 `/cpa/` 下。FAT 上不能保证原子改名，所以用了一套不依赖改名的提交协议。没插卡时退回内部分区 `cpafs`；插卡开机时，内部分区里还没同步的条目会**恰好一次**地迁移到 SD 卡。
  - 真机实测：保存 p95 **10.5 ms**（v0.1 的内部 Flash 存满 200 条时是 108–158 ms）；100 条积压的笔记 1.55 秒内全部送达；迁移 20 条，每条都恰好送达一次。
- **兼容 Launcher**：只发一个二进制，启动时自己判断是不是经 Launcher 启动。内部分区从 `spiffs` 改名为本固件专用的 `cpafs`，所以**不会碰到 Launcher 下其他固件共用的 `spiffs` 分区**。
  - 已实测：Launcher 2.9.1 经串口装好出厂固件和本固件，本固件启动后报告 `launcher=yes`、`store=sd`。
- **发布产物改名**：`cpa-v0.2.0.bin`（合并镜像，可以从 0x0 整片烧，也可以交给 Launcher 安装，Launcher 里显示为 cpa-v0.2.0）和 `cpa-v0.2.0-app.bin`（只有 app，从 0x10000 烧）。
- **单键返回**（#15）：输入框为空时按一下 Backspace 就退出；不在输入框时，按左上角那个键就返回。
- **协议**：`hello` 新增两个可选字段 `store`、`launcher`（协议版本 `v` 仍是 0）；主机发出的每一行都以 `{` 开头或者是空行，避免被 Launcher 的串口控制台当成命令执行。
- **daemon**：`cpa status` 显示存储位置和启动方式；控制 socket 路径太长时，会说清楚是哪个路径、上限多少、该怎么改（#4）。

### 修复
- 补丁版 SD 驱动：core 2.0.17 自带的驱动初始化不了部分大容量卡（ACMD41 参数问题），已打补丁，放在 `firmware/third_party/SD`。
- CI：GCC 13 的 `-Wformat-truncation` 问题；测试夹具读写 fake-claude 状态文件时的竞态。
- 上传前的脚本不会再缩短 daemon 已有的更长暂停时间。

### 验证
- 固件 302 个 native 测试，覆盖率 96%；daemon 593 个测试，覆盖率 97.3%；HIL 工具 175 个测试。
- 真机：设备测试（SD 存储、内存预算）；HIL 在有卡的固件上 13/13、无卡的固件上 10/10；迁移；单键返回；连续运行 10 分钟没有丢失或重复。

### 安装
- **直接烧**：`esptool.py --chip esp32s3 write_flash 0x0 cpa-v0.2.0.bin`，或者在源码目录里执行 `pio run -e cardputer-adv -t upload`。
- **通过 Launcher**：装好 Launcher 后，按 RST 再按 Enter 进入菜单，用串口命令 `flash firmware cpa-v0.2.0 <字节数>` 安装 `-app.bin`（见 docs/07 的 G-L1）。安装前先执行 `cpa pause`，免得 daemon 抢占端口。
- SD 卡必须是 FAT32。超过 32GB 的卡出厂一般是 exFAT，要先在 Mac 上格式化。

### 已知问题
- **#14**：开关在 ON（用电池）时插 USB，Mac 检测不到这根线，拨到 OFF 就能连上。推测是 VBUS 被反灌，还在等实验确认。
- 还没做的手动检查：固件切换和四种复位（G-L2）、和 Bruce 共存（G-L3）、拔卡开机、真实断电、60 分钟长测（见 docs/07）。
- 内部分区存满时，保存 p95 仍然高于 100 ms；只在没插 SD 卡时才会遇到。
