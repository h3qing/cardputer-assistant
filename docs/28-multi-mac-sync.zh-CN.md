## 0. 一页摘要

1. **你担心的事今天是真的**（§1）：任何一台连上的 Mac 都会把设备上的录音全部拉走，校验通过后设备立刻删掉自己的那份 [源 fw/rec/file_req.h:7-8；docs/11:341]。拉错了 Mac，设备上就没了，另一台 Mac 也拿不到。
2. **平衡点一句话**：**设备是信差，每台 Mac 是档案柜。** 录音在送到"该去的那台 Mac"之前一直在设备上；送到以后设备再**留底**几天；送错了可以在设备上"再交一次"，而且**这次不会再交给刚才那台**。分组（1–9）在设备上存一份镜像，换 Mac 不用重新分组；转写、归档状态、文件夹链接仍只在各自的 Mac 上。
3. **先防再救**：插上 Mac 时如果有**离线录的**录音，屏幕上先停 5 秒：`离线 3 条 → 这台 · Tab 不给`。标对了什么都不用按（0 下），不对按 Tab 再 Enter（2 下），这几条就不给这台 Mac（§3.2，D11）。这是最常见的标错：路上离线录的，跟着上一次连的 Mac 走。
4. **再交一次不会被同一台吃掉**（§3.4）：每次交出时，设备在账本里记下收件那台 Mac 的 `host_id` 哈希（4 B；`hello.host_id` 今天就在线上 [源 fw/protocol/messages.h:82；decode_host.cpp:16]）。"再交一次"的录音对那台 Mac **不可见**，只列给别的 Mac。
5. **留底**（§3.3）：默认 **7 天**，段数上限由开机扫描表算出（默认构建约 1260 段，远超 7 天的量），空闲 < 1 GB 时从最旧的整次录音删起。留底**对所有 Mac 都不可见**。按**整次录音**留和删，不拆会议。
6. **账本 `SENT.L`**（§3.4）：每个 epoch 目录一个只追加的小文件，每条 28 B、有魔数和 CRC，打开追加前先截掉残尾，所以掉电最多丢最后一条；每次写都先 fsync 再回 ack。只有音频任务写它（单写者）。丢一条的后果一律是"多交一次"或"改归属没生效、屏幕上看得到"，不会丢录音。
7. **留底是明文**（S1 在 SEAL 之前，§5）：`↑0` 不再等于"卡上没有明文"。锁屏和 系统 → 存储 要显示留底段数；docs/18 的"去不信任的 Mac 前先清零"改成"先清零、再清掉留底"。留底开不开是 👤 第 2 条。
8. **分组**（§4）：Mac 仍是编辑的地方。设备存镜像（key、名字、编号 + 身份哈希 `tid`）。**一套还是两套（家 / 公司各一套）是 👤 第 1 条**：一套 = 只分一次组，但公司 Mac 看得到家里的分组名；两套 = 家、公司各分一次，换的是坏掉的 Mac 才省事。默认一套，因为换电脑、重新分组多半就是家和公司之间。
9. **合并不删东西**（§4.3）：每台 Mac 存上次同步的整张表（不只哈希）；从设备拉回来时**只加不删**，设备上没有的分组在本机只是"没编号"；两边都改了按 key 取并集，名字冲突这台赢、另一份存档。
10. **新 Mac**：绑定（在设备上按 3–4 下，docs/27 §3.2，这是安全闸，**省不了**）以后，Mac app 一行"设备上有 5 个分组 [用这些]"。推翻 docs/27 D12 的一半，只限名字和编号（§4.4）。
11. **协议**：都是只新增、`v` 仍为 0。录音：`file.items` 每项加可选 `foreign`（§3.6）；按 `host_id` 过滤是行为变化、不是格式变化。分组：`projects.snapshot.tid`、`revs.ptid`、新请求 `projects.get` 和回复 `projects.items`（§7）。
12. **SEAL 以后**（§6）：默认**只封给当前档案**（docs/26 不改）；留底和改归属在 SEAL 后只能在收件人允许时用，否则灰掉。"离线录音封给两边"降为可选（👤 第 3 条），并写明它削弱 docs/26 的目标。
13. **分期**（§8）：S0 只动 Mac（导出包救急）；**S1a** 账本 + 留底 + 主机哈希 + 插上 5 秒提示 + 一项"把最近交给 ·3F2A 的再交一次"（不等 v0.8，约 2 个 PR + 一道掉电闸）；S1b 可翻的留底列表；S3a（选一套时）在 v0.8 之前就上设备镜像和新 Mac 采用；S2 改归属跟 v0.8；S3b 两套镜像；S4 跟 SEAL。
14. **18 条决定**都有默认（§10.1）；要你回答的 6 件在 §10.2。

## 2. 需求拆开

| 需求 | 意思 | 本文 |
|---|---|---|
| 给另一台 Mac 的录音，不能因为先连了这台就没了 | 录音被不该拿的 Mac 拿走，该拿的拿不到 | §3.2 插上先提示（防）；§3.3–3.4 留底 + 再交一次（救） |
| 录音和应用的数据也要在设备上存一份 | 设备上也要有一份 | §3.3 留底（有期限）；不做"设备永久归档"（D1） |
| 分组这类数据也存在设备上 | 分组在设备上有一份 | §4 设备镜像 |
| 插上一台 Mac，设备上的数据不能就此作废 | 插上 Mac 不该让设备上的东西消失 | §3.3 |
| 换电脑不用重新连接、重新分组 | 换 Mac（多半是家 ↔ 公司）少做事 | 分组：§4，取决于一套还是两套（👤 1）；连接：绑定仍要在设备上按 3–4 下（docs/27 §3.2），这是安全闸，不省 |

## 3. 录音：设备是信差

### 3.1 东西放哪（总表）

| 东西 | 设备 | 每台 Mac | 说明 |
|---|---|---|---|
| 没交出的录音（音频 + `.M`） | **是**，直到交给对的 Mac | — | 今天就是这样 |
| 交出后的录音 | **留底**：默认 7 天，按整次录音（§3.3） | 是，长期 | 新增 |
| 交给了谁 | 账本里每段一个 4 B 主机哈希 | 自己知道 | 新增，只用于"再交一次时别给它" |
| 录音的归属档案 | `.M` 的 `prof`（docs/18，录的时候定，永不改）+ 账本里的改归属 | manifest 里记一份 | 改归属只在设备上 |
| 转写、摘要、归档状态、星标、隐藏 | 否 | 是 | docs/23、docs/27 §4.1，不变 |
| 1–9 分组（key、名字、编号） | **是**，镜像（一套或每档案一套，👤 1） | 是（编辑在这里） | §4 |
| 分组链的文件夹、权限模式、hooks | 否 | 是 | 会执行东西的，永远不跨（docs/27 D12） |
| 去向（Opt+字母） | docs/18 的缓存，只给离线用 | 是 | 去向 id 每台 Mac 各自的 [源 docs/14 §2.2]，不当搬运 |
| 绑定、钥匙指纹、"上次连 Mac 时的 id" | NVS | 身份文件 | docs/18、docs/26；最后一项新增 12 B（§3.2） |

**不做"设备是唯一真相"**（D1）：设备没有 PSRAM、FAT 掉电不安全（改名掉电会留两个名字 [源 docs/gates/sd-card.md:133-136]），又是最容易丢的那个东西。Mac 才是档案柜；设备只保证"在送到之前、和送到后的几天里，不丢"。

### 3.2 交给谁

1. **v0.8 之后**：照 docs/18 §3.5。段只列给 `prof ∈ ok(H)` 的 Mac，**再减去**账本里被"不给这台"排除的那台（§3.4）。
2. **v0.8 之前**（S1）：没有档案，任何你点了"连上"的 Mac（docs/27 O3）都能拿，除了被排除的那台。
3. **插上时的 5 秒提示**（D11，S1a）：设备在每次断开时把**最后发出的 MonoId** 存进 NVS（12 B）。下次插上、握手完成时，如果有"比它新、还没交"的段（= 离线录的），屏幕底部出一条不挡操作的提示，5 秒：
   - v0.8 前：`离线 3 条 → 这台 · Tab 不给`
   - v0.8 后：`离线 3 条 → 家 · Tab 改`
   - 这 5 秒里**只扣住这几段**（不进 `file.list`），别的照常同步；5 秒后放行、`files.rev` 加一。
   - 按 Tab → Enter（2 下）：v0.8 前，这几次录音对这台 Mac 记"不给"（同 AGAIN 的主机排除）；v0.8 后，改到另一个档案（同 PROF）。
   - 什么都不按：0 下，照常交。
4. **改归属**（S2，D3）：在设备上把**还没交出**的录音改成另一个档案。
   - 只改整次录音（按 `rec`，所有段一起，**一条账本记录**），不拆段；
   - 正在录的那次不能改；
   - 连着 Mac 时，这次录音有任何一段在当前 `file.list` 页里或正在传，选项灰掉，写"拔线后再改"（防止一半已在那台 Mac 上）；提示那 5 秒里扣住的段不受影响；
   - 已交出的（在留底里）不能直接改，要用"再交给 公司"（§3.5），它同时改归属和排除原来那台；
   - SEAL 以后，目标档案的 Mac 必须在这段的收件人 `rk` 里，否则灰掉，写"公司 的 Mac 解不开这条"（§6）。

### 3.3 留底（交出后设备还留几天）

**规则**（D4、D5）：

| 项 | 默认 | 说明 |
|---|---|---|
| 什么时候进留底 | `file.del`、大小和 sha256 都对 | 原来是删文件；现在是追加 `DELIV`（带主机哈希）、fsync、从索引里拿掉、再回 ack（§3.4 写的顺序） |
| 单位 | **整次录音**（`rec`） | 进留底是逐段的（一段段交出），**删和再交都按整次**；一次录音只要还有段待传，就不删它已交出的段 |
| 留多久 | 7 天，从这次录音最后一段交出算 | 墙上时间来自 `time.set`；`wall_s=0`（交出时还不知道时间）的**永不按时间删**，只按空间和段数删；钟跳见下 |
| 最多几段 | `kKeptMax = 扫描表容量 − 256 − 16`：默认构建 1264；按需分配构建把 `kScanScratch` 从 4800 B 提到 16 KB 后是 752 | 见下面"段数上限怎么来的" |
| 空间 | 空闲 < 1 GB 时从最旧的整次录音删起 | 只在空闲数已知（FSINFO 读到，`free_known`）时用；不知道就只按时间和段数 [源 fw/shell/rec_port.h:31] |
| 谁看得见 | **哪台 Mac 都看不见**；`file.list`、`files{n,rev}`、`hello.pending` 都不算它 | 不泄露、不打乱 Mac 的去重，也不占 256 段 |
| 太长的录音 | 一次录音段数 > `kKeptMax / 2`（默认约 105 h）不留底，交出时屏幕写"太长未留底" | 几乎碰不到；碰到时用 S0 的 Mac 导出包 |
| 怎么删 | 先追加 `GONE`（按 `rec`）并 fsync，再删各段 `.W`、`.M` | 掉电在中间：开机扫描看到 `GONE` 的 id 还有文件，就补删 |
| 谁来删 | 音频任务：开机扫描后、每次交出后、收到 `time.set` 后、**每段录完时**（录音中只在段与段之间删一次录音） | 每段最多 10 min ≈ 19 MB，所以录音的 256 MB 警告线之前留底早就让出来了 [源 rec_core.h:58-59] |
| 你能改 | 系统 → 存储 → 留底：关 / 7 天 / 30 天 | 改成"关"会一次删掉全部留底，和"清掉留底"一样要确认框（光标在"取消"） |

**段数上限怎么来的**：开机扫描把每个名字放进 16 B 的表；名字超过表容量时，多的那些按目录顺序被丢掉，**待传的段可能悄悄漏出索引**，计数偏低还会放行更多录音 [源 rec_scan.cpp:48]。所以留底段数必须让"待传 256 + 留底 + 正在录的一段 + 崩溃留下的孤儿 `.W` + 删到一半的"始终放得下：预留 16 个。再加一道保险（D15）：扫描时数溢出，溢出了就把索引标成"不完整"，**拒绝开始新录音**（写"卡上段太多，先同步"），录音停了以后用环形缓冲重扫。默认构建 1264 段大约是 210 h 的录音，所以实际起作用的是 7 天和空间。[待] 按需分配构建在开机时最大空闲块约 209 KB [源 audio_task.h:21-24]，16 KB 的临时表要实测。

**钟跳**（D16）：任何 Mac 的 `time.set` 都直接收下 [源 fw/shell/runtime_link.cpp:109]。一台钟快了一年的 Mac 会让全部留底一下子"过期"。规则：如果新的墙上时间比"上次的墙上时间 + 开机以来的时长 + 1 天"还往前跳，**这次不用它来删留底**，等下一次（另一次连接）给出相近的时间再算。

**留底开不开**（👤 第 2 条）：S1 在 SEAL 之前，留底是明文（§5）。默认开 7 天，但锁屏和 系统 → 存储 总是写出留底段数和最旧那条的天数：`待传 3 · 留底 12（最旧 5 天）· 空闲 478 GB`。

**为什么"看不见"，而不是"留着给同档案的另一台 Mac 自动取"**（对编排方案第 2 点的修改，D5）：
- 用法 A（默认）每个档案只有一台 Mac，自动取对它没有用；
- 看得见的留底会被任何点了"连上"的 Mac 拿走，和"去别的 Mac 前先清零"冲突；
- docs/27 D8 默认就不做"会议跟着第一台 Mac"。
用法 C 真要的话，S5 再做（D13）。

**存储和寿命**：多留一个文件是零写入；每段多一条 28 B 的账本追加。卡是 512 GB、FAT32、32 KB 簇 [源 docs/gates/sd-card.md:14,25]；音频 115.2 MB/h [源 docs/11:207]。[推] 这点写入量不是寿命瓶颈；真正的限制是扫描表、RAM 和 FAT 掉电。

### 3.4 账本 `SENT.L`

不改写 `.M`（512 B 预算；原地写会撕裂；`.M` 的 `prof` 还要给 SEAL 的 AAD 用），而是每个 epoch 目录一个只追加的账本（D6）：

```
/cpa/rec/<E7>/SENT.L 或 SENT.K     每条 28 B，小端：
  magic(1)=0xA5  op(1)  prof(1)  flags(1)  boot(4)  seq(4)  seg(2)  rsv(2)  wall_s(4)  host(4)  crc32(4)
op: 0 GEN  文件头：boot+seq 存代号（generation）
    1 DELIV 某段交出、进留底；id = 这段；host = 收件 Mac 的 host_id 哈希
    2 PROF  改归属；id = 这次录音的 rec；prof = 新档案；flags.foreign
    3 AGAIN 再交一次；id = rec；host = 不给的那台；prof = 新档案（0 = 不改）；flags.foreign
    4 GONE  删了；id = rec
flags.foreign：这次录音换过档案或换过 Mac，交出时 file.items 带 foreign（§3.6）
```

- **按 `rec` 记**：PROF、AGAIN、GONE 一条管整次录音的所有段（待传的和留底的），掉电要么整次生效、要么整次没生效，不会一半给家一半给公司。DELIV 逐段记，因为交出本来就是逐段的。一段的状态 = 它自己最后一条 DELIV 和它所属 `rec` 最后一条 PROF / AGAIN / GONE，按账本顺序取后者。
- **主机哈希**：`host` = `host_id` 的 CRC32（`hello` 里带，v0.8 前就有）；`0` 保留为"不知道"。内存里每个 `RecIndex` 条目多 1 B，指向一张最多 4 个"不给的主机"的小表（16 B），合计 +272 B [设]，这也是 docs/18 F2 按条目过滤要的位置。`file.list`、`files.n`、`hello.pending` 对被排除的那台 Mac 都不算这些段。
- **写的顺序**（D17）：
  - DELIV：追加 → fsync → 从索引里拿掉 → 回 ack。追加或 fsync 失败就回错误（不回 ack），Mac 下次重试。卡满（ENOSPC）写不了账本时退回今天的做法：直接删，因为 Mac 已经存好了。
  - PROF、AGAIN：屏幕等音频任务回"已写入并 fsync"才显示"已改" / "已排回"；失败就写"没改成"。
  - AGAIN 放回待传前，重新读这次录音每段的 `.M` 和 `.W` 大小；缺段（被删过的）或待传 + 段数 > 256 时拒绝，写"不完整，不能再交" / "待传太多，先同步"。
  - GONE：见 §3.3"怎么删"。
- **残尾**：打开账本准备追加时，先把长度截到最后一条完整、魔数和 CRC 都对的记录，再写。读的时候碰到坏记录，往后按魔数找下一个能过 CRC 的位置。这样一次掉电最多丢最后一条，后面的追加不会全部错位。
- **丢一条会怎样**（§9 的预言都按这个写）：
  - 丢 DELIV：段又变成待传。同一台 Mac 列出时已有 `rec.seg.stored`，直接 `file.del`，再记一次 DELIV；**v0.8 前如果下一台是另一台 Mac，它会把这段也拉走**——两台都有一份，不丢，但多给了一台（允许的结果，v0.8 后档案闸挡住）。fsync 在 ack 之前，所以只有"fsync 前掉电"才会这样。
  - 丢 AGAIN：还在留底，屏幕上能看到没生效（因为屏幕等 fsync）。
  - 丢 PROF：归属不变，屏幕上能看到没生效。
  - 丢 GONE：开机看到文件还在，下一轮清理再删。
- **单写者**（D18）：账本只由音频任务写（它本来就拥有文件系统）。UI 上的 AGAIN、PROF、"清掉留底"、5 秒提示的"不给"都作为新的 `RecCmd` 发给音频任务，屏幕等它的回复事件。今天的命令只有 `{Start, Stop, Mark, Tag, List, Get, Del, SegMs, MicGain, Codec}` [源 fw/rec/rec_msgs.h:30]，要新增 `Ledger`（带 op）和 S1b 的 `KeptPage`。
- **压缩**：账本 > 16 KB 时，把活记录写进另一个名字（`SENT.L` ↔ `SENT.K` 交替），第一条是 `GEN` 记录、代号 +1，fsync，再删旧文件。开机两个都在：按代号先应用旧的、再应用新的；新的 GEN 坏了就只用旧的。文件名不是段名，`rec_parse_name` 只认 11 个字符、第 9 位是 `.`、第 10 位是 W 或 M，所以不会把账本当段 [源 fw/rec/rec_paths.cpp:41-42]。
- **开机扫描**：每个 epoch 先读账本（1 次打开），再扫名字。今天每个名字都要读 `.M`（`scan_entry` 和 `predecessor` 各一遍）[源 rec_scan.cpp:101,117]；"留底的段不读 `.M`"**需要改代码**：扫描先按账本状态把待传的名字放进表的前面，留底和已删的跳过 `.M`。这算在 S1a 里。
- **离线标记**：断开时存最后发出的 MonoId（12 B）进 NVS，给 §3.2 第 3 条用。
- **epoch**：`kMaxEpochs = 8`，超过 8 个 epoch 目录不扫。今天就这样；但擦设备后卡上留的东西会比今天多（有留底），擦设备时要么一起清掉，要么提示 `cpa sd scrub`。

都在 **录音应用 → Tab 菜单**（不加新键），录音时这些选项不出现。按键数从主页算起：

| 你想 | 怎么按 | 下数 | 期 |

### 3.6 Mac 这边

- **S1a 只要一处可选改动**：交出流程、`file.del`、去重照旧。"再交一次"的段对被排除的那台**根本不列出**；对别的 Mac 是普通新录音。
- **`file.items` 每项加可选 `foreign:true`**（只新增，旧 cpad 忽略 [源 protocol/README.md:52]）：这次录音换过 Mac 或换过档案。Mac 看到 `foreign` 时，**只认 `.M` 里的 project key，不认 slot**（slot 是别的电脑或别的档案的编号，翻出来会进错分组 [源 manifest.py:80]），没有 key 就当"没有分组"。key 本机不认识的进"别的电脑的项目"[源 docs/23:99]。
- 第二台 Mac 收到的是**同一个 `rec` id 的新 manifest**，归档状态从头开始。分组 key 如果两台 Mac 同步过（§4），就落进同一个分组。
- 第一台 Mac 上的那份不会自动消失（Mac 之间不通信）。Mac app 收件箱里照常可以隐藏或删掉。
- **v0.8 后 Mac 的规则**（和 docs/26 对齐，§6）：Mac 按**自己的绑定**加 `rk` 决定收不收，`.M` 和 SEAL 头里的 `prof` 是录的时候的档案，只用于校验 AAD，**不因为和本机档案不同就拒收**。
- **S0 救急（只动 Mac）**：Mac app 录音卡片上"转给另一台 Mac…"，打一个 `recording/v1` 目录包（manifest + wav），AirDrop 过去，另一台 `cpa rec import`。今天就能做；缺点是要两台 Mac 都在手边。超长会议没留底时也靠它。

## 4. 分组：设备上的镜像

### 4.1 一套还是两套（👤 第 1 条，先定这个）

用法 A 里家、公司各一台 Mac。

| | 一套（默认） | 两套（docs/18 §3.6 原来的默认） |
|---|---|---|
| 分组要做几次 | **一次**，家和公司共用 1–9 | 家、公司**各一次** |
| 换 Mac 省事吗 | 家 ↔ 公司、换掉坏 Mac 都省事 | 只有换掉坏 Mac 时省事 |
| 隐私 | 公司 Mac 看得到家里的分组**名字**（看不到录音、文件夹） | 互相看不到 |
| 什么时候能做 | **S3a，不等 v0.8** | S3b，等 v0.8 |

一句话：**两套 = 家/公司各分一次组；一套 = 分一次，但公司 Mac 看得到家里的分组名。** 默认一套，因为需求里换电脑后不想再分组的情况多半是家和公司之间；如果分组名本身就敏感（比如客户名），选两套。

### 4.2 格式

- 一套：`/cfg/projects.json`；两套：`/cfg/p1/projects.json`、`/cfg/p2/projects.json`。按今天的 `commit_file` 写。
- 内容仍是 `projects.snapshot` 那一行，计数清零，多存 `tid`。`tid` **不是自动保留的**：今天的缓存是从 `ProjectsData` 重新编码的 [源 runtime_outbox.cpp:225-236]，所以 `ProjectsData` 和编解码器都要加一个字段。
- `tid` = Mac 算的 32 位哈希，只覆盖 (slot, key, name)、按 slot 排好；**0 保留**（算出 0 就换成 1），因为 `ptid=0` 表示"设备没有镜像"。固件只存不算。
- 只存 key（`^[a-z0-9][a-z0-9-]{0,11}$`）、名字（≤24 字节 UTF-8）、编号 1–9 [源 protocol/limits.json:12-15]。**不存 `root`、`mode`、去向**。
- 镜像在 FAT 上原地写，写坏了就当没有缓存 [源 runtime_outbox.cpp:224-226]；`ptid` 只从成功解码的文件里取，解不出来就报 0。所以"设备丢了 / Mac 坏了能从镜像拿回"是尽力而为。

### 4.3 谁说了算：三方比较

Mac 仍是编辑的地方（`cpa project add|rename|slot|rm`、Mac app）。每台 Mac 对每台设备（两套时再分档案）存**上次两边一致时的整张表**（≤9 行 key/name/slot）和它的 `tid`，放在 `$CPA_HOME/sync/<设备码>.json`（一台 Mac 一个写者）。握手后 Mac 读 `revs.ptid`：

| 设备 `ptid` | 本机 `tid` | `synced` | 判断 | 动作 |
|---|---|---|---|---|
| = 本机 `tid` | = 设备 `ptid` | 任何 | 一致 | 只推计数（今天的行为），`synced` 更新为当前表 |
| = `synced.tid` | ≠ `synced.tid` | 有 | 这台改过 | 推 |
| ≠ `synced.tid` | = `synced.tid` | 有 | 另一台改过 | **拉**：`projects.get`，按 4.4 合进本机；Mac app 一行"另一台 Mac 改了分组：+阅读、改名 2→3 [撤销]" |
| ≠ `synced.tid` | ≠ `synced.tid` | 有 | 两边都改过 | 拉、按 4.4 合并（并集），合并结果推回去；名字冲突这台赢，被盖掉的名字存到 `$CPA_HOME/projects.conflict-<时间>.json`，Mac app 一行"有 1 个分组名两边不同 [看一下]" |
| ≠ 本机 `tid`，非 0 | 任何 | **没有** | 第一次见这台设备（新 Mac、导入过 `settings/v1`、S3 刚上线） | **问一次**："用设备上的 / 用这台的"；本机空时直接走 4.5 |
| 0 | 任何 | 任何 | 设备没有镜像（旧固件、刚擦过、文件坏了） | 推 |

不用时间戳（设备和两台 Mac 的钟不一定准）。

### 4.4 拉进来怎么合（**拉永远不删**）

按 key 对：
- 两边都有 → 用设备上的名字和编号；**本机的 `root`、`mode` 不动**。
- 只有设备有 → 新建一个**没链文件夹**的分组（`root=null`），只能归档、不能开 session，旁边写"链一个文件夹"。
- 只有本机有 → **保留**。如果它在 `synced` 里有编号、设备上没有了，本机只把它变成"没编号"（另一台可能只是把它移出了 1–9，快照里本来就不带没编号的分组）。**删除只在本机做**，从不跟着拉过来。
- 编号冲突（两个 key 抢同一个编号）→ 设备那份占位，本机那个变"没编号"。
- 推的时候同理：设备镜像只是 1–9 的那一页，推不会让别的 Mac 删东西。

代价：在家删掉的分组，公司那台还在（只是没编号了），要在公司再删一次。换来的是：链了文件夹、归了录音的分组永远不会被另一台 Mac 悄悄删掉。

### 4.5 新 Mac 第一次绑定

条件：这台 Mac 刚被设备绑定（docs/18 §3.2 或 docs/27 O3），本机没有分组，设备 `ptid ≠ 0`。
Mac app 首次设置（docs/27 §2.3）里"分组"那一行：`设备上有 5 个分组 [用这些] [不用]`。点"用这些" → `projects.get` → 按 4.4 全部新建（都没链文件夹）→ 存 `synced`。

**这推翻了 docs/27 D12 的一半**（D9）。docs/27 不做的两个理由：
1. **要新消息**：加 `projects.get` / `projects.items`（§7）；旧固件回 `E_UNKNOWN_TYPE`，Mac 退回 `settings/v1` 导出文件。
2. **防别的档案读到**：一套时任何绑定过的 Mac 都能读（这就是 👤 1 的代价）；两套时只回 ok(H) 的档案，ok(H) 为空回空表；`revs.ptid` 遵守 docs/18 §3.5 第 6 条。未绑定的 Mac 一律回空表。

`settings/v1` 导出仍保留，用于去向和 `rec_pull` 等不在设备上的设置；它导入的项目仍强制 `plan` 模式（docs/27 D12）。

### 4.6 和 projects-app 对齐

`feat/projects-app` 还没推送。合并前要它做四件事：`tid` 算法放在 `cpad/projects/registry.py`（纯函数、有测试向量、0 保留）；`add|rename|slot|rm` 写完 `projects.json` 后更新 `tid`；`$CPA_HOME/sync/<设备码>.json` 存上次同步的整张表；Mac app 的"被拉来改了 / 冲突"两行提示和撤销。

## 6. 和 SEAL（docs/26）的关系

- **默认不改 docs/26**（D14）：每个文件只封给**当前档案**已确认的 Mac；没有钥匙就明文；从不封给别的档案。
- 所以 SEAL 后，"改归属"和"再交给 公司"只有在 `rk` 里有目标档案的 Mac 时才能用（设备读得到 `.M` 里明文的 `rk`），否则灰掉。家和公司的 Mac 名单不同时，离线录的东西事后就改不了归属——这时靠 §3.2 的 5 秒提示在交出前拦下（它拦的是"交给谁"，不需要重新加密）。
- **可选：离线录音封给两边**（👤 第 3 条）：没连任何 Mac 时开始的录音，封给两个档案的全部 Mac。代价要说清：docs/18 §3.4 下离线录音都有当前档案，所以这几乎覆盖你大部分便条；一台公司 Mac **不用拔卡**，复位进下载模式刷个固件就能读卡（docs/18:25,434），也就能解开这些家里的便条。这削弱了 docs/26 的目标；选了它，docs/26 D7 和 D8（"从不封给别的档案的 Mac"，docs/26:507）两行都要改。
- **AAD 和 `prof`**：SEAL 头（明文、从不回写）里的 `prof` 是录的时候的档案，AAD = 头的 SHA-256 [源 docs/26:182-183]。改归属只写账本，不碰头，所以 AAD 校验永远用原头，照样通过。Mac 规则：**头里的 `prof` ≠ 交付档案时，只有我的 `kid` 在 `rk` 里才算有效**。这等于对 `prof` 的防篡改放宽一点（被改了也只能交给能解开的 Mac），要在 docs/26 记一行。
- 留底的文件是密文，"清掉留底"仍只是 unlink，空闲簇里留的是密文。

## 9. 测试（每期先写）

- **账本**：每种 op 的最后一条截断 1–27 B，之后再追加几条，**要求后面的全部读回**；`SENT.L` 和 `SENT.K` 同时在（按代号）；新文件 GEN 坏；中间一条 CRC 错（按魔数找回）；空账本。预言：不会有一段**既不在待传也不在留底却还有文件**；丢一条只能导致"多交一次"或"屏幕上看得到的没生效"。
- **掉电**（HIL，串行跑）：DELIV 在追加前 / fsync 后 ack 前拔电；GONE 之后删到一半拔电；AGAIN 写到一半拔电。开机后每段状态唯一；Mac 去重后不重复存。**允许的结果**：fsync 前掉电、下一台是另一台 Mac 时，两台各有一份（v0.8 前）。
- **再交一次**：交给 A → 在 A 上"再交一次" → **A 重连后 `file.list` 不列、`files.n`、`hello.pending` 不算**；B 正常拉；两台 manifest 的 `rec` 相同；B 的 manifest 里 slot-only 的分组变成"没有分组"（`foreign`）。
- **5 秒提示**：离线录 3 条、插上，5 秒内 `file.list` 不列这 3 条、列别的；Tab → Enter 后对这台永远不列；不按则 5 秒后列出、`files.rev` 变。
- **整次录音**：6 段会议在 PROF / AGAIN 中途掉电，开机后 6 段归属一致；清理只删整次；部分已交出、部分待传的录音不删；缺段的录音"再交一次"灰掉；待传 250 + 一次 10 段的录音"再交一次"被拒。
- **扫描上限**：名字数 = 表容量 + 1 时索引标"不完整"、拒绝开始录音、停后重扫完整；按需分配构建 16 KB 表的堆实测。
- **钟**：`wall_s=0` 的留底不按时间删；一次往前跳一年的 `time.set` 不删留底，第二次连接给出相近时间后才删。
- **空间**：`free_known=false` 时只按时间和段数；空闲 < 1 GB 时段末删最旧一次录音；录音不会因留底碰到 256 MB 警告线。
- **不可见**：留底的段 `file.get` 回 `E_UNKNOWN_ITEM`、`file.del` 回 ack 不动它、计数和 rev 不变。
- **改归属时在传**（S2）：连着 Mac、某段在当前 `file.list` 页里时 PROF 灰掉。
- **分组**：§4.3 六行各一个用例；`tid` 测试向量 Python 和固件一致、0 被换掉；**A、B 都改 → A 连 → B 连 → A 连：A 新加的分组还在**；一台把分组移出 1–9 后，另一台拉过来只是"没编号"、链的文件夹和归的录音都在；没有 `synced` 时问一次；未绑定 Mac `projects.get` 回空表；中文名 8 字、9 行转义后 ≤ 2048。
- **SEAL**（S4）：`rk` 不含目标档案时"改归 / 再交给"是灰的；头里 `prof` ≠ 交付档案、`kid` 在 `rk` 里的段 Mac 收下、AAD 用原头通过；`kid` 不在 `rk` 里的不交。

### 10.2 要你拍板

1. **家和公司的分组是一套还是两套**：默认**一套**——只分一次组，但公司的 Mac 看得到家里的分组名（看不到录音和文件夹）。两套 = 家、公司各分一次，互相看不到。分组名里有敏感的（客户名之类）就选两套。
2. **留底开不开**：默认开、7 天。代价：加密做出来之前，设备上会有最近 7 天的明文录音；设备丢了或者被一台不信任的 Mac 刷固件读卡，这些都能被读。也可以选 30 天，或者"关"（交出即删，和今天一样）。
3. **加密以后，离线录的便条要不要也封给另一边**：默认**不要**（只封当时的档案）。要的话，事后改归属更自由，但公司的 Mac 刷个固件就能解开你离线录的家里的便条。
4. **插上 Mac 时的 5 秒提示**：默认有（只在有离线录音时出现，不挡操作）。也可以选"不要提示"或"每次都先问"。
5. **在家删掉一个分组，公司那台要不要也跟着删**：默认**不跟着删**，只是去掉编号，免得链了文件夹、归了录音的分组被悄悄删掉；代价是要两边各删一次。
6. **你有没有"两台 Mac 都算家"的情况**（docs/27 用法 C，比如台式加笔记本）：没有就不做 S5。

回复模板：`1 一套 / 2 开7天 / 3 不要 / 4 要提示 / 5 不跟着删 / 6 没有`（不回就按这一行做）。

## 11. 评审处理记录（r1 → r2）

三轮评审的问题全部采纳，分歧这样定：

- **留底段数**：一位评审说 40 段只够 2–4 天、"7 天"不诚实；另一位指出 40 段来自把 `CPA_REC_ALLOC_AT_START` 读成"开机就录"，默认构建的表是 1536 个名字。采纳后者的事实：上限改成按扫描表算（默认 1264），按需分配构建把临时表提到 16 KB；再加溢出即拒录的保险（D15）。这样"7 天"在默认构建里是真的，并在 系统 → 存储 写出最旧那条的天数。
- **再交一次被同一台吃回**：三位都提了，统一成账本每条带 4 B 主机哈希、内存每条 1 B 指向 4 项小表（D2、§3.4）；记录从 20 B 变成 28 B（还加了魔数、按 `rec` 的段号）。
- **少按键**：采纳"插上 5 秒提示"（D11），从"不问"改为"不问，但提示"；整批"再交一次"放进 S1a，可翻列表拆到 S1b，因为设备今天没有自己的录音列表。
- **slot-only 分组进错组**：评审给了两种办法（设备上把 slot 翻成 key / 加"丢掉 slot"标记）。设备没法改 `.M`、Mac 看不到账本，所以选标记，并通过 `file.items` 的可选 `foreign` 告诉 Mac（§3.6）。这让"S1 零协议改动"变成"S1 一个可选字段"。

## 12. S1a 实现记录（2026-10-27，设备不在手边时做的）

照 §3、§8 的 S1a 做了，下面是和正文不一样或正文没说清的地方，每条都有测试。

| 项 | 正文 | 实现 | 为什么 |
|---|---|---|---|
| DELIV 的 `rsv(2)` | 保留 | 存 `back` = 这段 id 的 seq − 这次录音 rec 的 seq（同一个 boot，≥ 0xFFF 当"不知道"，这段自成一次录音） | 账本自己就能按整次录音删和数，不用再读 `.M` |
| AGAIN | 按 `rec` 一条 | 按段一条，一批一次 fsync；`flags` 新增 `HOLD`（0x04）= 只排除、不把留底放回待传（5 秒提示的"不给"用它） | 这批常常跨几次录音；屏幕等 fsync 才说"已排回"，掉电时屏幕看得到没生效 |
| 残尾 | 截到最后一条好记录再追加 | 不截：读的时候按魔数跳过，**脏了就整理**到另一个名字（GEN + 活记录，fsync，再删旧的） | FatFs 上不用 `ftruncate`；和压缩走同一条路，测试只要测一条 |
| 两个名字都在 | 先旧后新都用 | 只用旧的（GEN 代号小的；第一条不是好 GEN 的只有 `SENT.L` 算"原件"），删掉新的，下次再整理 | 新的是旧的整理结果，可能写到一半；旧的总是完整的 |
| 整理写什么（评审 1、2） | 活记录 | GEN 带 `BATCH`（0x08）：`host` = 最近一批的 Mac（0 = 没有），`wall_s` = 这批第一条的记录序号；之后按顺序写：GONE 了但文件还在的段各一条 DELIV → 每次录音一条 GONE → 不在这批的留底 DELIV → AGAIN（`host` 为 0 的不写）→ 这批的 DELIV | 整理会丢掉"隔开两批"的那条交给别的 Mac 的记录，老的同一台 Mac 的留底就会被并进最近一批（再交一次多交）；GONE 只作用于留底的段，删不掉文件时前面没有 DELIV 它就什么都不做，录音会回到待传 |
| 压缩阈值 | > 16 KB | > max(16 KB, 活记录 + 4 KB)，`清掉留底` 之后总是整理（账本里不再留各 Mac 的哈希） | 1264 段的活记录就有 35 KB |
| 回放的内存 | 没说 | 空闲时借 24 KB 环形缓冲当表，每段 16 B（按需分配构建临时分配 16 KB）；录音时账本命令回"忙" | 设备没有 PSRAM |
| `kKeptMax` | 扫描表 − 256 − 16 | 一样：默认 1264，按需分配构建把 `kScanScratch` 从 4800 B 提到 16 KB 后 752；整理按段数删到 `kept_low` = 上限 − 一整张待传表（256，表小时是一半）：1264 → 1008；**到上限时新交出的直接删**（今天的做法） | 保证开机扫描表永远放得下；留一整张待传表的余地，钟不可信、空闲不知道时新交出的也照样留底（评审 5）。到上限还删新的而不删最旧的，因为交出时音频任务手里没有回放账本的缓冲 |
| `RecIndex` | 每条 +1 B，合计 +272 B | 每条 +4 B（`excl` 指向 4 个主机的小表、`first` = 第 0 段），合计 +1 KB 堆 | `first` 让 5 秒提示按"次"数，不按段数 |
| 一段排除几台 | 最多 4 台 | 每段只排除最近一台（4 个槽给所有段共用，第 5 台顶掉最旧的槽） | AGAIN 以后交给了 B 再从 B 收回，A 再拿到它是允许的结果 |
| 清理时机 | 开机、每次交出后、`time.set`、每段录完 | 开机扫描后、拔线后（这次连接有交出时）、可信的 `time.set` 后、**插着线且空闲 < 1 GB 时在两次文件请求之间**（评审 4）；**录音中不清** | 交出不再腾地方（留底），插着线拉完马上开会也得先腾出来；空闲 < 1 GB 就从最旧删，一次会议最多 345 MB，录音碰不到 8 MB 的拒绝线 |
| 不完整的录音 | 有段待传就不删已交出的 | 最后一段（`last`）没进留底的录音不按时间删，只按段数、空间或"清掉留底"删 | 待传的段在 loop 的索引里，音频任务看不到 |
| D15 溢出 | 停了以后用环形缓冲重扫 | 拒绝开始录音（"卡上段太多：先同步，再重启"），重启后重扫 | 默认构建表就是环形缓冲，溢出只在病态情况 |
