## 0. 一页摘要

1. **你要的**（#19）：同一台 Cardputer 在家和在公司表现不同，而且**严格分开**。家里记的东西永远到不了公司的 Mac，反过来也一样，SD 卡上还没传的录音也算。
2. **今天做不到**：设备把待传的笔记和录音交给**任何一台**握手成功的 Mac。哪台先插上，哪台就拿走；录音拿走以后设备上就删了。项目缓存只有一份，以最后插的那台 Mac 为准（§1.1）。
3. **模型**（§3）有三样东西：
   - **档案**：v0.8 固定两个，**家**和**公司**；
   - **绑定**：一台 Mac（按 v0.4.1 hello 里的 `host_id` 识别）属于哪个档案，**只在设备上由你选**，Mac 自己怎么说都不算；
   - **当前档案**：新记的东西都打上它。**把 USB 插上**一台绑定过的 Mac，或者换了一台 Mac 握手时，自动换成那台 Mac 的档案；同一台 Mac 重新握手（cpad 重启、Mac 睡醒）不会撤销你的手动切换。

   两条规则管住所有交付：
   - **设备只把档案 P 的条目和录音交给绑定到 P 的 Mac。** 没绑定的 Mac、太旧的 cpad（没有 `host_id`）什么都拿不到；
   - **从 Mac 数据派生出来的东西，跟着数据的来源档案走，不跟当前档案走**（比如对家里 session 的回复、开 session 失败后存下的排队项）。
4. **不用打字**（§5）：插上一台新 Mac 时，设备弹一张选择单"这台 Mac 属于：以后再说 / 家 / 公司 / 都不是"，光标停在"以后再说"，选完还要确认。手动换档案在 系统（Opt+M）→ 档案 里，同样是选择加确认。**不加任何新键**，状态栏右边多一个字（"家"或"公"）。
5. **离线时记的东西**归当前档案，状态栏随时看得到是哪个档案。v0.8 不做事后改档案，也不按时间段自动换。
6. **WiFi**：v0.8 **不做**，只留一个闸门名字 G-WIFI（§6）。
7. **Mac 端**（§7）：cpad 从设备那里得知自己服务哪个档案，在事件和 `manifest.json` 里记下 `prof`，收到条目时再核对一遍；对不上就什么都不写、重新握手，**从不回 `rejected`**（那会让设备把条目移进 `bad/`，最终删掉）。`cpa mcp serve --profile` 和 `cpa export --profile` 按数据上的标记过滤，也就是 docs/15 的 D 期。
8. **威胁模型**（§8）：v0.8 能保证"诚实的 cpad 拿不到别的档案的内容，也拿不到别的档案的计数字段"，即 L1。**保证不了**的有两样：
   - 一台存心读设备的 Mac（比如被公司 IT 控制）可以用 esptool 把设备复位进下载模式，读出整片 Flash，再刷一个固件去读 SD 卡。设备上所有**还没同步**的东西都是明文。真要防，就得做 L3（每个档案的东西加密落盘，P8-E，由你决定）；
   - 少量元数据会漏：条目 ID 的间隔能推算出别的档案记了几条；别的档案正在录音时，`files.live` 是 true（§8.3）。
9. **迁移**（§9）：升级以后，在第一次插上带 `host_id` 的 cpad 之前，设备的行为和今天一样。**第一次插上时会暂停交付**，弹出选择单等你选；选"不分档案"就回到今天的行为。升级前记的待传不知道属于哪个档案，第一次绑定时会问你一次，光标默认停在"先留着"。分了档案以后，只要设备上所有带档案标记的待传都清零了，可以在设备上关掉。
10. **协议只新增，`v` 仍为 0，不新增消息类型和错误码**（§10）：
    - 设备的 `hello`、`pong` 加 `prof{act, ok, ask, legacy}`；
    - `outbox.item` 和 `file.items[]` 加 `prof`；
    - `debug.state` 加 `prof`；
    - 录音契约 v1 的 `manifest.json` 加 `prof`。
11. **测试**（§12）：在模拟器上跑一台虚拟设备，让三个 cpad 轮流连接（三个 `CPA_HOME`：家、公司、陌生）。家里的每条记录都带一个金丝雀字符串，最后断言公司那边的事件、笔记和录音目录里一个都找不到，也断言两边都没丢东西。协议层另加 `flows/prof/` 和一个检查"线上从不出现 `prof ∉ ok(H)`"的工具。
12. **要你拍板的 9 件事**见 §15。最要紧的是第 1 条：你用的是**两台 Mac**，还是**一台笔记本来回带**。

## 2. 原则

1. **档案只由主机身份和你的选择决定，从不由内容决定**，和去向的规则一样 [源 docs/13 §3 原则 8]。Mac 在 hello 里说什么都只作参考，绑定只在设备上由你来选。
2. **默认不给**：不认识的 Mac 什么都拿不到。不给待传，不给录音，不发 agent 请求，连"有几条待传"都报 0。
3. **当前档案和绑定分开管**：
   - 当前档案决定新记录打什么标记，以及界面显示什么；
   - 绑定决定能把什么交出去。

   比如你手动切到"公司"，家里那台 Mac 照样能拿走"家"的待传，但拿不到"公司"的。
4. **派生的东西跟着来源走**：从某台 Mac 推来的数据（session、队列、项目）派生出的条目，标记取那份数据所属的档案，不取"按下 Enter 时的当前档案"。
5. **收窄立刻生效，放宽等 Mac 知道以后**：忘掉一台 Mac、改绑，马上少给；绑定、交出"未定"，要等设备把新的 `prof` 告诉了这台 Mac 以后才多给。这样 cpad 永远不会收到它以为不该收的东西。
6. **只在没有浮层、没在录音、没有请求在途时换档案**。录音一律算开始那一刻的档案，一场会议不会录到一半换档案。
7. **只用选择，不打字**：所有操作都是"用 `;` `.` 选，按 Enter，再过确认框"。不加新键，因为 docs/14 §3.1 已经把 26 个 Opt+字母分完了（原来留给 WhisperWoof 的 W，docs/17 给了待办应用）。
8. **出了问题，往"不给"的方向走**：档案表读不出来，或者 NVS 被擦了，只要设备上还有带档案标记的东西或"已分档案"的标记，就按"已分档案、但没有任何绑定"处理，不会退回"谁都给"。
9. **协议只新增**，`v` 仍为 0，不新增消息类型，也不新增错误码 [源 docs/05 §6.9；docs/13 §12.2]。录音契约 v1 只加可选字段。

## 3. 模型

### 3.1 档案

| 序号 | key（用于线上、事件和 `--profile`） | 设备上显示 | 状态栏 | 颜色 |
|---|---|---|---|---|
| 1 | `home` | 家 | 家 | 现有的 `Color::Ok` [设] |
| 2 | `work` | 公司 | 公 | 现有的 `Color::Accent` [设] |
| 0 | （不写） | 未定 | — | — |

- key 的格式是 `^[a-z][a-z0-9-]{0,11}$`。数据结构按最多 4 个档案留了位置，但 v0.8 的界面只给两个 [设]：设备上打不了中文，自定义名字要等 Mac 端来配，在有人需要之前不做。
- **0 表示"未定"**：升级前记的、第一次绑定之前记的，以及 NVS 丢失后、重新绑定之前记的东西。它们有专门的处理（§9）：在你做出决定之前，不会交给任何 Mac。

### 3.2 绑定

- 一条绑定包含三样：
  - `sha256("cpa-host:" + host_id)` 的前 16 字节；
  - 档案序号：1、2，或者"都不是"；
  - 那台 Mac 自报的 `host_label`，只用来显示。
- **只接受至少 16 个字符的 `host_id`**。协议的 `host_id_pattern` 只要求 8 个字符 [源 limits.json]，也就是 32 位，太短，不够当口令用；cpad 自己生成的是 16 个十六进制字符 [源 config/host.py]。短于 16 的，设备提示"这台 Mac 的身份太短，分不了档案"，按太旧的 cpad 处理。
- **v0.8 里一台 Mac 只能绑一个档案**（形态 A）。选了"都不是"也会存下来，以后再插上就不再问，什么都不给；它在 系统 → 档案 里看得见，可以忘掉（§5.6）。
- 最多存 8 条 [设]，"都不是"也算。同类产品 cardputer-agent-deck 也是最多 8 台 [源 docs/02 §7]。存满以后，要先在 系统 → 档案 里忘掉一台。
- 绑定存在 NVS（内部 Flash）里，不放在 SD 卡上，所以换卡不会换掉绑定。

### 3.3 当前档案

| 什么时候 | 当前档案怎么变 |
|---|---|
| **把 USB 插上**一台绑定到 P 的 Mac（设备运行中看到 USB 从无到有），握手成功 | 换成 P，并提示"已切到 公司（插着「工作 MBP」）" |
| 握手的这台 Mac 和**上一次握手的不是同一台**（`host_id` 的哈希不同），它绑定到 P | 同上 |
| 同一台 Mac 重新握手（cpad 重启、Mac 睡醒、链路超时），线没拔过 | **不变**。你的手动切换一直有效，直到插上另一台 Mac 或者重新插线 |
| 拔掉 USB | 不变（仍是"最后插的那台"的档案） |
| 在 系统 → 档案 里选了另一个 | 换，要确认（§5.7） |
| 插上一台没绑定的、选过"都不是"的、或 cpad 太旧的 Mac | 不变 |
| 开机 | 恢复成关机前的那个；"上一次握手的是哪台 Mac"也一起恢复（都在 NVS 里） |
| NVS 丢了（§3.7） | 变成"未定"，之后新记的都是未定，直到你重新绑定 |

- **什么时候先不换**：有浮层、正在录音、有 agent 请求或共享通道的请求在途时，先记下来，等这些都结束再换（原则 6）。手动切换在这些时候直接提示"等…结束再换"。
- **为什么插上就自动换**：主机身份是 #19 里排在第一位的信号，而且每条绑定都是你亲手确认过的。不自动换的话，你每到一个地方都得多做一次选择。
- **为什么重新握手不换**：cpad 重启、Mac 睡醒、链路抖一下都会重新握手 [源 protocol 的 `daemon_restart` 流程]。如果每次握手都按绑定重算当前档案，你在家里手动切到"公司"，链路一抖就被切回"家"，之后记的工作内容就进了家里的 Mac。
- **为什么不按时间段换**：它会在你不知道的时候换掉档案，然后悄悄地给接下来记的东西打错标记。#19 只把它当兜底，这里不做（§15 第 8 条）。

### 3.4 每条记录打上档案

| 记录 | 标记打在哪里 | 标记取什么 |
|---|---|---|
| 打字的笔记、待办、排队项（outbox） | 条目文件本身多一个 `prof` 字段（这个文件就是线上发出去的那一行）。`OutboxCore` 另外存一份 1 字节的序号，发送时不用读文件就能过滤 | 按 Enter 保存那一刻的当前档案 |
| 便条、会议 | 每一段的 `.M` 多一个 `prof`；`RecIndex` 另外存一份 1 字节的序号 | 开始录音那一刻（第 0 段）的当前档案，之后每一段都照抄 |
| **派生的排队项**：对 session 的离线回复（`decide_reply` 走 `Route::Queue`）、开 session 失败或结果未知时存的排队项（`flush_agent_save`）、从项目页存的排队项 | 同第一行 | **来源数据所属的档案**：session 行、队列行、项目行所在切片的 `src`；在途请求的 `AgentReqInfo.src`（§3.6） |
| 开 session、回复（在线请求） | 不落盘；只发给服务来源档案的 Mac | 发出的那一刻 |

- 线上一律用 key（`"prof":"work"`），设备内存里用序号（0–4）。
- 旧文件里没有 `prof`，按 0（未定）处理。

### 3.5 交出去的规则（核心不变式）

设备连着 Mac H，`ok(H)` 是 H 绑定的档案集合（v0.8 里要么为空，要么只有一个）：

1. **outbox**：只发 `prof ∈ ok(H)` 的条目。未定的条目，要等你把"未定"归给 H 的档案以后才发（§9）。顺序仍按 ID，在途仍最多 4 条。
2. **录音**：
   - `file.list` 只列出 `prof ∈ ok(H)` 的段；
   - 对别的段，`file.get` 回 `E_UNKNOWN_ITEM`，`file.del` 回 `ack` 但不删除。这和"卡上没有这一段"的回复完全一样，不透露它的存在 [源 file_req.h]；
   - `files.rev` 只在 H 看得见的段提交或删除时才变（每个档案各记一个 rev，报 H 那个档案的）。cpad 本来就是"rev 变了就重新列"，所以兼容。
3. **计数**：`hello` 和 `pong` 里的 `pending`、`files.n` 只数 H 能拿的。
4. **在线请求**：`agent.spawn`、`agent.reply`、`agent.pick`、`queue.done`、`inbox.dismiss`、`rec.*`、`dest.send`（D5-B），以及 v0.6 新增的 `choice.get`、`todo.list`、`todo.act`（docs/17 §9），只在**当前档案 ∈ ok(H)** 时发。否则一律按离线处理，比如 Opt+S 会变成一条排队项。这只是设备端多一道闸，docs/17 的协议不用改。
5. **H 推来的快照**（项目、session、队列、去向、待处理）：
   - 当前档案 ∈ ok(H)：采用进 AppState，切片的 `src` 记成当前档案，并存进这个档案的缓存；
   - ok(H) 不为空、但当前档案不在里面：**不进 AppState**，只把能落盘的（项目、去向）存进 H 那个档案的缓存；
   - ok(H) 为空：照样回 `ack`，但既不采用也不缓存。

   `time.set` 照常接收。
6. **`revs` 报哪一份**（设备 `hello` / `pong` 的 `revs.*`，docs/14 §7.2 用它判断要不要重推）：
   - ok(H) 不为空：报属于 H 那个档案的那一份。当前档案就是它时，报 AppState 里的；不是时，项目和去向报 H 档案的缓存，session、队列、待处理（只在内存里）回显这次连接里 H 推来的；
   - ok(H) 为空：回显这次连接里 H 最后推来的那份的 rev（不管有没有采用）。这样旧 cpad 不会每 5 s 重推一次；
   - **永远不报别的档案的 rev**：rev 是内容哈希，报出来就等于把别的档案的指纹给了 H。
7. **`ok(H)` 什么时候重算**：
   - 收到主机的 `hello`。重新握手本来就会清空在途请求、把 outbox 条目退回待发 [源 protocol/README.md"流程"的不变式]；拔线后链路回到 Detached，换一台 Mac 必须重新握手；
   - 你在设备上改了绑定（§3.7）。

对 `ok(H)` 为空的 Mac（没绑定、选了"都不是"、没有 `host_id`、选择单正开着），链路照样握手、照样 ping，状态栏显示 `◇ 未分配`，`hello` / `pong` 带 `prof{ok:[], ask}`，计数报 0，除此之外什么都不给。

一句话的测试预言：**任何时刻，设备写到 H 线上的任何一行，都不包含 `prof ∉ ok(H)` 的条目或段的内容，也不包含按它们算出的计数字段（`pending`、`files.n`、`files.rev`、`revs.*`）。** 条目 ID 的间隔和 `files.live` 是已知的元数据泄露，不在这条预言里（§8.3）。

### 3.6 每个档案各有什么

| 东西 | 每个档案一份吗 | 存在哪里 | 说明 |
|---|---|---|---|
| 待传笔记和录音 | 是 | outbox 和 SD 卡（两个档案混放，靠标记区分） | §3.4 |
| 项目缓存 | 是 | `/cfg/p1/projects.json`、`/cfg/p2/projects.json` | 离线时 `#3` 按当前档案的项目解析，修掉"按最后那台 Mac 的项目解析"这个问题 |
| 去向缓存（v0.5） | 是 | `/cfg/p1/dests.json` 等 | 离线时 Opt+字母按当前档案的绑定走。去向 id 本来就是每台 Mac 各自的 [源 docs/14 §2.2] |
| session（含 docs/17 的 `why`）、队列（含 `review` 和"给 AI"标签）、待处理（v0.5） | 是 | 只在内存里，按 §3.5 第 5 条采用 | AppState 的这几个切片各带一个 `src`。**换档案时清空**，再从新档案的缓存载入能载入的（项目、去向）；session 和队列等这个档案的 Mac 推来。docs/17 的选择页和待办页同时清掉 |
| 会议录音开关 | 是 | NVS | #19 点名的"开会录音允不允许"。默认都允许；关掉以后按 Opt+R 会提示"公司 档案关了会议录音"。**可以砍**：如果你用不上，P8-F3 里删掉这一行 |
| 状态栏的字和颜色 | 是 | 写死在固件里 | §3.1 |
| 预设回复（#16，v0.6） | 天然就是 | 配在 Mac 上 | 每台 Mac 各有一套 |
| 其他应用的开关 | 否 | — | #19 草图里的"每个档案开哪些模块"，除了会议录音都不做 [设] |

**为什么要 `src`**：评审发现了一条真实的泄露路径。连着家里的 Mac、手动切到"公司"，再对一个家里的 session 回复：设备按离线处理，把回复存成排队反馈 [源 confirm.cpp:27-35；shell.cpp 的 `queue_instead`]，如果标记取当前档案，正文就打上 `work`、交给公司的 Mac；之后在"给 AI"里按 Enter，公司的 cpad 会用这段正文开一个**新** session [源 hub/reduce.py:141-174]。agent 请求还在途时切换，失败兜底存的排队项也一样 [源 runtime_outbox.cpp:166-185]。现在三道保险：
1. AppState 里来自主机的切片永远属于当前档案（只在当前档案 ∈ ok(H) 时采用；换档案就清空）；
2. 派生条目的标记取切片的 `src`，在途请求的失败兜底取 `AgentReqInfo.src`；
3. 有请求在途时不换档案（§3.3）。

### 3.7 绑定什么时候生效

| 改动 | 方向 | 什么时候生效 |
|---|---|---|
| 忘掉一台 Mac；把它改绑到另一个档案；把当前连着的 Mac 设成"都不是" | 收窄 | **立刻**：重算 ok(H)，在途的 outbox 条目退回待发（和重新握手一样），不再回答对不允许的段的 `file.*`；下一个 `pong` 带上新的 `prof` |
| 把当前连着的 Mac 绑定到一个档案；把"未定"交给 H 的档案 | 放宽 | **等设备发出一个带新 `prof` 的 `pong` 之后**。`pong` 只能作为 `ping` 的回复发出，间隔 5 s [源 limits.json `ping_interval_ms`]，所以最多晚 5 s。线上是一条有序的串口流，cpad 一定先看到新的 `prof`，再看到新放行的条目 |

为什么这样分：评审指出，如果确认绑定以后马上开始上传，cpad 手里还是 `ok:[]`，同步刚开始那几秒的每一条都会被拒收；被拒收的条目进 `bad/`，只留 20 条，多的直接删掉 [源 outbox_core.h:5、21]。现在设备这边先让 cpad 知道，cpad 那边对不上也只重新握手、从不拒收（§7.1 D2）。

## 4. 主机身份：`host_id`

### 4.1 Mac 端

- **v0.4.1 已经有的** [源 wt-v041-daemon config/host.py]：
  - 第一次运行时随机生成 16 个十六进制字符（`secrets.token_hex(8)`），存在 `$CPA_HOME/host_id`，权限 0600；
  - 文件内容 `.strip()` 以后不符合 `host_id_pattern` 就重新生成；
  - 从不写进日志；
  - `host_label` 来自 `config.json`，最长 24 B。
- **v0.8 加两条**：
  1. **跟硬件绑定**，指纹放在**单独的文件** `$CPA_HOME/host_hw`（0600），内容是 `sha256(IOPlatformUUID)` 的前 16 个十六进制字符。`host_id` 文件的格式**一字不改**：v0.4.1 的 cpad 读到两行的文件会判成格式错误、重新生成 `host_id` [源 config/host.py:22-40；validate.py:23-29 把 `$` 换成 `\Z`]，降级时绑定就全作废了。规则：
     - `host_hw` 不存在（从 v0.4.1–v0.7 升级上来）：保留现有的 `host_id`，写入指纹，**不重新生成**；
     - `host_hw` 存在而且和本机对得上：照常；
     - `host_hw` 存在但对不上：重新生成 `host_id`、写新的指纹，日志里写"host_id regenerated (hardware changed)"，不写新旧两个值。

     **为什么值得做**：迁移助理和备份恢复会把家里 Mac 的 `$CPA_HOME` 原样搬到另一台 Mac 上，那台 Mac 就能冒充家里那台，这是真实存在的 L1 风险。代价是换了新 Mac 以后，设备会再问你一次 [设]。
  2. **`cpa host reset`**：手动换一个新的 `host_id`（比如要把这台 Mac 送人），要输入 `y` 确认。设备上原来的绑定从此再也对不上，到 系统 → 档案 里把它忘掉即可。
- `cpa status` 不显示 `host_id`，只显示"本机：公司（设备上的绑定）"。

### 4.2 设备端

- 只存哈希（§3.2），不存原文。**任何一条线上消息都不会回显 `host_id`，也不会透露别的 Mac 的任何信息**；设备只把 H 自己的绑定告诉 H（`prof.ok`）。
- 每收到一次主机 `hello`，就算一次 SHA-256。设备上用 `hal_sha256`（mbedtls）[源 lib/hal/hal_sha256.h]，模拟器用 `sim/lib/simio/sha256.h`。纯函数库 `lib/core/profile` 不直接调用它们：Runtime 算好 16 字节的摘要再交给 `on_hello(digest, plugged)`，这样 native 测试不依赖 HAL。

### 4.3 为什么 USB 上不用配对密钥

#19 写了"多台主机配对，每台一把密钥"；docs/05 §8 则把"NVS 密钥 + hello 里的 HMAC 挑战"和无线放在一起。v0.8 只有 USB，所以不做配对密钥，理由如下：

- `host_id` 是 64 位随机数，只有那台 Mac（权限 0600 的文件）和设备知道，设备也从不把它说出去。同一台 Mac 上的恶意程序本来就不在防护范围内 [源 SECURITY.md]。
- **USB 上也不是完全没有第三方**：cpad 在绑定某块板的 USB 序列号之前，会把 `host_id` 明文发给任何一个 303A:1001 的串口 [源 port_finder.py:3]。所以一块插到你家里 Mac 上的陌生 ESP32-S3 开发板，能在 cpad 第一次握手时拿到家里那台的 `host_id`，以后拿去冒充它。这要求有人能往你家里的 Mac 上插设备，属于"物理 USB"这条信任边界之内；写进 §8.3 T4 的剩余风险。
- 要冒充家里那台 Mac，其他的路是拿到家里 Mac 的 `$CPA_HOME`（硬件绑定挡住了直接拷贝，§4.1），或者把设备的 Flash 读出来。走通后一条，对方已经拿到了想要的东西（设备上的全部明文），HMAC 并不能多挡住什么。
- 而加上挑战，就要多一次往返、在 NVS 里存密钥、两端各写一套实现，还得处理"Mac 换了但密钥没换"的情况。
- **等到做无线时**，线上的内容会被别人听到，`host_id` 就不能再当口令用了。那时按 docs/05 §8 做正式配对。

- **选择单开着的时候，什么都不交**，线上按"未分配"处理：`hello` / `pong` 带 `prof{ok:[], ask:true}`，`pending`、`files.n` 报 0。否则在你选"公司"之前，升级前的待传可能已经交给了这台 Mac。按 `` ` `` 关掉选择单等于"以后再说"。

- 选"不分档案"：要确认。确认后一切照旧，以后不再问。想分的时候，连着 Mac 打开 系统 → 档案 →"开始分档案"，会弹出同一张选择单（不含"不分档案"这一行）。
- 选"家"或"公司"：进入 §5.3 的确认框。

- **状态栏**：时钟左边加一个字，用档案的颜色显示，例如 `… ※k3 公 13:42 83%`；没分档案时不显示。连着未分配的 Mac 时，左边的链路一栏显示 `◇ 未分配`（Warn 色），这是 `link_glyph` 新增的一个取值 [源 status_bar.cpp]。

## 6. WiFi（P8-W，v0.8 不做）

设备今天没有任何 WiFi 或 BLE 代码；ADR 0001 定过 IDF 4.4 已经 EOL、加无线功能之前要重新评估工具链 [源 adr/0001-toolchain.md:77]；WiFi 栈还可能把空闲堆压到 150 KB 的底线以下 [推；源 docs/13 §10.3]。所以 v0.8 不做。以后如果做，方向是"只被动扫描、只建议、从不自动切换"（SSID 和 BSSID 都能伪造），先要通过闸门 **G-WIFI**（工具链重评估、堆、不发包、不影响 USB 链路），细节到那时再写。一台笔记本（形态 B）的 WiFi 信号放到 P8-B1 一起评估。

## 7. Mac 端：cpad、MCP、导出

### 7.1 cpad 的规则（P8-D1）

| # | 规则 |
|---|---|
| D1 | 每次收到设备的 `hello` / `pong`，记下其中的 `prof`。`ok` 里出现了新的档案，就追加进 `$CPA_HOME/profile.json`（权限 0600，**只增不减**：记"这台 Mac 收到过哪些档案、第一次是什么时候"，如 `{"version":1,"served":[{"prof":"work","since":"…"}],"devices":{"<dev>":{"ever_ok":true}}}`），并记一条事件 `prof.seen{dev, ok, legacy}` |
| D2 | 设备报了 `prof` 时：`outbox.item` 的 `prof` 必须在 `ok` 里；没有 `prof` 的条目，只在 `legacy` 有值时才收下，并按 `legacy` 记录。两条都不满足（设备 bug，或 cpad 还没看到新的 `prof`）：**什么都不写、不回 `rejected`**，记 `prof.mismatch{kind:"item"}`，然后**重新发一次主机 `hello`**。按现有不变式，这会清空在途、条目退回待发，设备的 `hello` 回复里带着最新的 `prof` |
| D3 | 录音：`file.items` 里 `prof` 不在 `ok` 里的段，不 `get`、不 `del`，记 `prof.mismatch{kind:"file", n}`，同样重新握手一次 |
| D4 | 同一次连接里连续 3 次 D2 / D3 不一致：停止接收这台设备的条目和录音（不回 `ack`、不拉），`cpa status` 和日志告警"device profile state is inconsistent"。设备上的东西原样留着，不会进 `bad/` |
| D5 | `item.received` 记录里带上 `prof`。cpad 写的 `manifest.json` 加可选字段 `prof`，录音契约 v1 允许新增字段 [源 protocol/recording/v1/README.md"向前兼容"] |
| D6 | `ok` 为空时（设备正在问你，或者这台 Mac 被设成了"都不是"），不推快照；`cpa status` 显示"在设备上给这台 Mac 选档案"。设备那边按 §3.5 第 6 条回显 `revs`，旧 cpad 也不会反复重推 |
| D7 | `cpa status` 加一行 `profile: work (公司)  device now: work`。设备当前的档案不归这台 Mac 时，显示 `device now: other`，因为设备不会告诉它具体是哪个（§10.3） |
| D8 | 同一个 `dev` 以前在这台 Mac 上报过**非空的** `ok`、现在不报 `prof` 了（固件被降级，或者你在设备上整片擦除后重来）：在 `cpa status` 和日志里警告"device no longer separates profiles"。只报过 `ok:[]`（比如选择单开着时、或者你选了"不分档案"）的不算。cpad 拦不住这种情况，只做警告 |
| D9 | v0.6.1 的设备审批：设备报的 `prof.act` 是 `null`（当前档案不归这台 Mac，设备不会发 `choice.get`）时，`decide` 立即回 null（`reason:"other_profile"`），不让 hook 白等 100 s（docs/17 §5.1） |
| D10 | （2026-10-22，docs/25 §4.5、R1-B）每个自定义去向带 `profiles:[…]`：`cpa dest add --profile X`（可重复），不给就是"每个档案都行"；`profile.json` 落地以后，`served` 多于一项时必填。前置检查 `other_profile`：去向有 `profiles` 而条目的 `prof` 不在里面（或不知道）就降级成今日笔记；所有 `dest.*` 审计行带 `prof`。§12 的金丝雀测试加一条：家里的字符串永远不出现在公司去向的链接、剪贴板写入里 |
| D10 | `host_hw` 和 `cpa host reset`（§4.1） |

没有档案标记的老数据（v0.8 之前的笔记、录音和事件），算作这台 Mac 的**默认档案**：`profile.json` 里 `served` 的第一项 [源 docs/15 §3.11]。

### 7.2 MCP 和导出（docs/15 的 D 期，P8-D2）

- `cpa mcp serve --profile work`：只返回标记为 `work` 的数据，再加上没有标记、而默认档案是 `work` 的老数据。**过滤只看数据上的标记**，不看设备此刻的状态：设备忘掉这台 Mac、正在问你、刷了机，都不会让 AI 客户端下次连不上。
- `--profile X` 而 `profile.json` 的 `served` 里从来没有 X（比如在公司的 Mac 上用 `--profile home`）：拒绝启动，退出码 2，stderr 写"profile home was never served on this Mac"。不悄悄返回空列表，免得你以为家里什么都没记。
- `profile.json` 不存在（这台 Mac 从没收到过带档案的东西）：`--profile` 一律以退出码 2 退出，stderr 写"no profile has been served on this Mac yet"。
- **每日笔记不过滤**：笔记的行上没有标记。形态 A 下一台 Mac 的笔记目录本来就只属于一个档案，所以整个返回；工具说明里写明"笔记不按档案过滤"。
- `mcp.json` 加 `"profile_required": true` 以后，没带 `--profile` 就拒绝启动 [源 docs/15 §3.11]。服务**从不**根据客户端自报的名字切换档案。
- docs/15 B 期的写入工具（`add_note`、`add_todo`、`queue_add`）写的事件带上 `prof`：`served` 只有一项时取它，没有或多于一项时不带（算默认档案）。
- `get_status` 返回的设备计数，本来就只包括这台 Mac 能拿的（§3.5 第 3 条），不会透露另一个档案有多少东西。
- `cpa export --profile work` 同理，`CPA-EXPORT.json` 里加 `"profile":"work"`；`profile.json` 不存在时同样退出码 2。仍然不导出 `host_id` [源 docs/15 §2.4]。
- **v0.8 之前这些参数都不存在**，和 docs/15 的约定一致。

### 7.3 一台 Mac 两个档案（形态 B，P8-B1，等你确认）

这里只列要做的事，不展开：
- 设备允许一台 Mac 绑两个档案，前提是 cpad 在 hello 里报 `caps.prof`；
- cpad 的 `config.json` 加 `profiles: {home: {notes_dir}, work: {notes_dir}}`，按条目的 `prof` 写进不同的笔记目录和录音目录；
- `rec.list` 加 `prof`，只列当前档案的录音历史；
- 项目表和 session 仍由这台 Mac 共用；
- 档案信号的来源（手动、Mac 的 WiFi）到那时一起评估。

**这种形态在安全上并不分开**：同一个 macOS 用户、同一块硬盘，只是整理上分开。README 里要写明。

## 8. 威胁模型

### 8.1 要守住什么

**一台"公司"的 Mac 永远拿不到"家"的任何采集的内容**，包括打字的、语音的、会议录音，也包括还躺在 SD 卡上没传的；反过来也一样。**也不给按别的档案算出的计数字段**（`pending`、`files.n`、`files.rev`、`revs.*`）。少量元数据泄露见 §8.3 T14。

这些保证**只对正式版固件成立**。测试版固件有 `debug.key`，任何一台连着的主机（包括未分配的）都能用它替你按选择单、给自己绑定；CI 和 release 工作流已经检查正式固件里没有 `debug.*` [源 protocol/README.md 第 16 条]。

### 8.2 三个等级

| 等级 | 防的是 | 怎么做 | v0.8 |
|---|---|---|---|
| **L1 路由** | 诚实的 cpad 拿错了：插错 Mac、新 Mac、从别处拷来的 `$CPA_HOME` | 设备按档案过滤（§3.5）；派生条目跟着来源；未知 Mac 默认不给；`host_id` 当口令用，设备只存哈希、只接受 ≥16 个字符的，Mac 端跟硬件绑定；cpad 再核对一遍 | **做** |
| **L2 配对密钥** | 有人在线路上冒充主机 | NVS 密钥 + HMAC 挑战（docs/05 §8） | 不做。理由见 §4.3，等做无线时再做 |
| **L3 落盘加密** | 存心读设备的 Mac（用 esptool 读整片 Flash，或刷个固件读 SD 卡）；设备丢失；SD 卡被拔下 | 每个档案的条目和录音，先用那台 Mac 的公钥加密再写盘。协议里早就为此留了 `enc` 这个名字 [源 protocol/README.md 第 14 条]；具体算法留给 P8-E 的设计 | 不做。单列为 P8-E，由你决定（§15 第 2 条） |

**为什么 L1 挡不住 L3 防的那类对手**：设备没开 Flash 加密，也没开 Secure Boot，因为这两样都是单向操作，开了以后社区的刷机工具就都用不了了 [源 docs/04 S11；SECURITY.md]。今天的 USB 串口支持自动复位进下载模式，`pio run -t upload` 就是靠这个刷机的 [源 docs/13 §9.6；adr/0001-toolchain.md:100]。所以一台存心的 Mac 不需要你按任何键，就能读出 LittleFS 和 NVS；再刷一个固件，就能读 SD 卡 [推]。这跟档案没有关系，是因为设备本身就是明文存储介质。

**L3 的代价**（所以默认不做）：
- 要先过闸门 G-ENC：录音时每秒加密 32 KB 的 CPU 和堆开销 [待]；ESP32-S3 不开射频时，随机数的熵够不够 [待]。
- `file.*` 的语义要改：传的是密文，由 cpad 解密。
- **v0.5 的设备回放对加密的录音不能用**，因为设备自己没有私钥。
- 设备也看不到自己存下的正文了。

### 8.3 威胁表

| # | 威胁 | 怎么应对 | 剩下的风险 |
|---|---|---|---|
| T1 | 家里的待传和录音被公司的 cpad 拉走 | §3.5 的过滤，计数也过滤；cpad 再核对一遍（§7.1 D2、D3） | — |
| T2 | 记的时候打错档案（忘了切换） | 状态栏一直显示档案字；插上绑定的 Mac 自动切换；有浮层、录音中、请求在途时不切换 | v0.8 不能事后改档案（§15 第 4 条） |
| T3 | 新 Mac、朋友的 Mac | 默认不给；选择单的光标停在"以后再说"，400 ms 防误触；选"都不是"就永久拒绝 | — |
| T4 | 一台 Mac 冒充"家里那台" | `host_id` 是 64 位随机数，权限 0600，不进日志；设备只存哈希，从不回显，只接受 ≥16 个字符的；Mac 端跟硬件绑定，拷走 `$CPA_HOME` 也没用 | 拿到家里那台 Mac 的人能冒充它，但那个人已经拿到了家里的归档。cpad 绑定板子序列号之前会把 `host_id` 发给任何 303A:1001 串口，往家里 Mac 上插一块陌生开发板就能拿到（§4.3） |
| T5 | 公司的 Mac 把 `host_label` 改成"家里 iMac"，骗你选错 | 选择单上写明"名字是它自己报的"；而且绑定时你人就在那台 Mac 跟前 | 你选错了，东西就会给错，**已经交出去的收不回来**（§9）。确认框是最后一道关 |
| T6 | 存心读设备的 Mac（受 IT 控制，或有恶意软件） | L1 挡不住。缓解办法：已同步的东西不留在设备上（录音拉走就删，outbox 收到 ack 就删）；状态栏的 `↑0+` 和 系统 → 档案 里的"家 ↑3 录2"提醒你，去公司之前在家插一下，把它清零 | 👤 §15 第 2 条。真要防，就做 P8-E |
| T7 | 设备丢失、SD 卡被拔下 | 和现在一样，是明文 [源 SECURITY.md] | 同上 |
| T8 | 通过 Launcher：浏览 SD 卡（它自带 SD 文件管理和 WebUI）；Launcher 装的其他固件和我们共用一个 NVS，可以改掉绑定 [源 docs/gates/launcher.md:50、54] | 不在 cpa 的控制范围内，README 里写明 [推] | 需要你自己操作才会发生 |
| T9 | NVS 被擦（`erase_region 0x9000`，或被 Launcher 擦掉）后退回"谁都给" | 原则 8：`PROFON` 标记写在 NVS 和**每一个挂上的存储**（内部 cpafs、SD 卡）上；outbox 和录音的开机扫描**都**能打开档案模式；两个扫描都做完之前什么都不交。NVS 丢失后当前档案是"未定"，新记的也是未定，什么都不给，等你重新绑定 [源 docs/gates/launcher.md:114] | 擦 NVS **加上**拔卡或换卡（又没有 cpafs，比如 Launcher 下）就等于重置。要你自己操作才会发生 |
| T10 | 刷回 v0.8 以前的固件 | 旧固件不认 `prof`，谁都给。cpad 会警告（§7.1 D8）；发布说明里写明"降级会失去隔离" | 需要你自己操作才会发生 |
| T11 | 回复、失败兜底打错档案，正文进了另一台 Mac，还在那里开了新 session | 原则 4 和 §3.6 的三道保险：切片只属于当前档案、派生条目取 `src`、请求在途时不切换 | — |
| T12 | 公司 Mac 上的 AI 客户端经 MCP 读到家里的东西 | 家里的东西根本不在公司的 Mac 上；`--profile` 和 `profile_required` 对录音、采集、队列再过滤一遍 | 每日笔记不按档案过滤（§7.2）；形态 A 下没有影响 |
| T13 | 一台 Mac 两个档案（形态 B） | 只是整理上分开 | README 里写明 |
| T14 | 元数据泄露 | 计数字段都按档案算（§3.5） | 条目 ID（MonoId）的序号由 outbox 和录音共用 [源 runtime_outbox.cpp:38]，公司的 Mac 看到 ID 有间隔，能推算出别的档案记了几条；别的档案正在录音时，`files.live` 是 true、`file.get` 回 `E_BUSY live` [源 file_req.h:3]。不为此做按档案分开的 ID 序列：那是范围膨胀 |

### 8.4 要写进 SECURITY.md 的

- v0.8 的信任边界：**每台 Mac 只拿到绑定给它的那个档案**；未知的 Mac 什么都拿不到。只对正式版固件成立。
- 设备仍是明文存储介质。能用 esptool 读 Flash 或者能刷固件的 Mac，可以读到设备上所有**还没同步**的东西，不分档案。去一台你不信任的 Mac 之前，先在家把"家"的待传同步清零（状态栏的 `↑0+` 会提醒你），或者等 P8-E。
- 条目 ID 的间隔和"正在录音"会让另一台 Mac 知道一点元数据。
- 降级固件会失去隔离；擦 NVS 加上换卡等于重置。

## 9. 迁移：从今天的"一个档案"过来

| 阶段 | 设备 | cpad |
|---|---|---|
| 刚升级到 v0.8，还没碰到带 `host_id` 的 cpad | 档案模式关闭，和 v0.7 一样：不带 `prof`，谁都给；项目缓存仍用 `/cfg/projects.json` | 设备不报 `prof`，cpad 也照旧 |
| 第一次碰到带 `host_id` 的 cpad | 弹出 §5.1 的选择单。**选择单开着时暂停交付**，线上按"未分配" | 收到 `prof{ok:[],ask:true}`，不推快照 |
| 选了"以后再说" | 这次什么都不交，下次插上再问 | 同上 |
| 选了"不分档案"并确认 | 记下"已拒绝"，以后不再问，一切照旧 | `prof` 不再出现；不触发 D8 |
| 选了"家"或"公司"并确认 | 档案模式打开：在 NVS 里写档案表，在 NVS 和每一个挂上的存储上写 `PROFON`；当前档案换成所选的；之后新记的都带 `prof`。旧的 `/cfg/projects.json` 不再使用，这台 Mac 马上会推一份新的，存进 `/cfg/pN/` | 下一个 `pong` 起收到 `prof`，写 `profile.json` |
| 设备上有旧的待传 | 弹出 §5.4：把"未定"留着，或者整体交出 | 交出以后，按 `legacy` 接收 |
| 插上另一台 Mac | 弹出 §5.2 的选择单 | — |
| 想关掉 | 所有带标记的待传都清零以后，系统 → 档案 →"关闭分档案"（§5.6） | `prof` 不再出现 |

- **为什么关掉要先清零**：关掉就等于把带标记的东西交给任何一台 Mac。清零以后设备上没有带标记的东西，关掉不会漏。不用再去 Mac 上跑 esptool 整片擦除。
- 如果你只用 v0.4.1 以前的 cpad（没有 `host_id`），档案模式根本打不开，一切照旧。
- Mac 端的老数据算作默认档案（§7.1 末尾）。
- **已经交出去的收不回来**：绑错了再改绑，改绑之前交出去的东西仍在那台 Mac 上。v0.8 之前已经交错的东西也不会自动挪回去：如果你以前就在两台 Mac 之间插来插去，公司 Mac 的 `~/CardputerNotes` 里可能已经有家里的东西，需要你用 `cpa rec ls` 和笔记自己清理。

## 10. 协议新增（只新增，`v` 仍为 0）

### 10.1 总表

| 变化 | 方向 | 内容 | 兼容性 |
|---|---|---|---|
| 设备 `hello`（回复）和 `pong` 加 `prof?` | D→H | `{act?, ok, ask?, legacy?}`，规则见 §10.3 | 旧 cpad 忽略多出的字段 [源 validate.py `obj()`]。档案模式关闭、也没有选择单开着时不带 |
| `outbox.item` 加 `prof?` | D→H | 顶层字段，和 `kind` 平级；`note` 和 `queue` 都可以带 | 旧 cpad 忽略。档案模式关闭时不带 |
| `file.items[]` 每一项加 `prof?` | D→H | 每一段都带 | 同上 |
| `debug.state`（回复）加 `prof?` | D→H | `{mode, act, hosts, legacy}`，只给 HIL 用 | 只在测试版固件里有 |
| 录音契约 v1 的 `manifest.json` 加 `prof?` | cpad 写 | 档案 key | WhisperWoof 忽略不认识的字段 |
| `limits.json` 加 `prof_key_pattern`、`prof_ok_max`（4）、`prof_host_id_min`（16） | — | 两端都读 | — |

- **不新增消息类型**：绑定和切换都是设备本地的操作，cpad 从 `hello` / `pong` 里就能知道结果。
- **不新增错误码**：别的档案的段用 `E_UNKNOWN_ITEM`；cpad 对不上时不回错误，只重新握手（§7.1 D2）。
- **主机 `hello` 不加字段**：v0.4.1 加的 `host_id`、`host_label` 已经够用 [源 hello.schema.json]。`caps.prof` 留给 P8-B1。
- **语义变化（字段不变）**：`files.rev`、`revs.*` 在档案模式下按 §3.5 第 2、6 条报。

### 10.2 例子

```jsonl

{"v":0,"t":"hello","id":"d1","re":"h1","role":"device","fw":"cpa-fw/0.8.0","dev":"020000000001","boot":"3QZK1M7-0000D","up_ms":5120,"rst":"poweron","time":true,"pending":1,"bat_mv":4020,"revs":{"projects":0,"sessions":0,"queue":0},"files":{"n":0,"rev":7,"live":false},"feats":["choose"],"prof":{"act":"work","ok":["work"],"legacy":null}}
{"v":0,"t":"outbox.item","id":"3QZK1M7-0000D-0003","kind":"note","prof":"work","at":{"up_ms":98000,"wall_ms":1792440045000},"body":{"text":"ask Lin about the Q4 deck","project":"deck","dest":"todo"}}
```

最后一行的情况：设备连着一台还没分配的 Mac，正在问你它属于哪个档案。设备上其实有 3 条待传，但 `pending` 报的是 0；`revs` 回显的是这台 Mac 这次推来的那几份，`files.rev` 不随别的档案的录音变化。

### 10.3 字段规则

| 字段 | 规则 |
|---|---|
| `prof.ok` | 必填。key 的数组，0–`prof_ok_max`（4）项，不能重复；v0.8 设备只会发 0 项或 1 项。**只列这台 Mac 自己的绑定**；放宽要等这里先出现（§3.7） |
| `prof.act` | 当前档案的 key，**只在它属于 `ok` 时才给**，否则为 `null`。这样公司的 Mac 不会知道"设备现在处于家的档案"；v0.6.1 的 cpad 也据此判断设备能不能替它审批（§7.1 D9） |
| `prof.ask` | 为 `true` 表示设备正在为这台 Mac 弹选择单 |
| `prof.legacy` | "未定"的东西已经归给了某个档案、而且这个档案在 `ok` 里时，给出它的 key。cpad 据此接收没有 `prof` 的旧条目 |
| `prof`（条目和段上的） | key，格式为 `^[a-z][a-z0-9-]{0,11}$`。设备发出的每一段都带：旧 `.M` 里没有的，按 `legacy` 补上再编码（`file.items` 本来就是现场编码的）。旧的 outbox 文件原样发送、不带 `prof`（文件内容就是线上那一行 [源 runtime_outbox.cpp:95-96]），由 cpad 靠 `legacy` 来认 |
| `debug.state.prof` | `mode`：`off` / `on` / `declined`；`act`：key 或 `null`；`hosts`：绑定的条数；`legacy`：key 或 `null`。只在测试版里有，给 HIL 断言用 |

### 10.6 合并约束

- 没有新的 schema 文件，所以固件 `test_codec_vectors` 里"schema 数 = `kMsgTypeCount + 1`"这条断言不受影响 [源 docs/14 §7.8]。
- 但固件的向量测试要求"解码后重新编码，逐字段相等"[源 test/core/test_codec_vectors/test_main.cpp:1-5；protocol/README.md 第 18 条下的说明]。所以新加的、带 `prof` 的合法用例，必须和固件 codec 认识 `prof` 的改动（P8-F0）**同一批**合进 main。
- `v040_cases.sha256` 只能追加 [源 protocol/README.md"校验"一节]。
- **新的流程放在 `flows/prof/`**：现有的 `core/test_link_flows` 只用 v0.2 的链路核心重放 `flows/`，做不出按档案过滤 [源 test/core/test_link_flows]；主机发 `file.*` 的流程又必须放在 `flows/rec/`。所以 `flows/prof/` 由 Runtime 级的固件测试（`test_profile_flows`）和 daemon 的 `tests/contract` 重放；新工具 `protocol/tools/prof_flows.py` 检查不变式"线上从不出现 `prof ∉ ok(H)` 的条目或段"，登记进 `check_vectors.FLOW_FOLDERS` 的必需流程清单。期望键加 `device.outbox_pending_visible`（H 看得到的待传数）；原来的 `device.outbox_pending` 仍是总数。
- 顺序照旧：先改 05 §6，再改 schema 和向量，最后改两端的实现。

### 12.2 协议

### 12.4 模拟器：三台假 Mac（G-PROF-1）

用现有的 `cpa-sim serve`：一个进程就是一台设备，卡和 outbox 一直在进程里，跨 `debug.reboot` 也会保留 [源 firmware/sim/README.md]。新写一个脚本 `tools/sim/run_two_hosts.py`，步骤如下：

1. 启动 `cpa-sim serve`；建三个临时 `CPA_HOME`：`home`、`work`、`stranger`（`cpad_sim.py` 本来就要求它们在临时目录里）。
2. 启动 cpad(home)，通过 stdin 按键，在选择单上选"这台是 家"并确认；等到下一个 `pong` 带上 `prof`。
3. `usb off`；记 3 条笔记、1 条待办、1 条排队项，正文都带 `HOMECANARY-<n>`；再录一段便条（用 `--mic` 指定的 WAV）。记下设备报的录音会话 ID。
4. 停掉 cpad(home)，启动 cpad(work)，`usb on`，选"公司"并确认；当前档案马上换成公司。记 2 条带 `WORKCANARY-<n>` 的笔记，再录一段会议。
5. **切换泄露的回归**：`usb off`，启动 cpad(home)，`usb on`（自动切到家）。对一个家里的 session（fake-claude）发一次回复，在 `agent.result` 回来之前手动切到公司，断言被推迟（"等 Mac 回完再换"）；回来以后再切到公司，断言"等你"里已经没有家里的 session。在公司档案下记一条 `WORKCANARY-x`。再让 cpad(home) 重启一次（同一台重新 hello），断言当前档案仍是公司。
6. 停掉 cpad(home)，启动 cpad(stranger)，`usb on`，等 30 s，选"以后再说"。
7. 再插 home，再插 work，中间做一次 `debug.reboot`。
8. **断言**：
   - work 的 `events.jsonl`、笔记目录和 `recordings/` 里，没有任何 `HOMECANARY`，没有第 3 步的录音会话 ID，也没有 `prof:"home"`；第 5 步的回复只出现在 home 那边；home 那边同样没有任何 `WORKCANARY`（包括第 5 步的 `WORKCANARY-x`）；
   - stranger 的 `events.jsonl` 里没有 `item.received`，一段录音都没拉到，`cpa status` 显示 `pending 0`；
   - 两边各自收全了自己的东西：不只要"没收错"，还要"没丢"；设备的 `bad/` 是空的；
   - 每一步的 `debug.state.prof` 都和预期一致。
9. 再单独跑一次"未定"的流程：先在不分档案时记 2 条，再开始分档案并选"先留着"，断言两台 Mac 都拿不到；然后在 系统 → 档案 里把未定的交给家，断言只有 home 收到。

截图用 `cpa-sim shots` 和新脚本 `scripts/v08_profiles.cpas`，覆盖：第一次的选择单、新 Mac 的选择单、确认框、未定、系统 → 档案、状态栏的"家"/"公"、`↑0+` 和 `◇ 未分配`、锁屏卡片。每张都要满足 `missing_glyphs == 0`。

**现有的 HIL 场景**：`run_hil_sim.py` 用的是真 cpad（自带 `host_id`），而模拟器开机时 NVS 是空的，第一次握手就会弹 §5.1 的选择单、暂停交付，`capture`、`offline_replay`、`rec_*` 这些场景都会卡住 [源 firmware/sim/README.md"HIL scenarios on the virtual device"]。办法：`tools/hil` 的握手步骤之后加一步"如果 `debug.state.prof.ask` 为真，就用 `debug.key` 选'不分档案'并确认"，这些场景就和今天一样跑；CI 里用 v0.8 固件把全部旧场景再跑一遍。真机 HIL 同样处理。

模拟器的 `FakePlatform` 要能保存档案表，这样它才能跨重启保留（P8-S）。

### 12.5 真机（G-PROF-2）

- 在同一台 Mac 上用两个 `CPA_HOME`（即两个 `host_id`）轮流跑，步骤同 §12.4，只是换成真设备和真 SD 卡。
- 再加三步，验证原则 8 和它的边界：
  1. 只擦 NVS、卡还在：开机后档案模式仍然开着（SD 上的 `PROFON`、带标记的条目都能打开它），当前档案是未定，什么都不给；
  2. 只擦 NVS、拔掉卡，但内部 cpafs 上有 `PROFON`（非 Launcher 布局）：同上；
  3. 擦 NVS、拔卡、又没有 cpafs：这是写明的剩余风险（§8.3 T9），断言设备回到"没分档案"并弹出第一张选择单，而不是悄悄交东西。
- 👤 如果是形态 A：请你在两台真 Mac 上各插一次，约 10 分钟；顺便看一遍选择单和确认框的文案。

## 14. 风险

| 风险 | 怎么应对 |
|---|---|
| 你其实是一台笔记本来回带（形态 B），v0.8 帮不上忙 | §15 第 1 条先问清楚；模型和协议都给形态 B 留了位置（`ok` 是数组），做 P8-B1 时不用改协议的形状 |
| 离线时忘了切换，记错了档案 | 状态栏一直显示档案字；插上绑定的 Mac 时自动切换；v0.8 不能事后改，已列为待你决定的事 |
| 回复或失败兜底打错档案 | 切片带 `src`、换档案清空、请求在途不换；性质测试和模拟器第 5 步专门守着（§3.6、§12） |
| 第一次绑定时 cpad 还不知道新的 `prof`，条目被拒收后删掉 | 放宽等 `pong`；cpad 对不上只重新握手、从不 `rejected`（§3.7、§7.1 D2） |
| 公司的 Mac 不让装 cpad | 那么"公司"档案的东西会一直留在设备上（`↑0+`、系统 → 档案 里看得到）。👤 和 §15 第 1 条一起问 |
| 两个档案共用 outbox 的 200 条容量 | 一个档案长期不同步，会挤占另一个档案的空间。系统 → 档案 里显示各自的数量；满了以后按现有规则拒收新条目 |
| 两个档案的录音混放在 SD 卡上 | 靠 `.M` 里的标记区分，由单元测试和性质测试守住过滤；拔卡就是明文（T7） |
| `OutboxStep` 变大，压到循环栈 | 跑 `stack_budget.py` [待]；不够就压缩成每条 2 位 |
| 新用到的字形不在 efontCN_12 字库里 [待] | 截图测试断言 `missing_glyphs == 0`；缺字就换成 ASCII 引号 |
| NVS 被擦以后退回"谁都给" | 原则 8：`PROFON` 写在 NVS 和每个存储上，两个开机扫描都能打开档案模式；真机测试专门擦 NVS 三次来验证；"擦 NVS 加换卡"写明是剩余风险 |
| 现有的 HIL 场景被第一张选择单卡住 | `tools/hil` 加一步自动选"不分档案"；CI 用 v0.8 固件重跑（§12.4） |

| 自动切换时你没注意到档案已经变了 | 每次都有提示；状态栏的字和颜色一起变；只在插线或换 Mac 时才自动换 |

## 15. 需要你拍板

如果你不回复，就按默认值做。

1. **你的用法**：是两台 Mac（家里一台、公司一台），还是一台笔记本来回带？公司的 Mac 能不能装 cpad？**默认：两台 Mac，而且公司的 Mac 能装**，v0.8 按形态 A 做。如果是一台笔记本，就先做 P8-B1，但那样只是整理上分开。
2. **防到什么程度**：**默认：v0.8 只做 L1**，也就是按档案路由、未知 Mac 不给、`host_id` 当口令；设备上的明文风险和少量元数据泄露写进 SECURITY.md。如果你认为公司的 Mac 可能故意读设备，那么在 P8-E 做好之前，别把设备插到公司的 Mac 上，或者去之前先在家把"家"的待传同步清零。备选：v0.8 就做 P8-E（落盘加密）。代价是 v0.5 的设备回放不能播放加密的录音，并且要多过一个闸门 G-ENC。
3. **未知的 Mac**：**默认：什么都不给**，弹出选择单，光标停在"以后再说"。
4. **离线记的东西归哪个档案**：**默认：归当前档案**；插线或换 Mac 时自动切到那台 Mac 的档案，并给出提示；同一台 Mac 重新握手不撤销手动切换；v0.8 不做事后改档案。备选：插上时先问你一次再切。
5. **升级前的待传**：**默认：第一次绑定时问一次**，光标停在"先留着"；以后可以在 系统 → 档案 里整体交出。
6. **档案的个数和名字**：**默认：固定两个，"家"和"公司"**，状态栏显示"家"或"公"。
7. **每个档案管哪些东西**：**默认**是项目缓存、去向缓存、会议录音开关，以及状态栏的字和颜色。不做"每个档案开哪些应用"。会议录音开关是 #19 点名的，但如果你用不上，可以砍掉。
8. **WiFi 和时间段**：**默认：v0.8 都不做**。WiFi 以后做成 P8-W，要先通过工具链评估和 G-WIFI。时间段规则不做。
9. **版本**：**默认：v0.8**（排在 docs/14、docs/15 之后）。如果你**现在**就已经在两台 Mac 之间来回插，就把 P8-P、P8-F0、P8-F1、P8-F2、P8-D1 提前到下一个版本，界面先用最简单的确认框。docs/13 §18 第 8 条原本就是这样安排的。

## 附：评审意见怎么处理的
