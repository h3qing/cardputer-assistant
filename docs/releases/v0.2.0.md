## v0.2.0 · Launcher + microSD storage

This release moves the Cardputer ADV's quick notes and items waiting to sync onto the **microSD card**, and lets the firmware sit in the **bmorcelli Launcher** alongside other firmwares (such as the factory firmware or Bruce) and be switched at any time.

### New
- **SD card storage**: items waiting to sync live under `/cpa/` on the SD card. FAT cannot guarantee atomic renames, so a commit protocol that does not rely on renaming is used. Without a card it falls back to the internal partition `cpafs`; when booting with a card inserted, items in the internal partition that have not synced yet are migrated to the SD card **exactly once**.
  - Measured on the device: save p95 **10.5 ms** (v0.1's internal Flash took 108–158 ms when full at 200 items); a backlog of 100 notes all delivered within 1.55 s; 20 items migrated, each delivered exactly once.
- **Launcher compatible**: a single binary that detects at startup whether it was started via the Launcher. The internal partition is renamed from `spiffs` to `cpafs`, specific to this firmware, so it **never touches the `spiffs` partition shared by other firmwares under the Launcher**.
  - Measured: Launcher 2.9.1 installed the factory firmware and this firmware over serial; after starting, this firmware reports `launcher=yes`, `store=sd`.
- **Release artifacts renamed**: `cpa-v0.2.0.bin` (merged image; can be flashed whole from 0x0 or installed by the Launcher, where it shows as cpa-v0.2.0) and `cpa-v0.2.0-app.bin` (app only, flashed from 0x10000).
- **One-key back** (#15): with an empty input field, one Backspace exits; outside an input field, the top-left key goes back.
- **Protocol**: `hello` gains two optional fields, `store` and `launcher` (protocol version `v` is still 0); every line the host sends starts with `{` or is empty, so the Launcher's serial console never runs it as a command.
- **daemon**: `cpa status` shows the storage location and how the firmware was started; when the control socket path is too long, it says which path, what the limit is and how to change it (#4).

### Fixes
- Patched SD driver: the driver bundled with core 2.0.17 could not initialise some large cards (an ACMD41 argument issue); patched and placed in `firmware/third_party/SD`.
- CI: GCC 13's `-Wformat-truncation` issue; a race in the test fixture reading and writing the fake-claude state file.
- The pre-upload script no longer shortens a longer pause the daemon already has.

### Verification
- 302 firmware native tests, 96% coverage; 593 daemon tests, 97.3% coverage; 175 HIL tool tests.
- Device: device tests (SD storage, memory budget); HIL 13/13 on firmware with a card, 10/10 without; migration; one-key back; 10 minutes of continuous running with no loss or duplicates.

### Install
- **Flash directly**: `esptool.py --chip esp32s3 write_flash 0x0 cpa-v0.2.0.bin`, or run `pio run -e cardputer-adv -t upload` in the source folder.
- **Via the Launcher**: with the Launcher installed, press RST then Enter to open the menu, and install `-app.bin` with the serial command `flash firmware cpa-v0.2.0 <字节数>` (byte count; see G-L1 in docs/07). Run `cpa pause` before installing so the daemon does not grab the port.
- The SD card must be FAT32. Cards over 32GB usually ship as exFAT and must be formatted on the Mac first.

### Known issues
- **#14**: with the switch ON (on battery), plugging in USB is not detected by the Mac; switching to OFF connects. Suspected VBUS back-feed, waiting for an experiment to confirm.
- Manual checks not done yet: firmware switching and the four kinds of reset (G-L2), coexistence with Bruce (G-L3), booting with the card removed, real power loss, the 60-minute long test (see docs/07).
- With the internal partition full, save p95 is still above 100 ms; only hit when no SD card is inserted.
