## v0.3.1 · 录音不出声，录音电平调高

这一版改两件事。

1. **录音全程不再出声**。这是用户的决定：录音不出声，供个人使用。设备只给自己用，所以提示音都去掉了，屏幕是唯一的提示。
2. **录音电平调高**（见下面的"麦克风增益"）。用户录音时手持设备、用正常音量说话。

### 改动
- **不再响的声音**：便条开始和已保存、会议开始和已保存、太短或取消、拒绝或失败。设备在录音和拒绝录音时都不出声，扬声器根本不打开。
- **屏幕提示**：录音页的 `● REC` 和电平条、状态栏的 `●12:31`、原有的拒绝说明（比如"录音需要 SD 卡"）都照旧。
- **便条的提示语**：准备时屏幕上的提示从"听到嘀声后说话"改成"**看到 ● REC 再说话**"。
- **会议确认框照旧**：`Opt+R` 之后仍然先弹出"请先告知在场的人"，按 Enter 才开始；结束也要确认。
- 没插 SD 卡（或者是 nosd 构建）时不再启动音频任务：以前它只用来放拒绝提示音，现在没事可做，省下约 6 KB 内存。
- 固件版本报 `cpa-fw/0.3.1`。

### 麦克风增益
- **以前的问题**：用户手持、正常音量说话的两段录音（7.4 s、57.3 s），样本峰值只有 −23.7 dBFS，有声部分的 RMS 约 −45 dBFS。增益全部加在 16 位样本之后（M5Unified 的 `magnification` 16，`over_sampling` 1，相当于 ×8），所以每个样本都是 8 的倍数，人声只用到大约 ±267 个量化级。
- **现在的做法**：增益放进 ES8311 codec，在样本变成 16 位之前加上去。
  - 每次 `Mic.begin()` 之后写 PGA（REG14）和 ADC 音量（REG17），并且读回来核对。`Mic.begin()` 每次都会把这两个寄存器写回 M5Unified 的默认值，所以每次开始录音都要重写。
  - 一个寄存器最多试 3 次。还不对就照常录音：这个寄存器停在 M5 的默认值，电平会比预期低，但录音不会丢。
  - `magnification` 改成 2。`over_sampling` 固定为 1，这时 2 就是不放大，样本原样保留。
  - 便条和会议用同一个增益。
- **目标**：手持、正常音量说话时，整段录音的样本峰值在 −12 dBFS 左右，允许 −14 到 −10。
- **定下的值**（HIL `mic_cal` 标定，2026-10-21：Mac 内置扬声器放参考音和中英文朗读，设备录 11 档增益）：
  - PGA：9（+27 dB）。REG17：0xC4（+2.5 dB）。`magnification`：2（不放大）。codec 里一共 +29.5 dB，比 v0.3.0 的电平高约 11.4 dB。
  - 预计这位用户的峰值：−11.9 dBFS。有声部分 RMS：−35.2 dBFS。安静时噪声底：−73.7 dBFS（150 Hz 高通后 100 ms 窗的中位数；不滤波约 −68 dBFS）。
  - `lead_ms`：仍是 150。新增益下 5 次无声开始，开头冲击 70–90 ms。
  - 为什么是这一档：+30 dB 的 5 种分法（PGA 6–10，其余放在 REG17）信噪比都在 37.4–39.0 dB 之间，按规则取 PGA 10；它预计峰值 −11.4 dBFS，再向 −12 的目标微调半档，规则落到 PGA 9 加 2.5 dB 的 ADC 音量。两档音质一样。
- **测试固件新增 `debug.mic{pga 0–10, vol 0–255, mag 1–64}`**，回 `ack`。
  - 设置的增益从下一次开始录音起生效，正在录的那一段不受影响。只给标定用。
  - 正式固件不认识它，回 `E_UNKNOWN_TYPE`。
  - 协议 v0 只新增，`v` 仍为 0。
- **Mac 端要跟着调**：WhisperWoof 的静音门限 `CARDPUTER_SILENCE_RMS` 建议从 0.0005 调高到 **0.00084**（标定给的值，取噪声底和"离设备 1 m 说话"估计电平的 dB 中点）。实测房间比预想的安静：不滤波的噪声底约 0.0004，0.0005 只比它高一点，没人说话的片段容易被当成有声。cpad 不用改。

### 没有变的
- 手势（按住 G0 录便条，`Opt+R` → Enter 录会议）、400 ms 防误触、拒绝规则和屏幕上的原因、5 分钟和 3 小时的上限、★ 标记。
- 录音契约 v1、协议 v0（只多了测试固件的 `debug.mic`）、分段、`file.*` 传输。cpad 不用改；WhisperWoof 只调静音门限（见上）。

### 验证
- 协议工具测试 246 个，录音契约测试 87 个，向量检查通过（测试固件 26 种消息，多了 `debug.mic`；15 个流程）；固件 native 测试 416 个，覆盖率 94%；daemon 测试 848 个，覆盖率 96.8%；HIL 工具测试 335 个。正式固件里找不到任何 `debug.*` 钩子（和 CI 同样的检查）。
- 真机（2026-10-21，同一台设备、同一张卡）：
  - **增益标定 `mic_cal`**：8/8 项检查通过，11 档都有效。前后两次 B1 只差 0.02 dB；不放大的那一档是 −17.91 dB（应为 −18.06 ± 0.5）；每档实测增益比名义值高 0.30–0.76 dB（允许 ± 1.5）；用音和用人声测出的增益最多差 0.15 dB；+33 dB、+36 dB 两档也没有一个样本削波。两个独立的复算都得到同一个结果。
  - **核对 `mic_verify`**（刷入新常量的测试固件）：5/5 通过。不发 `debug.mic`，重启后按固件自己的增益录：比 v0.3.0 的增益高 11.74 dB（名义 11.44），人声测出 11.83 dB；推算手持峰值 **−11.96 dBFS**，有声部分 RMS −35.3 dBFS，噪声底 −74.3 dBFS；没有削波；样本步长 1，16 位都用上了。
  - **设备测试**：`test_mic_gain` 3 次里 2 次全部通过（寄存器读回 0x1A / 0xC5，步长 1；换回 M5 默认值后读回 0x10 / 0xBF，步长 8），第 1 次见下面的已知问题。`test_rec_budget` 3/3：空闲剩 279,604 B 堆，录音时剩 273,224 B，音频任务栈余量 2,364 B。
  - **录音回归**（新增益的测试固件）：`rec_memo` 18/18、`rec_meeting` 20/20、`rec_resume` 10/10、`sd_empty` 2/2、`sd_store` 8/8、`sd_bulk` 8/8、`capture` 5/5、`handshake` 6/6。
    - 便条从按下 G0 到第一个样本 506 ms（v0.3.0 是 588 ms，含 500 ms 长按门限），会议从 Enter 到第一个样本 8 ms（v0.3.0 是 368 ms）：没有提示音以后开始得更快。
    - 会议 3 段，两个整段都正好 480,000 样本；★ 误差 −47 / −95 ms；拉取 335.9 KB/s，1 小时录音约 5.6 分钟；断点续传的偏移正好是 `.part` 减 64 KiB。
    - 这几段录的都是没人说话的房间：开头 150 ms 之后峰值不超过 72（−53 dBFS），RMS −67 到 −70 dBFS，样本步长 1。开头的冲击只在第 0 段，峰值约 4,600（−17 dBFS），落在 150 ms 的 `lead_ms` 里。每次刷机或重启后的第一段录音，前 512 ms 都正常，不是全 0。
    - `handshake` 第一次紧跟在 `sd_store` 的重启后面跑，4/6：这是 HIL 已知的问题（07 号文档 §5.9 第 3 条），它取到了重启前的 hello。按 v0.3.0 的顺序放在 `sd_bulk` 后面重跑，6/6。
  - 刷回正式版，用户的 cpad：`link: ready`、`fw=cpa-fw/0.3.1`、`store=sd`，卡上 0 段。

### 已知问题
- **`lead_ms` 的余量和数字增益有关**：新增益下无声开始的冲击是 70–90 ms，150 ms 够用。但冲击出现在 PGA 之后，会随 REG17 和 `magnification` 一起变大：在 v0.3.0 的 ×8 下，无声开始的冲击长达 260 ms。以后如果再调高数字增益，要按 docs/gates/m3-device-gates.md §5.2 重测 `lead_ms`。
- **开机后的第一次录音，开头约 0.75–1 秒全是 0**（#31，v0.3.0 就有）：用户的两条便条都是开机后录的第一条，开头分别有 754 ms 和 994 ms 的样本全是 0；紧接着录的会议没有。录音引擎不补零，0 来自麦克风这一路，最可能是 ES8311 上电后的模拟预热（M5Unified PR #348 在同款 codec 上记录过约 1 s）。HIL 没测出来，是因为设备一直插着 USB，codec 一直通电。`test_mic_gain` 那次开头 512 ms 全是 0 也符合这个解释。后果是开机后第一条便条的开头约 1 秒录不到。v0.3.2 修：开机后先把 codec 预热一次；并且等收到第一块非 0 的声音，才显示 ● REC、开始写文件。
- **会议的电平没有单独测**：增益是按手持便条定的，便条和会议共用。离设备 1–2 m 的真实会议录音会不会低于 WhisperWoof 的门限，还要拿一次真会议验证。
- **说话音量只测过两次**：v0.3.1 上用户又手持录了一条便条：峰值 −16.5 dBFS（v0.3.0 是 −23.7），有声部分 RMS −38.2 dBFS（v0.3.0 是 −46.7），样本有 3,517 个不同的值、最大公约数 1（v0.3.0 是 361 个、8）。分辨率完全恢复，电平高了约 8 dB，但比 −12 的预测低 4.5 dB；只有一条，分不清是这次说话轻还是拿得远，之后的录音再看。
- v0.3.0 列出的其余待办照旧（#21、#22、#23 里除提示音音量以外的各项、#14）。提示音音量的耳听检查已经不需要了。
