## v0.5.2 · English by default, a device that rests when dark, and no watchdog in big clean-ups

This release finishes what v0.5.1 left waiting for the device: the boot scan's stack and the task-watchdog fix (#85), the dark-screen idle yield (#87), and English as the device's default language (#94). All three were tested on the real device before they were merged (docs/07 §12). It also fixes the installer's "Broken pipe" noise (#98).

The device, cpad and the Mac app ship together. Protocol v0 does not change, so old and new firmware and old and new cpad mix freely. WhisperWoof keeps working.

### Device
- **English by default** (#94): a device with nothing stored (a new one, or one whose NVS was erased) starts in English. A device that already ran an earlier cpa-fw and was never switched keeps Chinese: on its first boot with this firmware it stores Chinese once. A language you already chose is never touched; Opt+M, `.`, Enter still switches.
- **Rests when the screen is dark on battery** (#87, docs/29 P1): dark and locked, nothing recording, no Mac on the cable and no key for 1 s, the main loop gives up the CPU for 10 ms after each pass instead of spinning at 240 MHz: 98 passes a second instead of about 14,400. A key is at most 10 ms later; lit, dimmed, recording and plugged into a Mac work exactly as before.
- **No watchdog reboot in big clean-ups** (#85, the known issue of v0.5.1): "deliver again" and "Clear kept" on a couple of hundred kept segments no longer starve core 0's idle task. On the device, 200 segments were queued again in 5.7 s and cleared in 14.2 s.
- **More room on the audio task's stack at boot** (#85): with about 100 recordings waiting on the card the boot scan left 1,028 B of the audio task's 6 KB stack; now 1,624 B (the gate is 1,536 B). Nothing else changes: no heap, static RAM or stack size.
- Firmware and simulator code comments are in English (Chinese only where a comment is about Chinese text itself).
- The firmware reports `cpa-fw/0.5.2`.

### Mac
- **Installer**: no more "printf: write error: Broken pipe" lines during a curl install (#98). It was harmless (the install succeeded), but alarming.
- Install instructions give the public `curl … | bash` line only (#97).
- `cpa --version`, `cpa-stt --version` and the Mac app are 0.5.2. No other change on the Mac.

### Upgrade
- **On the Mac**: run the installer one-liner again (README "Install"); running it again upgrades:

  ```bash
  curl -fsSL https://raw.githubusercontent.com/h3qing/cardputer-assistant/main/scripts/install.sh | bash
  ```

  Add `bash -s -- --lang zh` for Chinese output.
- **The device**: flash `cpa-v0.5.2.bin` from this release (`… | bash -s -- --firmware` also checks it and puts it in `~/Downloads`). On the main Mac: sync first (`↑0` and R0), `cpa pause 120`, then write it to 0x0 as in README "Install method A". Writing the merged image erases NVS, so settings go back to their defaults, which now means **English**; recordings and kept copies on the SD card are not touched. Opt+M, `.`, Enter switches to Chinese.

### Known issues
- **Kept copies are plain text** until SEAL encryption (docs/26) exists; clear them before going somewhere you do not trust (SECURITY.md).
- **WhisperWoof does not yet recognise `cpa-stt`'s claim file** (docs/22 §4.10): only one of them can be on.
- The real-device gates listed in v0.4.1 (carry it for a day, run a real meeting at your own pace, pull and reinsert the SD card) still need you.
