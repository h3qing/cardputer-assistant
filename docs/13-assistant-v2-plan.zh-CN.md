## 0. 一页摘要

**目标**：让 Cardputer 从"几个功能"变成"一个助手"：想到什么随手记下；回头找得到录音、等你处理的事和项目；锁屏随手可控；忘了快捷键也能找到。

**先说你今天提的"静音"**：已经定了"录音全程不出声"（录音不出声，供个人使用），`release/v0.3.1` 分支上已经改好、还没发布 [源 CHANGELOG.md 工作区；docs/11 第 8 行]。v0.3.1 之后设备**没有任何声音**，所以"开会时不想让大家听到"已经解决。v0.4 不再加静音键和音量档位：没有声音可以静音，加了就是空开关。菜单的"控制"页会写明"声音：关"。会议确认框保留，文案改成写明"告知并取得同意由你负责"（§7.4）。

**接下来分三步**：

1. **v0.3.x 收尾**：发布 v0.3.1（不出声）；**麦克风增益**单独先发，不等 v0.4。你今天测到的峰值只有约 6.5% FS，开会时离得更远，更不够（§7.5，要你约 20 分钟 👤）；用真实的 WhisperWoof 跑通端到端。
2. **v0.4.0「整机导航」，只改固件**：
   - **主页启动器**（Opt+H）：每个格子上的字母就是快捷键。项目看板挪到 **Opt+P**，Opt+1–9 照旧。
   - **Tab 常驻菜单**，任何页面都能按。菜单有三页：本页的按键、去哪、控制。选中一行按 Enter，效果和按那个键**完全一样**。每页提示栏最右边固定写"Tab菜单"。
   - **Opt+L 锁屏**：解锁时先按 Opt+L，再在 3 秒内按 Enter。锁屏时插着 Mac 也熄屏，口袋里乱按不起作用。
   - **录音时 ● 永远看得见**：锁屏、菜单打开、弹出提示时都一样。现在没有提示音了，屏幕是唯一的提示。
3. **v0.4.1「录音历史与待办」**，加协议和 Mac 端：
   - **录音应用（Opt+V）**：连着 Mac 时翻看全部历史，按全部 / ★ / 便条 / 会议筛选。可以加 ★、归到项目、从列表里隐藏。
   - **待办去向**：Opt+T 打字记一条待办；按住 G0 说话时按 T，这段话存成待办，按 N 存成笔记。

**之后的版本**：
- v0.5：去向做完整（#24，哪个键去哪由你在 Mac 上配置；语音转写后复制到剪贴板；存进 Obsidian）；录音 2.0（设备上回放、真正删除、在 Mac 上打开）。
- v0.6：选项式回复（#16）、待办应用、coding agent。
- v0.7：Mac app（WhisperWoof）和 thinking partner。
- v0.8：情境档案（#19）。

**需要你拍板的 9 件事**（§18）都给了默认值；你不回复，就按默认值做。

## 3. 设计原则

1. **只有一张按键表**。所有绑定都写在 `kKeymap` 里 [源 keymap.cpp:43-100]，菜单从这张表生成。测试保证每个动作都有一句说明，所以菜单写的键和实际按键对得上。
2. **一个字母只代表一件东西**。比如 T 永远和待办有关：全局 Opt+T 是"记一条待办"，在采集页按 Opt+T 是"改成待办"，按住 G0 时按 T 是"这段话存成待办"。已有先例：Opt+1–9 在全局是打开项目，在采集页是改目标项目 [源 keymap.cpp:48-52、72-76]。
3. **常用功能最多按两下**：按 Opt+字母，一下；在主页直接按字母，一下；Tab 再按字母，两下。少用的操作只放在菜单里，不占组合键。
4. **菜单和主页不另开一条执行路径**。菜单里的一行、主页的一个格子，都是"替你按那个键"，所以效果一定和直接按键相同（§6.2）。
5. **采集永远可用**。G0 在任何页面都能用，包括菜单。锁屏时多一步（§7.1）。开会时 G0 永远是加 ★。
6. **录音时 ● 永远看得见**，不管锁屏、菜单还是提示（§7.2）。
7. **会改动 Mac 当前状态的操作，只在连着 Mac、你按键的那一刻做，之后不补做**（PRD 原则 2 的延伸）。
8. **先落档，再投递**；**投递去向只由按键决定，从不由内容决定**。
9. **只用单键和两键组合** [源 04 §8.1]。**协议只新增不修改**，`v` 仍然是 0 [源 05 §6.9]。**录音契约 v1 在 v0.4 里一个字都不改**（§8.4）。

### 5.4 按键分发顺序（更新 05 §5.6）

今天 `Runtime::key_event` 先过 `power_key`，再进 `Shell::on_key`；熄屏时第一个键只亮屏、被吞掉，有浮层时连 G0 长按也会被吞 [源 runtime.cpp:155-162；power.h]。新的顺序：

| 步 | 在哪 | 做什么 |
|---|---|---|
| 1 | **Runtime，排在 `power_key` 之前** | **锁屏关卡**：锁住时只放行解锁键、3 秒窗口内的 Enter 和 G0（规则见 §7.1），其他键全部吞掉，也不点亮屏幕 |
| 2 | Runtime | `power_key`：不变 |
| 3 | Shell | **菜单**：菜单打开时吃掉所有键，G0 例外（§6.1）；v0.4.1 起菜单上写着的组合键也例外，关掉菜单再执行（docs/20 D9） |
| 4 | Shell | **系统键**：Tab、Opt+L，按 §5.3 的表处理 |
| 5 | Shell | 录音浮层（便条 HUD、会议确认框、会议页、结束确认框）：不变 |
| 6 | Shell | 采集页、确认框：不变 |
| 7 | Shell | 全局键：不变 |
| 8 | Shell | 前台应用；应用不处理的返回键退回上一层 |
| 9 | Shell | **按键重放**：应用或菜单要求"替我按一个键"（§10.1）时，放到这一步之后再从第 3 步走一遍。只走一层，重放出来的键不能再重放 |

第 5–8 步就是今天的顺序 [源 shell.cpp:89-98]，第 1、3、4、9 步是新加的。

## 6. 常驻菜单（Tab）

### 6.1 怎么用

- 按 Tab 打开菜单，再按 Tab 或 `` ` `` 关掉。用 `,` `/` 换页，打开时默认在"本页"。
- 用 `;` `.` 选一行，按 Enter：**菜单关掉，然后替你按下这一行写的那个键**。所以忘了键也能完成操作，而且效果一定和直接按相同。每行左边写着键，下次就能直接按。
- 一行写的是一组键（如 `1-9`）时，只是说明，按 Enter 不执行，行尾写"按 1-9"。v0.5（docs/19 §6.5）：键那一列画成键帽，键帽上已经写着 `1-9`，行尾不再重复；只说明的行键帽是另一种颜色。
- 在"去哪"和"控制"页直接按字母，等于按 Opt+那个字母。
- 在浮层上（采集页、确认框、会议页）打开菜单时，只有"本页"和"控制"两页，不能从菜单跳到别处，草稿和正在录的音都不受影响。
- **G0 在菜单里**：开会时 G0 关掉菜单并加 ★；不开会时，G0 先关菜单，再照常开始记一条或录便条。
- **录音时菜单保留状态栏那一行**，所以 ●计时 一直看得见（§7.2）。

### 6.2 菜单内容从哪来

- 每个动作（`Action`）有一句中文说明，集中在一张表里（`action_help`）。
- 每一行都带着它要重放的按键（`HelpRow{ev, keys, label}`，§10.1）。
- **"本页"**：浮层的行直接取 `kKeymap` 里那一层的绑定（`Binding.trigger` 就是要重放的键）；应用自己的行（比如录音列表里"空格 = 加 ★"）由应用的 `help()` 提供；最后加一行系统键。
- **"去哪"**：取全局层的绑定，连续的数字合并成一行（如 Opt+1-9）。
- **"控制"**：锁屏、声音（只读，"关"）、电量、SD 卡、待传录音、↑N、链路状态、cpad 版本。
- 测试保证四件事：每个动作都有说明；全局层的每个绑定在"去哪"或"控制"页里正好出现一次；每一行都能放进 240 px；**在录音列表、采集页、会议页的"本页"上，对每一行按 Enter，效果和直接按那个键完全相同**。

### 6.4 为什么用 Tab

| 方案 | 好处 | 问题 | 结论 |
|---|---|---|---|
| **Tab** | 单键；现在按 Tab 不产生任何事件 [源 test_chord_detector/test_main.cpp:74]；设备只能输入可见 ASCII，Tab 不和输入冲突 | 输入层要新增 `Nav::Menu` 事件，上面那条测试要改一行 | **采用** |
| Opt+/ | 和"?"在同一个键上 | 两键组合，比 Tab 多按一个键 | 不用 |

## 7. 系统控制：锁屏、● 永远可见、声音、会议确认、麦克风

### 7.1 锁屏（Opt+L）

按 Opt+L 后屏幕马上熄灭，键盘锁住。采集页的草稿留在内存里；如果正在开会，录音不停。**插着 Mac 也熄屏**：锁屏优先于"插着电就常亮"的规则 [源 power.h]。

| 锁住时按 | 不开会 | 开会中 |
|---|---|---|
| Opt+L | 亮出锁屏卡片，开一个 3 秒窗口；窗口内按 Enter 就解锁，回到锁屏前的页面 | 同左 |
| G0 短按 | 亮出锁屏卡片 3 秒 | 加 ★ |
| 按住 G0，屏幕是黑的 | **只亮出锁屏卡片，不录音**（这一次按住到松开都不录） | 加 ★ |
| 按住 G0，锁屏卡片亮着 | 录语音便条，录完回到锁屏（§18 第 3 条） | 加 ★ |
| 其他任何键 | 不起作用，也不点亮屏幕 | 同左 |

- **为什么"先点一下 G0，再按住"**：没有提示音以后，口袋里压住 G0 录下一段，你完全不会察觉，录到的还可能是旁人的谈话。分成两步以后，口袋里一次长按只会亮屏；你有意要说话时，只多点一下。
- **为什么解锁要两步**：口袋里同时压到 Opt 和 L、又在 3 秒内压到 Enter，概率很低；而且不需要新增"按住组合键"这类输入事件，因为输入层只在按下时产生事件 [源 chord_detector.h]。
- **实现位置**：锁屏关卡在 `Runtime::key_event` 里、`power_key` 之前；`PowerState` 加 `locked`。被吞掉的 G0 长按，它的松开事件也一起吞掉。
- **锁屏卡片只显示数量**：时间、日期、电量、"等你 2 · 待传 录2 · ↑0"，不显示项目名、session 名或任何正文。
- **锁屏不是安全锁**，作用只是防误触、不让旁人看到内容。它没有 PIN，SD 卡上的数据本来就是明文 [源 04 S11]。README 会写清楚。
- 以后可以加"熄屏几分钟后自动锁"，但要一个存盘的设置项，v0.4 不做。

```
              已锁屏
              13:42
        10/21 周二 · 电 83%
       等你 2 · 待传 录2 · ↑0

   解锁：Opt+L，再在 3 秒内按 Enter
   说一段：先点 G0，再按住 G0
```

### 7.2 录音时 ● 永远看得见

**规则**：只要 RecPhase 是 Cue、Recording、EndConfirm 或 Finishing，背光至少是"调暗"，并且画出 `● REC` 和计时。不管是否锁屏、菜单是否打开、是否在弹提示，也不管提示音设置（现在根本没有提示音）。

- 这延续了 v0.3 的规定："录音中不熄屏，`● REC` 一直可见" [源 docs/11 R11、B4]。v0.3.1 去掉提示音以后，屏幕是唯一的提示，这条规定更重要。
- **锁屏时开会**：背光调到最暗，只在左上角显示红色的"●42:10 ★2"，其他都不显示。
- **锁屏时录便条**：在锁屏卡片亮着时按住 G0，录音期间显示最简单的 ● HUD；松开、存完以后回到黑屏锁定。
- **测试**：{便条, 会议} × {锁屏, 菜单打开, 弹提示} 每一种组合都要画出 ●，背光不低于"调暗"。

### 7.3 声音

- v0.3.1 起设备不出任何声音（录音的开始、保存、取消、失败都不响）[源 CHANGELOG.md 工作区]。v0.4 不加声音，也就不加静音键、音量档位和存设置的文件。
- 菜单"控制"页有一行只读的"声音：关（录音不出声）"。你想找"静音"在哪时，能看到它已经是关的。
- #17（"按住 G0 没有声音，要提示音，带静音开关"）是你 10-20 提的，被今天的决定取代了。建议 Lead 在 #17 上注明理由后关掉。
- 如果以后你想要**只给自己听的便条"嘀"**，那时再加一个设置项"便条提示音：关 / 轻"，并配上 Opt+M 以外的静音键。**会议在任何设置下都不响**（§18 第 1 条的备选）。

### 7.4 会议确认框和同意

- **不变**：Opt+R 先弹确认框；400 ms 内的按键一律忽略；`consent:"ack"` 写进 `.M` 和 `manifest.json` [源 docs/11 G6]；便条只录你自己，不弹确认框。
- **改文案**：v0.3.1 的确认框只写了"请先告知在场的人" [源 rec_overlay.cpp:71-73]。现在没有提示音，旁人只能靠你告知，所以文案要写明责任在你。每行最多 20 个汉字：

```
开始会议录音？（不出声）
加州等地录私下谈话要所有人同意。
请亲自告知每个人并取得同意，
这由你负责。
屏幕会一直显示 ● 和计时。
Enter 我已告知，开始     ` 取消
```

- 确认框打开期间文案不会变，所以不存在"文案刚变、Enter 就按下去"的问题。草案里按 Opt+M 换档位、确认框当场改文案的设计已经删掉。
- README 写明："录别人说话前要告知并取得同意；这不是法律意见。"
- 录音不出声，供个人使用。如果你只录自己，就用便条（按住 G0）；会议录音本来就会录到别人，确认框照旧保留。
- GPIO21 的 LED 没有验证过 [源 11 §2]，不靠它。

### 7.5 麦克风增益（先于 v0.4 单独发）

- **现状**：你录的 7.4 秒便条和 57 秒会议，峰值都只有约 6.5% FS [测]。增益仍是 M5Unified 的默认值：magnification 16、PGA 0 dB [源 audio_io.h:25]。
- **难点**：开会时人离麦克风 1–2 米，说话声比 30 厘米时低 10–16 dB [推]。另一方面，PGA 开到 +18 dB 时，安静房间的底噪已经达到 0.0030 RMS，正好碰到 WhisperWoof 0.003 的小块门限 [测 m3-device-gates.md 第 34、206 行]。只按 30 厘米调一个增益，能过关，开会却可能仍然太小声。
- **完成标准**（两条都要满足）：
  1. 30 厘米正常说话，峰值落在 20–50% FS；
  2. 1.5 米说话，100 ms 窗口的 RMS 至少是所选 `CARDPUTER_SILENCE_RMS` 的 3 倍 [源 m3-device-gates 第 35、223 行]；并且用真实的 WhisperWoof 转写一段从 1.5 米外放出的会议参考录音（Mac 扬声器播放），没有一句话被当成静音丢掉。
- 一个增益兼顾不了两种场景时，允许**便条和会议用不同的增益**：由 `StartSpec` 带上，会议的更高。
- 要你做 👤：用正常音量录一条便条确认效果，再帮忙把设备挪到 1.5 米外放一次，约 5 分钟。增益扫描由 Lead 自动跑：Mac 扬声器放参考音，每档增益录一段、取回、分析。不找旁人试录（录音不出声，供个人使用）。
- **怎么发**：这一项不依赖 v0.4 的任何东西。等 v0.3.1 的静音改动提交以后，能赶上就并进 v0.3.1，否则发 v0.3.2（工作包 V3-G）。

## 8. 录音应用（Opt+V，v0.4.1）

### 8.1 历史存在哪，怎么排序

- **历史在 Mac 上**。Mac 校验收到一段录音后，设备就把这一段删掉 [源 11 §3.3]。daemon 的 `sessions.rows()` 已经能列出每个会话，包括还在设备上没传的 [源 sessions.py:68]；结果事件里有标题 [源 results.py:70]。
- **按页向 Mac 要**：设备发 `rec.list`，Mac 回 `rec.items`，每页 6 条。设备内存里只放一页，列表不进 AppState。
- **排序**：按录音开始时的墙钟时间，新的在前；没有墙钟时间的用归档时间；时间相同时按会话 ID。**不能只按会话 ID 排序**：MonoId 只在同一个 epoch 内按创建顺序排列，而 NVS 被整体擦除后会换一个随机 epoch [源 mono_id.h:2-4；launcher.md R4]。那样今天的会可能排到历史的最后一页。`cpa rec ls` 同样改成按时间排序。
- **翻页游标由 cpad 生成**，设备不解析它，原样带回（`cursor`，最长 32 B）。以后排序方式变了也不用改协议。

### 8.2 能做什么

- **标签**：全部 / ★ / 便条 / 会议，用 `,` `/` 切换；翻到最后一行时自动加载下一页。
- **每行显示**：★（加过星时）、日期时间、标题（没有标题时用便条开头，或"会议 42m"）、时长、状态。

  | 符号 | 含义 |
  |---|---|
  | `↑` | 还在设备上 |
  | `…` | 正在传输或处理 |
  | `✓3` | 已整理，有 3 条待办 |
  | `✓` | 已整理 |
  | `✗` | 没转写成 |

- **按键**：
  - Enter：看详情；详情页上 Enter 不做任何事；
  - **空格：加 / 去 ★**（会议页里空格本来就是加 ★ [源 keymap.cpp:93]）；
  - 1–9 / 0：归到项目 / 不归属，这就是 v0.4.1 的"打标签"（§18 第 5 条）；
  - Opt+D：从列表里隐藏，要确认（§8.4）。
- **"在 Mac 上打开"不放进 v0.4.1**。草案里在详情页按 Enter 就会在 Mac 上执行 `open summary.md`。开会时 Mac 的屏幕常常在共享或投影，两次 Enter 就把纪要亮在大家面前。v0.5 再加，换一个键，并且先确认。v0.4.1 在 Mac 上找录音用 `cpa rec ls`。
- **离线时**：页面显示"连上 Mac 才能看历史录音"，以及设备上待传的段数。
- **cpad 太旧时**：Mac 的 hello 里没有 `caps.recs`，页面直接显示"Mac 端 cpad 需要升级"，不发请求。
- **★ 和项目的修改只记在 cpad 的事件日志里**（`rec.edited`），**不改 `manifest.json`**（§8.4）。`cpa rec ls` 显示 ★、项目和是否隐藏，仍然不显示标题和正文 [源 sessions.py:4]。

### 8.4 v0.4.1 的"删除"是"从列表隐藏"

**为什么不真删、也不移进回收站**：录音契约 v1 规定 `manifest.json` 只写一次、之后不改；双方都不改、不删对方的文件；WhisperWoof 处理"有合法 manifest、但还没有 result.json"的目录 [源 protocol/recording/v1/README.md 单写者表和交接规则 1；docs/11 §6.4、§7.2]。你马上要合并的 WhisperWoof PR #149–#152 就是按这些规则写的。草案打算在加 ★ 时改写 manifest、在删除时整个移走目录，这两件事都违反契约：加 ★ 可能让 WhisperWoof 重新处理这个目录，或者和它的读取撞车；移走的目录里还有 WhisperWoof 写的文件。

**v0.4.1 的做法**：

| 录音的状态 | 按 Opt+D 并确认 | 怎么找回 |
|---|---|---|
| 任何状态 | 记一条 `rec.hidden` 事件。设备列表和 `cpa rec ls` 都不再显示，Mac 上的文件一个都不动 | `cpa rec ls --hidden` 能看到；`cpa rec unhide <会话>` 恢复 |

```
从列表里隐藏？
「客户同步：定价和交付」
Mac 上的文件不动，
可以用 cpa rec unhide 找回。
Enter 隐藏                    ` 取消
```

- 确认框打开后 400 ms 内的按键一律忽略，和现有确认框一样 [源 04 §8.1]。
- **说清楚**：隐藏**不是**删除。音频、转写、纪要、每日笔记里的那一行，以及 `events.jsonl` 里的标题，都还在 Mac 上。SECURITY.md 会写明这一点。
- **v0.5 的真删除**：先在契约里加一条规则，"会话目录可能随时消失；WhisperWoof 遇到 ENOENT 就当作取消，永远不重建这个目录"，并配上测试向量。WhisperWoof 支持这条规则以后，v0.5 的删除就把目录移进 `~/CardputerNotes/.trash/`，30 天后清掉。最省事的做法是合并 #149–#152 之前就把这条规则加进去（§18 第 4 条）。

### 8.5 留给 v0.5

- 在设备上回放：先过闸门 G-P1（流式播放 10 分钟 0 次欠载；首次出声不超过 150 ms；播放时空闲堆不少于 140 KB）。回放复用录音用的 24 KB 环形缓冲。v0.3.1 起扬声器完全没有用过，回放是它的第一个用途。
- 真删除（§8.4）；在 Mac 上打开（换一个键，并且先确认）；设备上保留已传的录音（`files.keep`）；离线浏览；删除还没传的录音（二次确认）；自由标签（从 Mac 上配置的标签列表里选）；从 AI 给的候选里选标题；`cpa rec retry` 重新处理一条录音。

| 按住 G0 说话 | `recordings/<日期>/…` 录音目录，加上每日笔记一行；WhisperWoof 判断是待办的，写成复选框 | 先录在卡上，插上后自动传 [源 11 §6.7] |
| Opt+R 开会 | 会话目录里的 `summary.md`（含待办），加上每日笔记一行 | 同上 |

### 9.2 模型：每条采集 = 内容 + 去向

- **按哪个键，就决定了存到哪里**。这和 WhisperWoof 的"热键就是去向"是同一个思路，G0 相当于设备上的 Fn 键 [源 WhisperWoof README:104、CLAUDE.md:21]。
- 去向分五类，规则按类别定：

| 类别 | 例子 | 离线采集，插上 Mac 后 | 连着 Mac 时 |
|---|---|---|---|
| 归档 | 今日笔记、待办复选框、项目队列、Obsidian（v0.5） | 自动投递 | 当场投递 |
| 界面 | Mac 剪贴板（v0.5）、光标处粘贴（v0.7） | **永远不补做**，只落档，进"待处理" | 只在你按键的那一刻执行 |
| 执行 | 开 session、回复 session | 按 v0.1 的规则变成排队项 | 发在线请求，再弹确认框（不变） |
| 外发 | Todoist、TickTick、Notion（v0.7） | 只有你在 Mac 上开启过的才自动投递，每次都记审计 | 同左 |
| 问答 | 问一下（v0.7） | 连上 Mac 后回答，回答放进"等你" | 同左 |

- **不认识的去向一律降级成今日笔记**，绝不降级成粘贴或执行。WhisperWoof 遇到不认识的热键会回退到"粘贴到光标处" [源 WhisperWoof dictation-route.ts:14]；设备上的条目可能几小时后才同步，照这样回退，字会被打进同步时碰巧在前台的程序。
- **默认去向只能是"归档"类、并且不离开 Mac 的**。"界面"和"外发"类必须由你明确按键选中。
- **去向永远不由内容决定**。会议里有人说"发到 Slack"，什么都不会发生。

### 9.6 不做的事

- **不把设备做成 USB 键盘**：HID 和现在的 CDC 串口共用一个 USB PHY，要切到 TinyUSB，刷固件就不能自动复位了 [源 02 第 41 行；01-mac-setup:17、219]；键码受输入法影响，打不了中文；设备会变成能往任何前台程序里打字的按键注入器。真想当键盘用，可以通过 Launcher 切到出厂固件的 Keyboard 应用（#12）。
- 不让 cpad 自己发送按键事件（那要把辅助功能权限授给一个通用的 Python 解释器）。
- 不在同步时自动复制或粘贴；不自动开 session；不按 LLM 从内容里猜出来的去向往外发；"替你发消息"类的去向（如 Slack）不在计划里。

## 10. 固件 App 框架

### 10.1 v0.4.0 加什么（只新增，都有默认实现）

```cpp
// module.h
struct HelpRow { KeyEvent ev; const char* keys; const char* label; };  // ev = 菜单按 Enter 时重放的键
class Module {
  // 原有：id / begin / onEnter / onKey / render / hint / contextSlot
  virtual uint8_t help(const HelpRow** rows) const { *rows = nullptr; return 0; }
};
class ModuleContext {
  // 原有：state / compose / confirm / request / open / toast / nowMs / sys
  virtual bool press(const KeyEvent& ev) { return false; }  // 替我按一个键：排到第 9 步重放
};
// chord_detector.h：Nav::Menu（Tab）
// keymap.h：Layer::System（Tab、Opt+L）、Layer::Lock；Action::Menu、Lock、Unlock、Projects
// app_state.h：struct UiFlags { bool menu; bool locked; };  放在 AppState.ui（2 B）
```

- **主页的格子和菜单的行都通过"重放按键"执行**：主页上按 P，就是 `ctx.press(Opt+P)`；菜单里对一行按 Enter，就是重放这一行的 `ev`。不另设一个"执行动作"的接口，所以不会出现"菜单里能做、按键却做不了"的不一致。草案里的 `ModuleContext::act(Action)` 不要了。
- 重放只走一层：重放出来的键不能再触发重放。
- 菜单本身不是模块，是外壳的浮层：`MenuState` 放在 Shell 里，内容和画面来自纯函数库 `lib/help`。

### 10.2 v0.4.1 加什么

```cpp
enum class RequestKind : uint8_t { QueueDone, InboxDismiss, RecList, RecAct };  // 新增后两个
struct ModuleResult { RequestKind kind; bool ok; ErrCode code; const RecPage* page; };
class Module { virtual void onResult(const ModuleResult& r) {} };   // 自己发出的请求的结果
// domain.h：Dest{Daily, Todo}、NoteBody.dest、RecFilter、RecOp、RecRow、RecPage、RecCursor
// SysInfo：host_caps{recs, todo}（来自 Mac 的 hello）
```

- `agent.*` 仍然只能从 `confirm()` 发出 [源 module.h]。新的请求类型都不能执行 agent。
- **在途请求**：`rec.list`、`rec.act` 和现有的 `queue.done`、`inbox.dismiss` 共用同一个"最多一个在途"的通道，超时 10 秒 [源 runtime.h:50]。`request()` 返回 false（通道正忙）时，应用提示"Mac 正忙，稍后再试"，和"请求失败"分开处理。
- **结果只交给发出请求的那个应用**；它已经不在前台时，结果直接丢掉。超时按失败处理（`ok=false`）。

### 10.3 规则和预算

- **编译期注册，用手写的列表**（静态库里靠自注册的对象会被链接器丢掉，初始化顺序也不确定）[源 05 §5.5]。
- **应用的写法**：不用堆、不阻塞；不 include Arduino、M5 或 esp 的头文件；状态是值类型，用纯函数推进，在 native 环境上测试。
- **模块很便宜**：现有三个模块各占 2.6–4.3 KB flash，对象只占 8–12 B RAM [测 firmware.map]。
- **预算** [源 05 §5.13；v0.3.0]：单个应用对象不超过 1 KB（录音应用一页 6 条，约 700 B [算]）；AppState 不超过 4 KB（现在 3,488 B [测 固件调研]）；空闲堆至少 150 KB、最大连续块至少 64 KB；loop 栈至少留 4 KB。

### 11.2 v0.5：正式的去向适配器接口

```python
DestClass = Literal["archive", "ui", "exec", "outbound", "ask"]

@dataclass(frozen=True, slots=True)
class DestSpec:
    id: str            # "daily" "todo" "clip" "file.sb-inbox" "ww.note" …
    label: str         # 设备上显示，≤24 B
    cls: DestClass
    key: str | None    # 绑定的字母
    leaves_mac: bool   # 云端，或者会被同步出这台 Mac 的文件夹

class Destination(Protocol):
    spec: DestSpec
    async def probe(self) -> DestStatus: ...                     # 不碰任何内容
    async def deliver(self, d: Delivery) -> DeliveryResult: ...  # 按幂等键 f"{dev}:{item}:{dest}" 幂等
```

- 纯函数 `decide()` 根据四个条件决定投递、暂存、降级还是改成排队项：去向类别、是否在线、是不是刚按下的键、这个去向开没开。用真值表测试。
- `clipboard`：正文从 stdin 交给 `pbcopy`，设 `LANG=en_US.UTF-8`，超时 2 秒，正文从不出现在命令行参数和日志里。在 LaunchAgent 里能不能正常用，要实测 [待]。
- `file.append`：路径必须在你配置的根目录里；拒绝符号链接；拒绝 `~/Documents`、`~/Desktop` 和 iCloud Drive。
- 贡献者加去向的三种方式：配置一个 `file.append`（不写代码）；写一个 Python 适配器并通过共享的契约测试；v0.7 起写 WhisperWoof 的 MCP 插件。

| `rec.act` | 设备发的在线请求 | `rec`、`op`（star / unstar / tag / hide）、`project?`（tag 时用，null 表示不归属）。Mac 回 `ack` 或 `error` | 同上 |

```jsonl
{"v":0,"t":"outbox.item","id":"3QZK1M7-0000C-0005","kind":"note","at":{"up_ms":98000,"wall_ms":1792440045000},"body":{"text":"call the plumber","project":"cpa","dest":"todo"}}
{"v":0,"t":"rec.list","id":"d23","filter":"all","max":6}
{"v":0,"t":"rec.items","id":"h24","re":"d23","next":"t1792440000000-a1","items":[{"rec":"3QZK1M7-00009-0001","mode":"meeting","wall_ms":1792440000000,"dur_ms":2530000,"project":"cpa","starred":true,"marks":2,"st":"done","title":"客户同步：定价和交付","todo_n":3}]}
{"v":0,"t":"rec.list","id":"d25","filter":"all","max":6,"cursor":"t1792440000000-a1"}
{"v":0,"t":"rec.act","id":"d27","rec":"3QZK1M7-00009-0001","op":"hide"}
{"v":0,"t":"ack","id":"h28","re":"d27"}
```

- `cursor` / `next`：不透明字符串，`^[A-Za-z0-9_-]{1,32}$`，设备原样带回。
- `st` 沿用 `sessions.state_of` 的取值（on_device、pulling、archived、processing、blocked、done、transcript、failed、stale）[源 sessions.py:20]。
- **不新增错误码**：找不到这个会话 → `E_UNKNOWN_ITEM`；字段不对 → `E_BAD_FIELD`；Mac 内部错误 → `E_INTERNAL`。`hide` 对任何状态的会话都可以做，所以不需要 `E_BUSY`。
- **新旧版本混用**：新 cpad 配旧固件时，旧固件不会发新消息，cpad 也不主动发新东西（hello 里多出的字段会被旧固件忽略）。旧 cpad 配新固件时，设备看 `caps`，事先提示"cpad 需要升级"，其他功能照常。
- **行长**：协议规定每行不超过 2048 B。`rec.items` 带 6 条、每条标题都是 48 B 中文、所有可选字段都填上，约 1.5 KB [算]，由 `test_worst_lines` 守住。
- **录音契约 v1 不改**：没有 `user{}` 块，没有 `cue`，`manifest.json` 仍然只写一次。11 §18 原计划的 `recs.snapshot` 快照推送不用了。

## 13. 隐私与同意

1. **会议录音**：确认框永远保留，文案写明告知责任在你（§7.4）；`consent:"ack"` 留档；● 和计时永远在屏幕上，锁屏时也在（§7.2）；README 写明"这不是法律意见"。
2. **锁屏时的便条**：要先点一下 G0 才能按住录音（§7.1）。这样口袋里压住 G0 不会悄悄录下旁人的谈话。
3. **锁屏**：锁屏卡片只显示数量。锁屏不等于加密，SD 卡和 `~/CardputerNotes` 里的内容都是明文 [源 11 §9]。
4. **录音标题**：解锁时会显示在设备上；锁屏卡片和主页不显示任何正文。cpad 的日志和 `cpa rec ls` 仍然不出现标题 [源 sessions.py:4]。
5. **隐藏不是删除**（§8.4），SECURITY.md 写明。
6. **离开 Mac 的内容**：v0.4 没有新增任何离开 Mac 的路径。v0.5 起，用 Obsidian Sync 或 git 同步的文件夹会把内容带出 Mac；v0.7 起还有云端插件。这些都按去向逐个开启，默认关闭；每次投递记审计，但不记正文。
7. **多台 Mac**：v0.8 之前，离线条目会同步给下一台插上的 Mac [推]。我假设你现在只在一台 Mac 上用 [设]，见 §18 第 8 条。
8. **防注入**：去向只由按键决定；正文只作为数据交给适配器（stdin、往文件里追加一行、插件的 `{text}` 参数），从不拼进命令行或模板。
9. **日志**：沿用 `RedactFilter`，错误信息里只给错误码 [源 daemon logging/redact.py]。
