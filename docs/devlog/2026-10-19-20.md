## Timeline and key decisions

**2026-10-19**
- The Mac could not see the device. Using the port controller state (`ConnectionActive` / `TransportsActive`), we found the problem was on the device side; in download mode it enumerates.
- Backed up the full factory flash (8MB; SHA-256 recorded in `backups/README.md`).
- After flashing hwtest, the chip entered download mode on every reset. Root cause: G0 latch; one power cycle fixed it. Then wrote up a "safe way to open the serial port".
- HWCDC had a "sent data gets held back" problem: added a 20ms kick in firmware and handshake retries on the Mac. Later HIL also found the link dropping briefly, so we added a 500ms unplug debounce.
- Default decisions (in docs/06): Apache-2.0, sessions started from the device default to plan mode, notes go to `~/CardputerNotes`, USB only at first, Claude Code only at first.
- Toolchain decision (ADR-0001): Arduino 2.0.17 + gnu++17; the microphone was tested and works on this toolchain.

**2026-10-20**
- Installed `cpa` with `uv tool install --editable`; registered acmeshop (slot 1) and Cardputer Assistant (slot 2); installed the LaunchAgent; `cpa status` shows link ready.
- Found that `claude auth status` shows not logged in (issue #2, needs the user to confirm).
- Created the GitHub repo, milestones v0.1.0 to v0.5.0, issues #1–#10, PR #11 (v0.1.0), and turned on Auto-fix.
- The user added direction: a **pocket Granola** (record → transfer automatically → transcribe, summarize, to-dos), a thinking partner, and a real Mac app; interaction with coding agents still matters. The roadmap changed accordingly: v0.2 Launcher+SD → v0.3 Granola voice → v0.4 agent interaction → v0.5 Mac app.
- The user inserted an SD card and authorized wiping and formatting it.
- On PR #11's first CI run, GCC 13 reported `-Werror=format-truncation` (local clang did not). After the fix CI went green → merge → tag `v0.1.0` → CD published the Release automatically, with the app image, full image and SHA256SUMS.
- The user approved downloading Launcher 2.9.1; the archive location is `~/CardputerNotes`; transcription, summaries and the Mac app changed to integrate with WhisperWoof (#13). The user asked to keep the factory firmware so Launcher can switch to it (#12): the factory app image (2.48 MiB) has been cut out of the backup.

- The user did the manual checks and gave 4 points of feedback: long-pressing G0 makes no sound (→ #17 prompt tone); the Fn+` exit key is hard to remember (→ #15, changed to single-key back in v0.2); after unplugging for 10 seconds and plugging back in, the device did not come back online (→ #14); typing on the device is tiring (→ #16: replying to sessions becomes picking from preset options; main input is by voice).
- Investigating #14: after replugging, the Mac's USB-C port controller **never detected the cable** (ConnectionActive was No on all three ports; only MagSafe was connected). So the problem is more likely the physical connection (cable or port) than the daemon or firmware. Set up a one-shot logger to capture the state on the next plug-in.
- PR #18 (v0.2.0) was opened as a draft; CI passed 8/8 on the first run. Real-device tests, Launcher install and the v0.2.0 release all wait for the device to be connected.
- When the user plugged USB back in, the Mac kept not detecting the cable, until the user flipped the switch to **OFF**; then it connected and synced within 1 second. Hypothesis for #14: with the switch ON, the battery back-feeds VBUS through the boost circuit, so the Mac refuses the connection. Still waiting for the user's switch experiment to confirm.
- The user confirmed a local WhisperWoof repo already exists. M3-W is developed in one of its worktrees and does not touch uncommitted changes on the user's main.
- The user made 4 M3 decisions: the agent opens PRs and the user merges; hold G0 to record a memo, Opt+R to start a meeting; a meeting needs confirmation first and has a fixed prompt tone; audio is kept 30 days, text forever.
- **Launcher tested for real**: flashed Launcher 2.9.1 with esptool (SHA-256 checked) → installed the factory firmware and cpa-v0.2.0 with the serial `flash firmware` (about 10.7 KB/s); our firmware reports `launcher=yes store=sd`. Pitfalls: as soon as Launcher's port appears, the daemon grabs it, so you must `cpa pause` first; you must press Enter during Launcher's 5-second splash screen to stay in the menu.
- PR #18 had a flaky test: the test fixture and fake-claude read and wrote the same state file at the same time. Reproduced with a stress test (3/3 fail); after the fix 5/5 pass.

**2026-10-21**
