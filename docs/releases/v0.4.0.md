## v0.4.0 · Whole-device navigation: home, Tab menu, lock screen

This release turns the Cardputer from "a few features" into an assistant with navigation; all device-side changes are in the firmware. It answers user feedback from 10-21: there should be one interface, with each feature as an app reachable by a shortcut; there should be a menu that is always available to remind you of shortcuts you forget; and the lock screen matters. The plan and trade-offs are in docs/13-assistant-v2-plan.md.

This release also carries v0.4.1's protocol and Mac side, plus the matching codec in the firmware (see "Also included: v0.4.1's protocol and Mac side"); the device UI does not use them yet. Protocol v0 changes are additions only: old and new firmware and old and new cpad can be mixed in any combination. WhisperWoof needs no change.

### Decided (defaults from docs/13 §18)
1. **Sound**: since v0.3.1 the device makes no sound at all. This release adds no mute key and no volume levels, because there is no sound to adjust. The menu's "Control" page has a read-only row "Sound off (recording is silent)".
2. **Keys**: Opt+H becomes Home, and the project board moves to **Opt+P**; new **Tab** menu and **Opt+L** lock. Opt+M is still System. Only Opt+H changes meaning.
3. **G0 while locked**: tap G0 first to show the lock card; only while the card is showing does holding G0 record a memo; with the screen dark, holding G0 only wakes the screen. During a meeting G0 always adds a ★.
4. **Meeting confirm dialog text unchanged**: still v0.3.1's "Start meeting recording? / Tell the people present first / Enter start ` cancel". docs/13 §7.4 proposed new text, which the user has not approved, so this release does not use it.
5. Only single keys and two-key combos (checked by `test_keymap_static`).

### New
- **Home launcher (Opt+H)**:
  - A 3×3 grid: P Projects, I Waiting, R Meeting, N Note, Q AI queue, S New session, M System, L Lock, Tab Menu.
  - On Home, pressing a tile's letter is the same as pressing Opt+that letter; 1–9 open the Nth project page; `;` `.` `,` `/` move between tiles, and Enter opens the selected tile.
  - Tiles do nothing themselves; they only "press that key for you", so the effect is exactly the same as the shortcut.
  - The title shows the date ("Home · 10/21 Wed", or just "Home" when the time is unknown); the Projects tile shows "running N" and the Waiting tile "!N"; the line below shows the most urgent "waiting" item (project/name and how long it has waited, never the body), or "No session waiting for you" when there is none.
  - Home is the root page: pressing back from the first level of any app returns to Home. A project page opened from the project board overview is the second level, and back first returns to the overview.
- **Tab menu, always available**:
  - Opens with Tab from any page, except during a memo and while locked. Three pages: **Here** (the keys this page accepts), **Go** (global keys, with Home, Projects, Waiting, project pages and System at the top), **Control** (lock, plus read-only sound, battery, SD card, Mac link).
  - `;` `.` pick a row, `,` `/` switch page, Tab or `` ` `` closes. Enter on a row: the menu closes and then presses the key written on the left of that row for you, with the same effect as pressing it directly. Rows for a group of keys (like `Opt+1-9`) are only descriptions; Enter does nothing on them.
  - Tab then a letter is the same as Opt+that letter (on "Here" and "Go"; on "Control" when that page has such a row), so Tab, P takes you to the project board in two presses.
  - Opened on the capture page, a confirm dialog or the meeting page, it only has "Here" and "Control"; letters on "Here" are eaten by the menu, so you cannot jump elsewhere from the menu, and drafts and recordings in progress are unaffected.
  - The capture page's "Discard what you typed?" is handled as a confirm dialog: the menu says Enter discards the draft, `` ` `` and Fn+` return to editing, and Opt+L does nothing.
  - When holding Backspace closes the menu, that same hold does not go on to delete the draft or leave the page.
  - G0 in the menu: the menu closes and G0 works as usual (adds ★ during a meeting; otherwise a note or a memo).
- **Opt+L lock**:
  - The screen goes dark at once and the keyboard locks, **even with the Mac plugged in**; pressed on battery when the screen is already off after 60 seconds without keys, it locks directly. The page before locking, the capture page's draft and any meeting in progress are all kept, and recording does not stop.
  - Unlock: press Opt+L first (shows the lock card and opens a 3-second window), then Enter within the window, returning to the page before locking.
  - While locked, tap G0 to show the lock card for 3 seconds; while the card shows, hold G0 to record a memo (also when locked on a draft; the draft is untouched); before the mic opens the top left shows "● Ready", and after recording it returns to dark and locked. With the screen dark, holding G0 only wakes the screen, and that hold records nothing until released. During a meeting G0 adds a ★. No other key does anything, and none lights the screen.
  - The lock card only shows the time, date, battery, the number of waiting items, the number of recording segments waiting to transfer, and ↑N; never project names, session names or text; no toasts while locked.
  - **The lock is not a security lock**: there is no PIN; it only prevents pocket presses and keeps content from onlookers (see SECURITY.md).
- **● is always visible while recording**: during recording (Cue, Recording, EndConfirm, Finishing), the backlight dims no further than "Dim", and ● and the timer are drawn, also when locked, with the menu open or with a toast. A meeting while locked dims the screen to the minimum and shows only one line like "●42:10 ★2" at the top left. Since v0.3.1 removed the beeps, the screen is the only cue, so this rule matters more.
- **Hint bar**: the right end of the hint bar on Home, project board, Waiting, System, capture page and meeting page always reads "Tab Menu"; confirm dialog hints are unchanged. To make room on the capture page, its hint dropped "Opt 0-9 target" (changing the target project is in the menu's "Here").
- **Test firmware**: `debug.state` gains an optional field `ui{menu, locked}`; with the menu open, `overlay` still reports the layer under the menu. HIL uses it to tell whether the menu is open and the device locked. The release firmware has no `debug.*` at all.
- Firmware version reports `cpa-fw/0.4.0`.

### Also included: v0.4.1's protocol and Mac side (no device UI yet)
The protocol, cpad and firmware codec for v0.4.1's recordings app and capture destinations were done first and merged into this release. Nothing on the device uses them yet: the firmware sends no `rec.*` and no `dest`, and does nothing with `caps.recs` / `caps.todo` in the host's `hello`. The recordings app, destination picker and other UI are left for v0.4.1.
- **Protocol v0, additions only** (protocol/README item 20, docs/13 §12.2):
  - The host `hello` gains optional `caps.recs`, `caps.todo`, plus this Mac's `host_id` and `host_label`.
  - Notes (`outbox.item`) and each item of `file.items` can carry `dest`. v0.4.1 only uses `"todo"`; omitted, `null` and `"daily"` all mean the daily note, and unknown values are treated as the daily note too.
  - New messages `rec.list` → `rec.items` (recording history, at most 6 per page, paged with the opaque `cursor` given by cpad) and `rec.act` → `ack` (add ★, remove ★, file to a project, hide; no delete).
  - `rec.items` is the only host reply allowed over 256 B, still within the 2048 B single-line limit. Recording file contract v1 and `manifest.json` are unchanged, word for word.
- **cpad**:
  - `hello` carries `caps.recs`, `caps.todo` and `host_id`: generated randomly on first run, stored in `$CPA_HOME/host_id`, never logged. `host_label` is optional, from config.
  - Notes with `dest` `todo`, and memos whose segment 0 carries `dest:"todo"`, are written as a `- [ ]` line in the daily note.
  - Answers `rec.list` (newest start time first, not just by MonoId) and `rec.act`. Adding ★, filing to a project and hiding only append `rec.edited` and `rec.hidden` events, without touching recording files or `manifest.json`.
  - `cpa rec ls` shows ★ and project, and lists hidden recordings only with `--hidden`; new `cpa rec unhide <sid>`.
- **Firmware**: the codec reads and writes all the new fields and messages above (`lib/protocol/codec_rec.cpp`; `rec.items` decodes directly into a fixed 6-row page inside the message, so the message does not grow); runtime and UI are unchanged. When the host does not send these fields, the encoded output is byte-for-byte the same as before.

### Fixes
- **Recordings transfer to the Mac faster** (#43): during a transfer, every received block redrew the whole screen (about 20 times per second, without answering the transfer while redrawing), and v0.4.0's Home draws slower than the old project board, so meeting recordings dropped from 336 KB/s to 263 KB/s. Now a change in the "last received" time alone no longer triggers a redraw (only the System page shows it, still refreshed once per second). Measured on the device, meeting recordings transfer at about **513 KB/s**, about 50% faster than v0.3.2; a 1-hour recording transfers in about 3.5 minutes.

### Key changes
| Key | v0.3.1 | v0.4.0 |
|---|---|---|
| Opt+H | Project board | Home (launcher) |
| Opt+P | none | Project board |
| Tab | none | Menu |
| Opt+L | none | Lock; while locked, the first step to unlock |
| Enter (while locked, within 3 s of Opt+L) | — | Unlock |

The full key table is in docs/04-prd.md §8 and the README's "Keys" section.

### Unchanged
- The other global keys: G0 note, hold G0 memo, Opt+1–9, Opt+I, Opt+M, Opt+N/Q/S, Opt+R, the back key.
- The meeting confirm dialog: text, 400 ms anti-misfire, `consent:"ack"` written to `.M` and `manifest.json`. Recording gestures, the 5-minute and 3-hour limits, ★ marks, completely silent recording.
- Protocol v0 additions only (the test firmware's `debug.state.ui`, plus the v0.4.1 fields and messages above); recording contract v1 and `file.*` transfer unchanged.
- Navigation stack at most 4 levels.

### Known issues
- **No banners on Home**: "Claude Code not found on the Mac" and "version mismatch" only show on the project board (Opt+P); the status bar still shows "◇ version mismatch".
- **Holding G0 while locked without an SD card**: the toast refusing to record is hidden (no toasts while locked), so it looks like nothing happened.
- All v0.3.2 fixes are in this release (#31: the first ~1 second of the first recording after boot was all zeros: the codec is warmed up at boot, and recording only counts as started once there is sound). The known issues listed for v0.3.2 still apply (real power-off then power-on only tested once, the 2 s count not yet visible in `debug.state`, meeting levels not measured separately, etc.); see docs/releases/v0.3.2.md.
