## v0.4.1 · 稳当版：Mando 主题，小屏幕上按错了也看得出来

这一版回应的是 10-22 定下的要求：这是小屏幕小键盘的设备，用起来方便、稳定最重要。交互审查（docs/20）发现，v0.4.0 的底子是稳的，问题在于"按错了你不知道"：设备没有声音、没有振动，屏幕是唯一的反馈，可不少地方什么都不显示。这一版把审查的修复全部做完，和 Mando 主题（docs/19）、v0.4.0 真机长测找到的问题一起发；10-22 语音便条里提的三件事也在里面（下一节）。

设备上的改动都在固件里；cpad 配合着改了几处小地方（session 名、sid 去重、队列的 `uncertain` 和 `cpa queue reopen`、会议第 0 段以后的项目标签，见下面各节）；同一个 tag 还带上了 main 上 Mac 侧的三件：`cpa-stt`、`cpa rec ls` 显示到秒、从 wheel 安装的 cpad（见"Mac 上"）。协议 v0 只新增：新旧固件和新旧 cpad 可以任意搭配。WhisperWoof 照旧能用，但它还不认 `cpa-stt` 带来的认领文件，两个只能开一个（见已知问题）。原计划的 v0.4.1「录音历史与待办」的设备界面顺延成 v0.4.2（D10，docs/13 §15）。

### 语音便条里提的三件事（gh #51，docs/20 U26）
1. **便条不再说着说着断掉**：要求：按住 G0 说话时，便条不能自己停掉。原因是侧键一次接触不良的采样被当成了松开（M5Unified 的去抖在一轮循环慢于 10 ms 时不起作用）。现在 G0 的松开要相隔至少 30 ms 的两次采样都读到才算；松开以后还有 0.6 秒宽限，页面上写"松开了 · 0.6 秒内按回继续"，这期间按回来还是同一段、同一个文件，没按回才结束并保存。在编辑器、确认框、菜单上按住录的（D4），锁卡上录的，都一样；按回的那一下只属于这段录音，不会提交草稿、不会打开记一条。
2. **双击 G0 免提录音、再按一下结束**：要求：一直按着太累，双击 G0 进入语音模式，再按一下关闭。凡是点一下 G0 是"记一条"的地方（主页、各页；Tab 菜单开着时第一下先关菜单），两下短按，第二下一按下就开始录（不用等 0.5 秒的按住判定；照旧看到 ● REC 再说话），松开也继续；页面写"免提录音 · 按 G0 结束"；再按一下 G0 结束并保存，点两下结束也行，不会接着打开记一条。录的时候 1–9 / 0 归项目，Tab 菜单，Opt+L 锁屏、录音不停，别的键不起作用（口袋误触不会结束它）；5 分钟上限照旧，最后 30 秒写"还剩 0:30"。锁着时只在按键点亮的卡片上算（黑屏时、卡片自己亮着时第一下只亮卡片）；免提录着锁住时，黑屏按 G0 只亮卡片（写"免提录音中：按 G0 结束"），再按一下结束，卡片写"√ 已存"。第二下慢一点（1 秒内、中间没按别的键）也算；点一下再按住仍是按住说。点一下的记一条要等 0.35 秒才打开（看有没有第二下），这期间直接打字，第一个字就落进去。
3. **波形跟着声音动、不被房间嗡声带着动**：四段样本便条里，说话的块比原来设想的轻 7–19 dB，按线性刻度全画成了一个点。现在电平按 dB 画（-60 dBFS 是点，-24 dBFS 满格），说话占 5–9 格；电平这条路上先过一个 4 阶 130 Hz 高通，屋里 35–68 Hz 的嗡声压低 22–46 dB，停顿时是点，Mando 也不再对着嗡声点头。录下的 WAV 一个字节都没变。

### 定下的事（docs/20 §3，10-22 定下：D1–D10 都用推荐的默认值）
1. **D1 主页单字母**：主页上 R 和 L 要按 Opt（Opt+R 开会，Opt+L 锁屏），其他格子仍是单键。按不是格子的字母，每进一次主页提示一次怎么记一条。
2. **D2 自动锁**：用电池时屏幕一熄（60 秒没按键）就上锁；插着 Mac 不自动锁。代价：黑屏时打字记一条，要 Opt+L、Enter、G0 三下。说话录便条照旧是"点一下再按住"。
3. **D3 会议的两个框**：开始框上 Opt+L 是取消并锁屏，15 秒没人按就取消，打字或数字也是取消；结束框上 Opt+L 是继续录并锁屏，10 秒没人按就回会议页。两个框都从最后一次按键算，Tab 菜单开着时不走。开始框不算录音（屏幕会熄，Mac 能拉录音）。会议页上 ` 只提示"开会中：Opt+R 结束"。400 ms 内太快的 Enter 提示"太快了，再按一次 Enter"，不会被悄悄吞掉。**会议确认框的文案没改**。
4. **D4 浮层下按住 G0**：没在录音时，编辑器、确认框、菜单开着也能按住 G0 录便条，草稿留着。
5. **D5 编辑器的返回键**：编辑器里 ` 是退出（有字先问"放弃？"），反引号这个字符改用 Fn+` 打。不做停放草稿。
6. **D6 确认框上的 `**：开 session 和回复的确认框上，` 回到编辑器，文字和目标都留着。
7. **D7 锁着时什么时候亮卡**：上锁那一刻亮 2 秒；录音结束（包括自动停）亮 2 秒，写结果；插着 Mac 时"等你"数增加亮 3 秒，只写数字。锁着时按 Enter 或空格不亮。
8. **D8 便条开头**：不预录。G0 一按下（而且这次会录）就显示"● 准备"，还是"看到 ● REC 再说话"。
9. **D9 菜单开着时按组合键**：按菜单上写着的组合键（比如 Opt+L），菜单关掉再执行。
10. **D10 发版**：这些和主题一起作为 v0.4.1 发；录音历史与待办的设备界面改成 v0.4.2。

### 新功能
- **Mando 伴侣主题**（docs/19，#45）：
  - WhisperWoof 的暖棕配色（画布仍是 8 位，换成索引色板）、圆角卡片和键帽。主页九宫格、项目页、等你、锁卡、录音页、Tab 菜单和状态栏全部重画。
  - Mando 有八种样子：在呢、在听、嗅一嗅、等你、存好了跳一下、没听到、打盹、离线。计时和时钟用 Nunito 大数字。
  - 只在全亮时动：200 ms 节拍、局部刷新、呼吸的录音 ●、滚动的波形、带 ★ 的会议时间线、Tab 菜单从右边滑入。录音时屏幕的 SPI 时间从约 104 降到 21–30 ms/s。
  - `lib/theme` 是给模块和第三方应用的公开画法；图和字体的版权见 NOTICE。
- **锁卡**（docs/20 B1）：
  - 锁着时按住 G0 被吞掉，原来时钟的位置写大字"没有在录 / 松开，点一下再按住"，Mando 歪头，不打盹（打盹读起来是"一切正常"）。这几个字留到卡片熄灭或者再按一个键。
  - 锁着时录音结束，卡片写结果："√ 已存 0:12"、"× 太短，未存"、自动停的原因（"会议已停：电量低"、"已到 5 分钟上限"）、没录上的原因；只写状态和数字，不写名字。
  - 牌子：等你 N（没有数据就不画；数据是 Mac 断开前留下的，卡片顶上写"已锁屏 · 离线"，牌子不标黄），录N、↑N（为 0 时不画），或者"√ 已同步"；电量 30% 以下黄、17% 以下红。
- **录音页**（B2）：便条 4:30 起写"还剩 0:30"；会议页保留"电 N%"；30% 以下开始框写"电量约够 N 分钟"；会议提示栏写回"空格 加★"。
- **状态栏**（B3）：有宽度预算，永远不重叠；0 值不画；※k 只亮 10 秒；※SD 表示有录音功能但没有能用的 SD 卡。
- **主页**（B4）：离线时问候语写"现在离线"、最急一条写"离线 · N 分钟前的情况"，Mando 换成离线的样子；最急一条先列在等你的，再列最近空闲的，空闲一天以上的收起来；不能录音时 R 格变灰，G0 提示写原因。
- **收件箱和看板**（B5）：提示栏按选中的那一行写 Enter 能不能送到；完整名字，确认页写名字结尾加短 id；结果未知的开 session 在看板上标"开?"。
- **文案和排版**（B6）：确认框的卡片和提示栏用同一个动词（"Enter 开始 · ` 返回修改"），Tab 菜单的行也照框上的字写；编辑器在空格处断行；固定的提示条都放得进主题的提示条胶囊（224 px）。
- **按了不起作用的键给一句提示**（U17）：编辑器开着时按 Opt+H/I/P/M、会议页上按位置键或 Enter、菜单里按说明行、列表里选中的那条已经不在了；同一句 3 秒内不重复。
- 测试版固件的 `debug.state.diag`（#21）：空闲堆和最低值、最大块、主循环和音频任务的栈余量、循环耗时计数、键盘计数；录过音后 `debug.state.rec` 带健康计数。协议 v0 只新增（protocol/README 第 21 条），正式固件不带。
- `cpa queue reopen <qid>`：设备上 Opt+D 点错了行，在 Mac 上撤销（U12）。
- 协议 v0 只新增：`queue.snapshot` 每项可选字段 `uncertain`（protocol/README 第 22 条）。从这样的项开 session 时，确认框另起一行写"可能已开过，先看 Sessions"（U25）。
- 运行时模糊测试进 CI（`test_fuzz_runtime`，每次约 3 秒），`fuzz-nightly.yml` 每晚跑完整矩阵。
- 固件版本报 `cpa-fw/0.4.1`。

### 改变
- **提示条**（U20）：自己操作的结果马上显示，顶掉排着的"X 等你"；错误显示 4.5 秒；锁着或黑屏时提示条不过期，亮屏后只留最近一条录音结果和错误。
- **录音结束都说清怎么结束、录了多长**（U6）："会议已停：电量低 · 已存 42:10"、"已到 5 分钟上限 · 已存 5:00"。没锁时录音自己停了，屏幕像按了一下键一样亮起来，结果看得见，然后照常变暗、熄屏、上锁。
- 便条到 5 分钟上限时 G0 还按着，屏幕停在"已到 5 分钟，已保存 / 松开 G0"，直到松开；用电池时也不熄（U15）。
- 确认框和它的提示条一行写得下，不再提"v0.4"；在等你的 session 不再说"正在运行"（U7）。
- 文案统一（U22）：记一条 · 排队给 AI · 开 session · 回复；年龄用中文（"2 小时"，列表行右边写"45分钟"）；终端 / 后台代替 tty / bg。
- 用电池时熄屏前先变暗 10 秒（U24）。锁卡被按住的 G0 点亮时，最多比平时多亮 10 秒（口袋里压着侧键不会一直亮着耗电）。
- "放弃草稿？"上的 Enter 有 400 ms 防误触，Tab 菜单第一行是"返回编辑"（U18）。
- 没有项目的槽位（U13）：排队或开 session 到不存在的项目，提示"Opt+数字：1 acmeshop · 2 cardputer"，草稿留着，不再报 E_STORAGE。
- SD 卡运行中出错（U16）：提示"SD 卡出错：插好后需重启"；有内部存储时这期间的采集先存进内部 cpafs。
- 列表按 sid / qid 记住选中的那一条，刷新后 Enter / Opt+D 不会落到别的条目（U12）。
- cpad：下发 session 名时去掉它自己项目的 `key/` 前缀；中文口述的任务用开头 8 个字起名（U14）。

### 修复
- **会议框悄悄吞 Enter、框不消失**（U1）：见 D3。以前"Opt+R、Enter、Opt+L、揣兜"手一快，框留在那里，之后口袋里一下 Enter 就开始录会议。
- **录音收尾事件丢了，设备卡在收尾，只能重启**（S1）：5 秒后再发一次停止，10 秒后回到空闲并提示"录音收尾超时：已写下的段还在卡上"。每段录音带一个代号，迟到的结束事件只认自己那一段。
- 会议第 0 段以后才设置或清除的项目标签，在 Mac 上以最新的为准（#46）。
- cpad 按 8 位 sid 去重：一个重复的 sid 不会再让整个 `sessions.snapshot` 被设备拒收。
- 测试：`test_runtime_budget` 的快照字符串顶到协议上限，预算按真的中文数据量算；HIL 的 `Device.home()` 按 Enter 之前等过 400 ms 防误触；HIL 的 `latency` 用 ` 关空编辑器（D5 以后 Fn+` 打出反引号）。
- D1–D10 做完后的审查又找到 9 处，都已修好（docs/20 §5.6）：锁卡在被吞的按住松开后翻回旧的"√ 已存"；确认框的菜单写"Enter 确认"；锁卡在没有数据时写"等你 0"；"先处理确认框"在框没了以后还在；HIL `latency` 关不掉编辑器；结束框在菜单下面走完、之后的 Enter 落空；被吞的按住让卡片一直亮；没锁的会议自己停了看不到结果；会被拒的时候也显示"● 准备"。

### Mac 上（同一个 tag 带上的，来自 main）
- **`cpa-stt`**（docs/22 §4，VC-1，#52）：在这台 Mac 上转写录音的独立程序，和 WhisperWoof 一样是录音契约 v1 的转写程序；契约规定同一时间只能有一个在写（认领文件 `recordings/.transcriber`），WhisperWoof 还没加上这条，所以两个只能开一个（见已知问题）；cpad 里没有转写代码。**默认关**：`cpa-stt setup` 找已有的 ggml 模型（问过你才链接，不复制、不下载），`cpa-stt use` 打开，`cpa-stt run --once` / `watch` 跑，`cpa-stt service install` 才装 LaunchAgent。命令都包在 `sandbox-exec` 里（不能联网）；有 `result.json` 的目录不碰；环境坏了只写 `blocked`，修好后 `cpa-stt retry`。`cpa status` 多一行"transcriber"。
- `cpa rec ls` 和 `cpa rec show`：10 分钟以内的时长显示到秒（`51s`、`4m59s`），短便条不再都是 `1m`（#55）。
- `uv tool install ./daemon` 装的 cpad 不再每条命令都报找不到 `limits.json`（#57）：`limits.json` 随包进 wheel；CI 构建 wheel，在仓库外的新 venv 里跑一遍。

### 没有变的
- 其他全局键：G0 记一条（只是晚 0.35 秒打开）、Opt+1–9、Opt+H/P/I/M、Opt+N/Q/S、Opt+R、Tab、Opt+L，解锁仍是 Opt+L 再在 3 秒内按 Enter。
- 会议确认框的文案（"开始会议录音？ / 请先告知在场的人"）、`consent:"ack"`、5 分钟和 3 小时的上限、★ 标记、录音全程不出声。
- 锁屏不是安全锁（SECURITY.md）；锁卡只写数字，不写项目、session 名或正文。
- 协议 v0 只新增；`file.*` 传输不变；录音契约 v1 只新增（`cpa-stt` 带来的认领文件 `recordings/.transcriber`、`status.json` 的 `by` 和 `reason: engine`、`manifest.json` 的 `cap`）；WhisperWoof 照旧能用，要和 `cpa-stt` 同时开得等它认 `.transcriber`（见已知问题）。

### 已知问题
- **点两下在真机上还没数过**（docs/07 §8.3 U26-1）：主页、看板、刚记完一条时各点两下 20 次，记下没认出来的次数。去抖让 G0 的松开至少晚 30 ms 才算（循环慢时更晚，长测里一轮最长 108 ms），所以接近 0.5 秒的一下可能变成按住；循环很慢时两下间隔太短会并成一下。没认出来的那次不应该误录：最多是记一条，或者一段"录音太短，已丢弃"。
- **记一条晚 0.35 秒打开**：等第二下。HIL 的采集页延迟上限从 300 ms 放宽到 650 ms（docs/04 AC1）。
- **波形的高通是估算的耗时**：每块约 0.6–0.9 ms（ESP32-S3，按反汇编估算，没在真机上量）。
- **要人做的真机闸门还没跑**：UX-H1（揣着过一天，含用电池时的自动锁和锁屏便条手势）、UX-H2 按你自己的手速开一场真会、UX-H3（拔插 SD 卡）。真机上脚本做过的：H2 的按键时序、H5、模拟电池的自动锁（docs/07 §8.4）。docs/20 原来定的是 v0.4.1 发之前跑 H1、H2；这一版没等它们就发了，H1、H2 改到发版后跑（docs/20 §5.6 已改）。
- **真机上这次没跑的**（docs/07 §8.4）：nosd 回归；HIL 的 `sd_store`、`rec_cold_start`（要 Mac 放音）、`latency`；设备测试 `test_mic_gain`、`test_rec_sd`、`test_sd_absent`、`test_sd_store`、`test_sd_wake`、`test_storage`（v0.4.0 跑过其中的 `test_mic_gain`）。
